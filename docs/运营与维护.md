# 运营与维护规划

[返回产品规划](大纲.md)。关联功能：F09、F10、F11，以及所有发奖、支付和提现功能。

本模板用于决定产品上线后由谁配置、谁处理问题、如何发现故障及恢复服务。各项为建议规划范围，负责人、目标值和具体流程均待填写，不表示已具备这些能力。

维护部分参考 Google SRE 对容量、监控、依赖故障、备份恢复和分阶段发布的检查维度，并按本项目业务补充资金与奖励处理。[参考上线检查清单](https://sre.google/sre-book/launch-checklist/)。

## 四 客服与用户沟通

| 问题类型 | 核查信息 | 待填写的处理规则 |
| --- | --- | --- |
| 任务完成未发奖 | 用户、任务、证明、奖励状态和规则版本 | 查询、重验、补发、通知时限 |

| 钱包或账户恢复 | 控制方式、身份验证与关联历史 | 可恢复范围、操作权限及告知 |

## 五 监控与告警

先确定服务承诺，再填告警阈值。服务可用率目标【待填写】；奖励到账目标【待填写】；支付发现及确认目标【待填写】；提现处理目标【待填写】。

| 监控对象 | 信号或指标 | 阈值 / 观察窗口 | 告警接收人 / 处置入口 |
| --- | --- | --- | --- |
| 用户关键流程 | 登录、任务提交、支付查询的错误率和耗时 | 待填写 | 待填写 |
| 任务和奖励 | 验证积压、待发奖时长、失败量、异常发奖量 | 待填写 | 待填写 |
| 邀请和水果机 | 归因异常、奖励成本、概率配置和结果异常 | 待填写 | 待填写 |
| 链上监听 | 节点可用性、扫描落后、补扫积压、确认延迟 | 待填写 | 待填写 |
| 商户通知 | 失败率、最老未送达事件、重复或补发量 | 待填写 | 待填写 |
| 提现与结算 | 待处理时长、失败、结果未知、资金或网络费不足 | 待填写 | 待填写 |
| 对账 | 未匹配交易、差额、重复或遗漏记录 | 待填写 | 待填写 |
| 基础设施 | 容量、存储、备份结果、证书和依赖额度 | 待填写 | 待填写 |
| 告警自身 | 通知失败、无人响应、重复噪声 | 待填写 | 待填写 |

每类告警补充：业务影响、定位信息、临时措施、恢复条件与关闭人。日志应给开发运维提供错误原因、依赖返回、业务 idx、请求关联和状态变化等诊断上下文；不记录私钥、助记词或访问凭据。日志访问范围、保留时间与检索方式【待填写】。

单次处置模板：发现时间【待填写】；影响范围【待填写】；负责人【待填写】；暂停或降级动作【待填写】；用户及商户通知【待填写】；恢复步骤【待填写】；恢复后对账与补偿【待填写】；复盘及跟进日期【待填写】。

| 演练场景 | 需填的恢复方案与验证结果 |
| --- | --- |
| 链节点不可用或限流 | 是否切换来源、扫描进度如何保留、如何补扫和去重 |
| 奖励或提现执行中断 | 如何确认执行结果、恢复未完成工作、避免重复资金操作 |
| 商户长时间无法接收回调 | 重试、告警、查询、补发及商户确认方式 |
| 数据或配置错误 | 如何停止扩散、恢复配置、识别受影响用户并纠正 |
| 主服务或数据存储故障 | 恢复顺序、依赖检查、恢复后完整性与账务核验 |

备份对象【待填写：账户、账单、订单、任务结果、关系、配置及扫描进度等】；频率【待填写】；保留期限【待填写】；隔离位置与访问权限【待填写】；RPO（可容忍丢失的数据时间范围）【待填写】；RTO（目标恢复耗时）【待填写】；恢复演练频率及最近证据【待填写】。

资金签名材料的管理与恢复是否属于平台职责，按钱包控制方式单独决定；恢复数据后还需核实外部已发生的交易。
