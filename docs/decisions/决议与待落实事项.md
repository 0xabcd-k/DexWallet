## 状态含义与来源优先级

| 状态 | 含义 |
| --- | --- |
| 已确认 | 继承用户明确要求或记录中的明确决议，不能因界面重写改变 |
| 本版方案 | 本轮采用的导航、流程、默认值或工程组织，用于设计与实现准备，不表示已运行 |
| 待落实 | 必须形成具体业务决策、配置或技术证据，才能开放相关能力 |

当前用户要求优先，其次是明确决议；历史文档同一事项以较新的明确补充为准。已确认业务语义高于旧页面限制；设计建议不能因为文档日期更新就被提升为用户已确认决议。

## 本版采用的方案

| 编号 | 方案与理由 |
| --- | --- |
| D01 | 用户端钱包、奖励、记录；邀请在奖励中，记录提供异步恢复入口 |
| D02 | 按收款对象选择来源，目标在换钱包或付款方式后不变；页面与底层业务类型分开 |
| D03 | 奖励提现主按钮称转入美元余额，美元出金称转出到链上钱包 |
| D04 | 后台以经营列表和待办详情组织，减少跨页面核对，不引入复杂组织权限 |
| D05 | 商户美元计价，默认优先余额；组合固定一个钱包、网络、资产，先预留后核验 |
| D06 | 正常订单整单退款，异常多付差额退款；原则上回原来源，数量与费用另需落实 |
| D07 | 企业创建商户后平台审核启用；主账户平台开通，首版可只开放一个商户 |
| D08 | 个人账户收款人须已注册，静态码支持美元互转和链上代充值，不做未注册待领取转账 |
| D09 | 美元出金费用暂按平台垫付并从金额扣除，普通链上转账由用户钱包承担费用 |
| D10 | App 暂沿用 Telegram 身份，商户和平台后台独立管理账户 |
| D11 | 水果机采用固定七档候选表，无空奖、额外奖池、保底或自动连转 |
| D12 | 后端按模块组织，候选 Go/go-zero 与关系数据库；前端候选 React TypeScript，App 框架待定 |
| D13 | 按各客户端资产范围设计付款、充值、出金，再逐通道启用；未验证通道不可用 |

这些方案在本分支内保持一致；调整时同步业务、页面和验收，不需要反复回答旧问卷。

## 开放能力前待落实

| 编号 | 事项 | 必须形成的结果 | 未落实时的处理 |
| --- | --- | --- | --- |
| O01 | 各链资产与到账归属 | 真实资产标识、专属地址或关联协议、事件唯一键与归集方案 | 不开放无可靠归属的入金 |
| O02 | 充值代付 | 每网络资产和钱包路径的签名、费用扣取、失败成本验证 | 通道不可用，不静默改由用户另付 |
| O03 | 手动外部转入 | 交易所费用、受益映射、无锁价与晚到账计价 | 不显示手动转入入口 |
| O04 | 退款政策 | 退币量、网络费、退款费、汇差与特殊来源目标验证 | 不开放缺少可执行退款方案的付款通道 |
| O05 | 有效提交与冻结期限 | 逐链签名失效、替代、晚到账补偿及自动人工处理时限 | 未知保持可追踪并进入责任队列，不任意释放 |
| O06 | 企业商户启用 | 资料字段、审核条件、首版商户数量及地址变更规则 | 不启用未完成资料与审核的商户 |
| O07 | 结算执行 | 费率、最低额、等待期、签名工具与权限、重报价责任 | 保留申请能力与明确待处理，未授权不执行 |
| O08 | 用户费用与限额 | 成本测算、费用上限、最终收费与剩余预留退回规则 | 原型数字不作为真实报价 |
| O09 | 平台资金钱包 | 收款归集出款职责、备付占用、签名隔离与备份恢复 | 不接入真实平台资金执行 |
| O10 | 内置钱包与 App | 各客户端密钥保护、导入兼容、身份授权和回跳验证 | 不承诺任意助记词恢复，不把示意创建当安全钱包 |
| O11 | 真实任务与奖励资格 | 任务类型、次数、到期验证、外部接口、动态转入条件及审核时限 | 未实现任务不可发布，无隐藏完成条件 |
| O12 | 金额与业务契约 | 各账本精度舍入、签名算法、错误码、事件与幂等保留窗口 | 先定源定义，再生成与实施 |

上述事项是具体能力的实施前置，不构成停止整个项目文档或原型工作的理由。

## 历史冲突的处理

| 历史描述 | 本版口径 | 原因 |
| --- | --- | --- |
| 首次奖励可能被理解为 1000 积分或现金累计到 $2 解锁 Pro | 首奖只给 $1 与 1000 进度，Pro 按累计任务积分进度 | 采用后续明确决议 |
| 账户收款码只接美元互转、充值只能本人 | 支持链上给本人或他人美元账户充值 | 采用最新资金工作流的明确需求 |
| 商户仅平台手工开通 | 企业创建商户；平台审核启用为本版方案 | 区分新业务需求与审核流程建议 |
| 平台代收可能只是默认方案 | 平台代收与人工结算属于已确认要求 | 采用 10 月 24 日工作流 |
| 钱包、任务、邀请导航 | 钱包、奖励、记录 | 本轮按最新交互方案重新组织 |
| 原版 Word 页面优先编辑 | 新版 Markdown 为当前项目定义 | 避免未同步旧稿与新版并行定义同一规则 |

历史资料完整保留，不再将旧问卷未填项或旧网络建议误认为必须重新确认的决议。
