# 任务与奖励

任务域包含参与资格、任务验证、首奖、邀请、积分、Pro、抽奖和奖励转入。共用规则 R01 至 R12 见 [业务规则](02业务规则.md)，本页展开计算与完整体验。

## 任务生命周期

每种任务实现资格查询、执行入口、完成验证与到期判定；通用任务层负责重复请求、结算、邀请关系和记录。任务配置只能选择已实现类型，不能通过配置凭空获得新验证能力。

用户查看任务 → 检查本任务所需身份，缺少时引导绑定 → 去完成 → 返回原任务 → 主动检查并领奖。绑定后重新查询资格，不自动认定完成。验证通过自动结算；未满足返回具体缺项；验证超时保留原请求查询，不生成第二份奖励。是否允许重复参与或过期后领奖由任务类型决定。

### 任务次数与奖励归属

依赖外部身份的任务，以外部身份为次数消耗主体，不能只按当前产品用户或一条可删除的绑定关系计数。当前任务依赖 TG，后续可扩展其他身份；无需外部身份的任务由其类型明确资格主体，不强制补 TG。首奖资格、奖励账户及既有 Pro 归属仍按产品用户，完整规则见 [业务规则](02业务规则.md)。

| 情形 | 规则结果 |
| --- | --- |
| 同一 TG 解绑后重新绑定 | 原任务次数消耗保留，不能通过重建绑定刷新资格 |
| 产品用户 A 从 TG X 换到 TG Y | 查询 Y 自己的任务剩余资格；A 的首奖状态及已得奖励不变 |
| TG X 后续绑定到产品用户 B | X 已用掉的任务次数仍已用；原来入账给 A 的奖励不随 X 移动 |
| 同一产品用户使用不同外部身份完成任务 | 分别校验任务资格，但产品首奖仍最多一份 |

换绑按 [业务规则](02业务规则.md) 的身份数量、有效登录态及新身份验证条件执行，已占用身份拒绝绑定，不自动合并或转移账户。任务不保存“进行中”的参与状态，也不以用户已点击“去完成”为由锁定换绑。

各类身份分表后，任务引用同时携带身份类型和该表内身份 id；不同表的相同数字 id 不是同一身份，不能混用任务次数。

服务端读取本次所需外部身份及绑定版本并完成外部验证；数据库提交时重新检查产品用户状态、会话、绑定版本、任务资格及邀请上下文。验证期间身份解绑或换绑导致版本变化时，本次不结算，提示重新检查当前身份资格，不能把旧身份的验证结果用于新身份。外部验证调用不放在数据库事务内。

完成记录固定实际使用的外部身份、受益产品用户及有效邀请上下文；记录写入、次数消耗、首奖判定、邀请关系、奖励分录和 Pro 更新在同一事务提交或回滚。持久唯一约束与幂等保证并发和重试只完成一次，不存在业务上的“完成但待发奖”中间态。提交结果未知时按原请求查询或幂等重试，不生成第二份奖励；未提交成功不产生完成事实。页面加载、验证请求和技术重试不形成任务进行中状态，亦不改变资金业务及后台投递自身的状态模型。

用户进一步说明：「首奖」在内部设计中是预期任务奖励的前置体现，不是任务奖励之外另送一份独立补贴。首奖与后续任务奖励需按同一奖励流程理解，不能由此推导新增抵扣、欠款或事后扣回。用户已确认实际入账仍在首次任务完成后；此解释只供内部理解，对外继续使用首奖及实际账户状态，不主动介绍“奖励前置”。当前没有新增按外部身份终身限制首奖的规则。

| 情形 | 参与者得到 | 邀请者得到 | 关系与资格 |
| --- | --- | --- | --- |
| 新用户自己完成首次任务 | $1 待提现奖励、1000 Pro 进度 | 无 | 成为老用户，之后可邀请 |
| 新用户从有效邀请页完成首次任务 | 同一份首奖与进度，不另发任务积分 | 本次任务积分，按邀请者权益计算 | 完成时绑定上级并消耗参与资格 |
| 老用户本人完成任务 | 本次任务积分，按本人权益计算 | 不涉及直接助力奖励 | 按该任务规则消耗资格 |
| 老用户从他人邀请页助力 | 无本人奖励 | 本次任务积分，按邀请者权益计算 | 消耗参与资格，不变更原关系 |

每次有效助力对邀请者都算一次任务奖励，接受助力次数不限；这不代表同一个参与者可以绕过自己的资格无限重复。本人打开本人链接不产生奖励记录。

## 邀请关系与分成

仅首次任务通过邀请页完成时绑定直接上级。打开多个邀请链接、登录或注册均不提前绑定；结算使用实际完成时验证过的邀请上下文，并避免并发首任务重复绑定。

实际获得任务积分的人，其直接上级得到 `floor(最终任务积分 × 20%)`。首奖、抽奖现金、分成积分不再产生分成；上级 Pro 不再放大该分成。关系不可由用户修改，老用户不能补建关系。

例如 C 是 A 的上级，A 已有 Pro；A 邀请新用户 B 完成基础 200 积分的任务：B 得 $1 和 1000 Pro 进度，A 得 400 任务积分及对应进度，C 得 80 分成积分。B 的首奖不另给 A 20% 现金或积分。C 的 80 不再向上递归分成，也不增加 C 的 Pro 进度。

## Pro 进度与权益

累计进度 = 首次任务额外 1000 + 本人任务最终积分累计 + 好友助力使本人获得的任务积分累计。分成积分不计，抽奖不增减，积分消费不减少。达 2000 自动永久解锁。

结算时先依据获得奖励前的权益计算任务积分，再更新进度并判断是否解锁；触发解锁的当笔不翻倍，之后取得的任务积分翻倍。任务开始时间不决定权益。

示例使用不同的有资格任务：首任务后进度 1000、积分 0；完成基础 500 积分任务后进度 1500、积分 500；再完成基础 500 积分任务后进度 2000、积分 1000，自动解锁；随后完成基础 100 积分任务得 200。消费积分不会退回普通身份。

## 积分抽奖

每次固定投入 100 积分，计价基准 $0.10，初始目标 RTP 0.95。结果进入待提现奖励，不能将 1000 积分直接宣传为可兑换 $1。

本版采用固定奖项候选表，无空奖、无累计奖池、无保底、无自动连转；正式发布需保存配置版本并校验概率与期望。以下金额和权重是方案参数，不能描述为已经上线。

| 档位 | 奖励美元 | 万分权重 | 概率 | 图案方案 |
| --- | --- | --- | --- | --- |
| 普通一档 | 0.08 | 1500 | 15% | 一个图案 1，其余不为 1 |
| 普通二档 | 0.09 | 5000 | 50% | 两个图案 1，其余不为 1 |
| 普通三档 | 0.10 | 3000 | 30% | 三个图案 1 |
| 小额加奖 | 0.12 | 400 | 4% | 三个图案 2 |
| 双倍奖 | 0.20 | 90 | 0.9% | 三个图案 3 |
| 大奖 | 1.00 | 9 | 0.09% | 三个图案 4 |
| 最高奖 | 5.00 | 1 | 0.01% | 三个图案 7 |

权重合计 10000；加权期望为 $0.095，除以 $0.10 得 RTP 0.95。95% 结果为 $0.08–$0.10，99% 为 $0.08–$0.12。概率是独立单次概率，不保证某人转固定次数后出大奖或达到提现门槛。普通组合可使用图案 5、6 填充，结果不能匹配多个奖项。

参数调整将金额、权重和图案映射作为一个版本发布。普通一档与二档间每转移 1000 权重，RTP 改变 0.01；这是有限范围的调整方式，不得用负权重、静默裁剪或结算舍入凑任意 RTP。保留其余权重时，0.90 对应前两档 6500/0，0.96 对应 500/6000。

同一事务完成积分检查、扣分、确定结果、记录和现金入账。重复请求返回原结果，动画只表现已确定结果；断网、退出和动画中断都不能触发重新抽取。记录保存投入、结果、金额、图案和规则版本，历史查询不套用新配置。

## 奖励转入美元余额

界面主操作采用「转入美元余额」，说明这是奖励提现的固定到账位置，不填写链上地址。

| 阶段 | 行为与状态 |
| --- | --- |
| 查看 | 展示待提现奖励、在途申请、Pro、最低 $2 及当前动态条件 |
| 提交 | 复查资格，幂等创建申请并扣除待提现奖励，进入自动处理或高风险审核 |
| 通过 | 在账务事务中完成在途转换并增加本人美元余额，只入账一次 |
| 拒绝 | 退回原待提现奖励，展示原因；允许重新申请，但仍复查当前条件 |
| 未知 | 查询原申请，保留在途结果，不再次扣款或返还 |

Pro 与最低金额分别显示。动态条件提供具体缺项和可完成路径；尚无可执行步骤时说明等待原因，不通过隐藏条件诱导继续做任务。费用为 0，奖励转入后用户才可消费或再申请链上转出。

## 统计口径

好友数按已建立直接关系计，助力次数按有效完成事件计；助力任务积分与 20% 分成分别统计。本人任务、助力、分成、首奖、抽奖、奖励转入记录关联各自业务，美元与积分不直接求和。

规则变更保留生效范围与版本。已完成奖励不增加通用事后撤销；未提交事务回滚和申请拒绝恢复仍需处理。验证清单覆盖 R01–R12，见 [验收文档](../testing/验收与场景追踪.md)。
