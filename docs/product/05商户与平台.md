# 商户与平台

## 企业与商户的职责

企业是经营归属主体，商户是订单与应付款归属主体。企业创建商户、平台审核启用为本版方案，取代旧稿中只能平台手工创建商户的流程；首版主操作账户仍由平台开通，具体企业字段和启用条件见 [待落实事项](../decisions/决议与待落实事项.md)。

一个商户一个主操作账户作为初始方案，不建设复杂角色配置，但数据查询、开单、退款、凭据与结算均在后端校验归属。企业或商户停用不能删除历史资金和处理义务。

## 后台用户开通与权限

管理端用户与商户端用户分别建表，独立于产品用户。管理端用户由运维直接在后端服务器运行 super 可执行程序创建，不通过管理页面创建；商户用户由管理端创建。两端邮箱、密码及邮箱验证码共同完成登录，不开放后台自助注册。首版权限固定为平台管理员与商户主账号，账号管理与商户业务主体开通分别处理；商户主体与绑定在 6.1 落实，尚未绑定主体的商户账户只使用本人账户功能。

2.5 已确认交付两端登录、当前账户、改密、普通退出及访问控制，平台管理后台账号状态/密码、查询和禁用/恢复产品用户、只读查询操作记录。登录成功/失败、密码及状态变更均记录操作者、目标、时间、原因、结果与 traceId；业务变更成功与记录同事务，不记录密码、验证码或 token。确认及边界见 [2.5 讨论记录](../design/工程工作记录/02-用户与鉴权/2.5-后台登录与权限基础/01讨论记录.md)，2.5 鉴权与管理基础已实现，商户主体和资金业务仍待后续阶段。

## 商户工作流

1. 建立企业资料和商户，提交启用申请，按原因补充信息。
2. 配置结算地址及服务端接入；手工开单不依赖完成 API 集成。
3. 创建美元计价订单，分享支付链接或二维码。
4. 通过后台、可信通知或主动查单确认收款，再由企业业务系统交付。
5. 必要时申请整单退款并跟踪各资金分项。
6. 从可结算资金中申请企业结算，平台审核、人工执行并核验到账。

资金页面区分历史收入、可结算、退款占用、结算占用、等待结算资格和已结算。订单已付款不表示企业链上钱包已到账；创建订单与申请结算都不产生已到账事实。

## 接入能力

| 能力 | 商户应得到的结果 |
| --- | --- |
| 创建订单 | 平台订单 idx、商户订单号、支付链接、有效期、状态；同号同参幂等 |
| 查询订单 | 权威支付与退款状态、金额构成、事件版本 |
| 支付与退款通知 | 可验签、可去重的事件，明确金额、单位、对象与版本 |
| 测试通知 | 不产生真实资金的测试事件及响应诊断 |
| 凭据轮换 | 明确新旧凭据生效或停用范围，完整新凭据仅生成时受控展示 |
| 结算资料 | 网络、资产、目标地址和版本，变更不覆盖已申请单据 |

凭据只由企业后端使用。回调地址校验不能允许任意请求平台内部网络；返回地址按允许目标处理。具体签名算法、重试参数和协议字段在实现契约阶段确定，不能把此表当作可调用 API。

通知接收方按事件 idx 幂等，按业务版本处理乱序；平台至少一次可靠投递，超过自动重试窗口进入待办。回调失败不撤销付款，主动查单可以恢复。商品履约由企业负责，履约失败通过退款处理，不改写已支付事实。

## 平台日常工作

平台采用单人维护可用的待办工作台，不引入多级审批。每项待办具有业务类型、对象、金额、等待时长、风险或异常原因、证据、责任与下一次处理时间。

| 工作 | 允许的操作 | 必须保留的边界 |
| --- | --- | --- |
| 用户管理 | 查看账户、任务、邀请与风险记录，限制或恢复明确范围 | 不直接编辑余额、积分或邀请上级 |
| 企业商户管理 | 查看资料、启用、暂停新收款、设置通道及费率、恢复账户 | 历史资金继续处理，费率变更不覆盖旧订单 |
| 任务管理 | 配置已实现类型、多语言文案、奖励和参与规则，预览发布 | 不上传任意执行代码，不撤销已发奖励 |
| 审核 | 奖励转入、用户出金、退款、结算、商户启用；通过、拒绝、补充材料 | 通过不等于链上到账，拒绝依据各业务恢复资金 |
| 异常处理 | 重新核验、关联实收、补记、差额退款、重试通知、暂挂 | 不凭截图或手动点击将未知付款改成功 |
| 资金与对账 | 查询原币与美元账、备付、归集和对账差异 | 不用余额直接编辑掩盖差异，不无依据任意打款 |
| 配置 | 草稿、校验、预览、发布、暂停新业务、查看版本 | 通道开关不等于已具备签名或代付能力 |
| 审计 | 查询前后状态、原因、执行结果，受控导出 | 失败也留痕，无删除历史操作入口 |

退款或结算批准前核对来源、目标、额度与占用。人工执行通过唯一出款任务，不将签名提案导出后当作未执行而再次打款。已执行未知时优先查原交易。

## 配置与风险

可运营参数包括通道开关、限额、链上业务费用、行情源、报价有效期、风险条件、任务配置、抽奖奖项和概率、商户链上业务费率及通知重试。中心化账户之间流转手续费固定为 0，纯余额商户收款及余额退款不得配置收费；商户后续链上结算单独按通道计费。手续费边界、首奖等已确认产品规则展示为摘要，不默认变成任意可改配置。

发布前校验费用符合 [手续费边界](02业务规则.md#手续费边界) 且非负、限额有效、资产标识、概率总和和 RTP，展示生效范围。既有交易保留自己的版本。暂停通道停止新操作，历史核验、退款和异常仍有处理路径。

风险判断基于系统与用户统计；高风险进入审核，拒绝不能丢弃已到款。平台诊断保留上下文，公开端不暴露可绕过策略的阈值或凭据。

## 处理完成标准

每笔待办完成必须对应明确业务结果、资金变化或无资金影响的理由，并能追溯操作者与证据。暂挂不能从待办视图消失；通知重试、资金补记、真实出款分别执行，不能混成万能「完成」按钮。

界面与操作入口见 [后台界面](../design/03商户与平台界面.md)，完整资金流程见 [钱包与支付](03钱包与支付.md)。
