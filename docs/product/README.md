# DexWallet 产品页面目录

先修改 [可编辑页面稿](可编辑页面稿/README.md)，每个页面对应一个 Word/WPS 文件。稿内只保留展示字段、按钮和位置，支持直接编辑表格；下列 Markdown 保留详细业务说明。

这是一版可用于低保真原型的产品规划。按角色与页面分文件，页面正文分别写展示、按钮、弹窗和状态；不再把全部功能堆在一个文档，也不要求先回答细节问卷。

用户端 23 个页面、商户端 6 个页面、平台端 9 个页面，加 1 份两类后台复用的登录页面，共 39 份页面说明。创建与导入等同一目的的步骤共用页面文档；弹窗与详情抽屉不另计页面。

先读 [导航与流程](导航与流程.md)，需要核对已确认规则或默认假设时看 [产品约定](产品约定.md)。用户端以移动端布局为主；商户与平台后台以列表、侧栏和详情抽屉为主。

## 目录结构

```text
docs/product/
├─ README.md                 产品入口与页面目录
├─ 导航与流程.md             页面关系和主要路径
├─ 产品约定.md               已确认规则与默认方案
├─ 公共/                     通用弹窗、后台登录
├─ 用户端/
│  ├─ 钱包/                  资产、收款、转账、充值、提现
│  ├─ 支付/                  扫码、支付确认、支付结果
│  ├─ 任务/                  任务、受邀、积分、水果机、Pro
│  ├─ 邀请/                  好友与收益统计
│  ├─ 记录/                  账单列表与详情
│  └─ 账户/                  登录、账户与帮助
├─ 商户端/                   订单、收款、结算、接入
└─ 平台端/                   管理、审核、异常和参数
```

## 阅读与修改方式

每页都可单独提出修改，例如“转账页把两种转账拆开”或“钱包首页先展示链上资产”。没有明确规定的行为已采用默认方案并集中标记，先审阅页面是否齐全、入口是否合理，再按需要调整业务细节。

网络资产、奖励账户、Pro 与邀请规则继续沿用已有决议；链上充值和中心化余额互转已纳入。跨设备钱包配对、通用邀请链接和任务奖励事后撤销不在本轮范围内。
