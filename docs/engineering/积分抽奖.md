# 积分抽奖

4.6 已接通本地单次积分抽奖：100 积分投入、版本奖表、后端判奖、原子扣分与现金入账、结果动画、历史记录和原请求恢复。数据库要求 **business 13**。七档具体参数仍为 [本版候选](../product/04任务与奖励.md#积分抽奖)，本轮不开放生产抽奖。

## 开启本地验证

服务必须 Environment=local、Mode=dev，且 draw_control 有有效版本才允许新抽奖；初始为空，页面展示未开放。其他环境禁止新抽奖，但已提交结果仍可查询或按原键返回。无需提供 Bot token、链上钱包或资金；已有积分来自本地 mock 任务领奖。

先按 [开发与测试环境](开发与测试环境.md) 准备专用隔离数据库并显式升级至 13，再执行以下命令。工具验证 DEXWALLET_MYSQL_DSN 的隔离账号/目标，--database 必须与其一致；不能拿生产 DSN 运行。配置另需 DEXWALLET_ID_SECRET，不将其贴入日志或提交。

```sh
# backend/；环境变量从本机不入库的专用配置加载。
go run ./tools/drawdemo --database <实际隔离测试库名>
```

工具安装 candidate_v1 后打开用户端 /#/draws。重复安装同名同内容复用版本，不创建用户资金；有积分后用户主动点击才结算。正式运营发布/暂停入口归 4.8，本轮没有公开配置写接口。

## 接口与数据

契约源 [platform.api](../../backend/manifest/api/platform/platform.api)，全部使用产品 JWT。金额/积分返回字符串，idx 不能替代归属鉴权。

| 接口 | 行为 |
| --- | --- |
| GET /v1/user/draw-state | 余额、是否开放、生效版本、100 积分投入、全部奖项与万分权重、RTP |
| POST /v1/user/draws | requestKey 与 versionIdx；服务端决定奖项并原子结算 |
| GET /v1/user/draws/by-request/:requestKey | 本人原请求结果；404 不能单独证明先前请求未执行 |
| GET /v1/user/draws | 本人记录，before 游标、limit 默认 20/最大 100 |
| GET /v1/user/draws/:idx | 本人抽奖详情与凭证来源 |

[000013 迁移](../../backend/manifest/sql/diff/business/000013_point_draw.up.sql) 新增不可变奖表版本、当前指针和抽奖结果；完整 [DDL](../../backend/manifest/sql/ddl/draw/tables.sql) 与 [约束](../../backend/manifest/sql/ddl/draw/constraints.sql) 同步维护。迁移不安装候选奖表；存在版本或抽奖记录时 [降级](../../backend/manifest/sql/diff/business/000013_point_draw.down.sql) 拒绝删除。拒绝产生的 dirty 标记/guard 表需人工核对，不直接 force 或丢弃数据。

## 计算与一致性

[规则计算](../../backend/logic/draw/rules.go) 使用精确十进制校验美分、权重总和与 RTP；不舍入凑概率。后端 crypto/rand.Int 在 [0,10000) 上均匀取票，再匹配累计权重；零权重永远不会选中。固定七档图案互斥，实际票、图案、金额、成本及版本持久保存。

[结算](../../backend/logic/draw/service.go) 按产品用户加锁，与任务领奖顺序一致；奖表指针共享锁保持当前结算版本稳定。抽奖记录与公共 account.Post 同一事务：扣 task_points、贷平台 point_consumption，同时借平台 reward_expense、贷 reward_usd。每个单位分别平衡，Pro 与分成无变化。任一失败全回滚，不建异步补发队列。

同用户同请求键只能有一条抽奖，同键异版本冲突。提交前会话/账户状态再次复查；资金不足由锁定后的公共记账入口拒绝。死锁仅在确认回滚后最多重试一次并复用当次随机票；未知提交查原键，查询未找到仍保留未知。已经提交的结果不受当前奖表暂停或替换影响。

## 页面与恢复

奖励首页提供抽奖入口；/draws 展示余额、差额、全部奖项概率和一次性按钮；/draw-history 与 /draws/:idx 提供本人历史。账单 point_draw 来源跳转到抽奖详情。

原请求按 API 服务和产品用户保存在本机，通过 Web Locks 协调多标签；存储不可用则明确报错，不在未保存请求时发起扣分。刷新/断网保留原键，用户可主动查询或重试。金额、凭证、图案或版本不匹配的结果不标记成功。

结果先结算再展示动画，历史/恢复不触发新抽奖，减少动态效果设置受支持。明确版本变化或资金不足且核对原结果未找到后，刷新当前规则/余额再等待新的主动点击；未知结果不允许自动换键。页面不提供保底、购买积分、自动连转或直接积分兑换美元的承诺。
