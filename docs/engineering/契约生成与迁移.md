# 契约生成与迁移

本页记录 1.2 实际入口。业务边界沿用 [开发规范](开发规范.md) 与 [1.2 方案](../design/工程工作记录/01-工程基础/1.2-契约与代码生成/02实施方案.md)。当前交付隔离工程示例和工具链，正式 API、业务表、前端页面及中间件客户端留给后续工作项。

## 源、配置与产物

| 内容 | 权威源或实际入口 | 生成/手写边界 |
| --- | --- | --- |
| API 示例 | [contract.api](../../backend/manifest/api/examples/contract.api)、[shared.api](../../backend/manifest/api/examples/shared.api) | 支持 import、嵌套、数组、可选字段和枚举；正式业务入口不导入示例 |
| 数据库示例 | [完整 DDL](../../backend/manifest/sql/ddl/examples/contract_sample.sql)、[第一步迁移](../../backend/manifest/sql/diff/examples/000001_create_contract_sample.up.sql)、[第二步迁移](../../backend/manifest/sql/diff/examples/000002_add_sample_note.up.sql) | 完整 DDL 描述目标；增量 SQL 独立执行；不把示例扫描进业务迁移 |
| 类型映射 | [backend/goctl.yaml](../../backend/goctl.yaml) | `model.types_map` 配置 Decimal、NullDecimal 及 pkg，覆盖 decimal/dec/numeric；无需 model 模板补丁 |
| Go 产物 | [types](../../backend/tests/codegen/example/internal/types/types.go)、[routes](../../backend/tests/codegen/example/internal/handler/routes.go)、[model 生成区](../../backend/model/example/contract_sample_model_gen.go) | 完全生成，不手改；基于完整 DDL 生成无缓存 model |
| 手写扩展 | [回显逻辑](../../backend/tests/codegen/example/internal/logic/example/echo_logic.go)、[model 扩展](../../backend/model/example/contract_sample_model.go) | 回显保留金额字符串并将空数组输出为 []；WithSession 参与调用方事务，不自行提交 |
| TS 契约 | [api-contract](../../frontend/packages/api-contract/package.json)、[示例类型](../../frontend/packages/api-contract/src/example.ts) | 仅 types 导出 `@dexwallet/api-contract/example`，未引入生成请求运行时 |
| 文件归属 | [生成文件清单](../../scripts/generated-files.json) | 4 个纯生成文件带 SHA-256，8 个首次骨架保留手写内容 |

生成在临时目录进行，复制 module、源定义及 goctl.yaml，使用固定版本工具的干净内置模板；显式固定 `GOCTL_EXPERIMENTAL=on` 与临时 GOCTL_HOME/TMPDIR，不读取个人模板。TS 产物只规范化末尾换行，不替换字段或类型。goctl 会格式化输入及创建备份，因此仅向它提供临时副本。缺少配置或 DECIMAL 生成结果退回浮点时失败，实际源文件和产物不变。

更新前检查整批结果；纯生成区的本地手改会阻止覆盖，旧的纯生成文件按登记清单清理。已有 handler/logic/config/svc/main/model 扩展不覆盖，旧手写骨架须明确处理后再生成。检查包含未跟踪的额外生成文件；不以单次 git diff 代替完整比较。文件写入遇到磁盘异常时应检查差异后重跑，不承诺多个文件的写入是文件系统原子事务。

目前直接 TS 链明确拒绝 `.api` 指针及 interface{}，不假装支持 JSON null。示例可选字段缺省时省略，金额保持字符串，数组输出 []。未来业务若必须区分缺省与显式 null，应补充契约表示和生成能力验证；不能改成 any 或仅依靠类型断言。类型检查不会替代服务端输入校验或权限校验。

```sh

```

## 生成与不依赖数据库的检查

以下命令在仓库根目录执行；检查前应在当前 shell 切换到上述 Node/pnpm 版本：

```sh
python3 scripts/generate.py
python3 scripts/generate.py --check
bash scripts/check_contracts.sh
python3 scripts/check_docs.py
git diff --check
```

generate 仅处理登记的示例源，不连接 MySQL/Redis/RocketMQ；--check 不修改源码或已提交产物。check_contracts 执行生成差异检查、生成行为测试、Go 编译/单测及共享 TS 严格类型检查。Go 测试不含带 integration 标签的真实数据库用例。

增加业务源时应扩展生成输入与输出归属，保持 module/path 参数化，不将例库清单改成递归扫描所有 SQL。生成产物与源同次提交；数据库变更同时更新完整 DDL 与编号迁移。已执行迁移保持不可变，用新文件修正。

## 显式迁移

迁移入口为 [backend/tools/migrate](../../backend/tools/migrate/main.go)，从 `backend/` 执行。通过本地环境或凭据管理注入 `DEXWALLET_MYSQL_DSN`，使用 MySQL Go driver DSN 格式且包含目标库名；不要把值写入仓库。工具同时要求显式目标数据库，两者必须一致。

当前只有 examples 集，允许作用于预先建立的 `dexwallet_contract_` 前缀测试库；以下库名只是命令示例，工具不会自动建库：

```sh
go run ./tools/migrate --source examples --database dexwallet_contract_dev --action up
go run ./tools/migrate --source examples --database dexwallet_contract_dev --action version
```

up 无待执行文件时保持成功且显示当前版本；不在生成或应用启动时执行。迁移失败会返回非零并保留 dirty/version 状态；没有自动 force/down。MySQL 的部分 DDL 可能已经提交，应先核对实际结构再修复。数据库连接密码只由环境传入，不作为 CLI 参数打印。正式业务迁移集与部署入口随业务和 1.5 建立，不能把 examples 指向生产库。

## 独立 MySQL 验证

从 `backend/` 执行，先通过环境注入 `DEXWALLET_TEST_MYSQL_DSN`。测试凭据需要能创建和删除项目隔离库；测试始终创建随机 `dexwallet_contract_` 前缀库，不使用 DSN 原有库作为测试对象：

```sh
go test -tags=integration ./tests/integration -v -count=1
```

测试创建三个专属库，对比空库迁移、带旧数据升级与完整 DDL；验证 decimal 精确往返、NULL/零区分、WithSession 回滚、DDL 部分成功后 dirty 状态与重试阻止。测试正常退出时清理自身创建的库；进程被强杀时需依据该前缀及当次记录核对残留，不能清理其他项目数据库。

本轮复用用户现有 Docker MySQL，服务报告 9.4.0；验证只覆盖该实例，不锁定生产 MySQL 版本。Redis/RocketMQ 未接入或修改。详情见 [实施记录](../design/工程工作记录/01-工程基础/1.2-契约与代码生成/03实施记录.md) 和 [验证记录](../design/工程工作记录/01-工程基础/1.2-契约与代码生成/04验证记录.md)。
