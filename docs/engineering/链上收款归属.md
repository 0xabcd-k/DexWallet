# 链上收款请求与到账归属

阶段 5.3 的内部收款流程先开请求，再核实链上实际到账，最后将一个转账事件归给一个请求。请求保存用途和受益人，例如 A 给 B 充值时，付款钱包属于 A，充值受益人固定为 B。归属成功只写关联记录。美元入账、报价、费用和商户订单结算由后续业务步骤处理。

## 如何确定是哪一笔请求

| 收款方式 | 适用范围 | 链上识别依据 |
| --- | --- | --- |
| 一次性收款地址 `single_use` | Solana Devnet、Base Sepolia、TRON Nile、TON Testnet 的已配置资产 | 平台登记一个自己控制的全新地址，每个地址只分配给一个请求。首次分配后永久保留，包括请求过期的情况。 |
| TON 共享地址 `ton_memo` | TON Testnet 的原生 TON 和已配置的测试 USDT | 每次开请求时生成独立的 128 位随机标识，格式为 `dw:` 加 32 位小写十六进制字符。用户钱包随付款携带完整标识。 |

收款地址由内部运维独立确认平台控制权后登记。登记时固定网络和用途模式。收款目标使用钱包 owner，SPL token account 和 Jetton wallet 由到账核验层按链上证据识别。资产使用完整目录 ID，测试替代币包含合约或 mint。平台登记的收款地址不能充当付款人。

内部业务在将地址或备注交给钱包前，使用稳定的付款尝试键开请求。可信调用方给定用途、受益人、付款 owner、网络、资产、最小单位金额和截止时间。收款 owner 可由系统分配，也可由调用方显式指定已登记地址。充值的受益人是用户，商户付款的受益人是商户。接入公开业务时应从已授权的充值请求或商户订单取得这些字段。同键同条件重试可读回原请求和备注，同键修改条件会返回冲突。

### 一次性地址的签发与补充

开请求时省略收款 owner，系统只从该网络已登记的 `single_use` 地址中选择一个。地址在同网络的所有资产、充值和商户付款之间共用库存，每个地址终身只签发一次。请求和地址绑定写入同一条记录后才返回收款地址，可据此生成二维码。

- 重发同一付款尝试键和原条件，会取回已签发的地址，即便该网络已停用。改动金额、资产、受益人或有效期等条件时返回冲突。
- 多个请求同时选中同一地址时，数据库只允许一个请求取得它，其余请求继续选择可用地址。地址耗尽返回 `ErrReceiveAddressExhausted`，调用方应等运维登记新的受控地址后用原键和原条件重试。若付款窗口已经结束，需重新开单。
- 若要使用 TON 共享备注地址，开请求时须显式指定登记为 `ton_memo` 的 owner，并把返回的备注连同地址交给钱包。自动分配始终只使用专属地址。

### 批量补充与查看库存

运维按网络准备文本文件，每个非空行放一个公开收款地址。首次登记的地址应为全新地址，并已由运维核实控制权。导入会去掉行首尾空白，并按该链的地址格式规范化、去重。以下命令在 `backend/` 下运行，数据库配置同下文。

```bash
go run ./tools/chain_receive -action import -network base-sepolia -file "$ADDRESS_FILE"
go run ./tools/chain_receive -action inventory -network base-sepolia
```

导入返回 `network`、`added`（本次新增）和 `existing`（此前已登记为专属地址），两个数量都按去重后的地址计算。已有分配关系会保留。文件出现无效地址、已有共享备注地址或数据库写入错误时，整批回滚。若提交应答丢失，可用原文件重试；最终每个地址只登记一条，返回数量反映本次执行。

库存查询返回同一数据库快照中的 `total`（专属地址总数）、`allocated`（曾签发）、`available`（从未签发）。例如返回 `{"network":"base-sepolia","total":12,"allocated":5,"available":7}` 表示该网络此刻还有 7 个可签发地址。过期或已匹配到账的请求仍占用原地址，TON 共享备注地址单独管理。网络停用后仍可查询库存，新增登记需要先启用对应测试网。并发开单可能随时改变可用数量，业务以实际开单结果为准。

### TON 共享备注的核验

TON 原生转账读取收款消息中的标准文本备注。Jetton 读取收款 Jetton wallet 的内部转账载荷，同时核对付款 owner 发往其 Jetton wallet 的原始转账指令，两端的 `forward_payload` 哈希必须一致。缺失、拼写错误或未知标识会留下未匹配的到账事实。同地址、同币种、同金额同时出现多个请求时仍按实际备注区分。

## 匹配条件与恢复

1. 先由各链核验器取得最终确认的交易并保存原始证据。匹配入口只接受网络、交易 ID、事件类型及序号。Solana 使用顶层指令序号，Base 区分原生转账、日志和内部调用，TRON 区分原生与日志，TON 使用收款端交易。
2. 按事件中的收款 owner 和归属方式定位请求，逐项核对付款 owner、资产 ID 和整数金额。交易发起人、手续费支付人可能与实际付款 owner 不同。短款、超付、来自已登记平台地址的款项均不能自动归属。
3. 以已保存的链上收录时间判断有效期。Solana 取交易区块时间，Base 取规范区块时间，TRON 取固化回执时间，TON 取收款交易时间。精度为 Unix 秒。有效期包含 `opensAt`，排除 `expiresAt`。开始时间取签发后的第一个完整秒，调用方从该时刻起发起支付。窗口内到账可在过期后补查匹配。报价受理时间和报价执行窗口由 5.4 单独判断。
4. 数据库用条件更新及事件唯一约束保证双向唯一。同一事件重试返回原归属，同一请求收到第二笔有效付款时返回冲突，第二笔保留待核查。记录成功但匹配失败、进程重启或写回应答丢失时，可按原事件位置重新匹配。

## 内部运行入口

在 `backend/` 下运行。设置专用测试数据库的 `DEXWALLET_MYSQL_DSN` 并启用目标测试网。测试替代资产需设置对应合约。收款地址和请求表要求 business 32 或以上的干净版本。库中已有收款地址时，降至 31 会被拒绝。配置见[链上资产查询](链上资产查询.md)。

以下命令演示如何登记一个全新的 Base Sepolia 受控地址，然后由业务开单取得地址。金额为最小单位，截止时间为 Unix 秒。

```bash
go run ./tools/chain_receive -action register -network base-sepolia \
  -recipient "$RECEIVING_OWNER" -route single_use

go run ./tools/chain_receive -action open -network base-sepolia \
  -key "$ATTEMPT_KEY" -purpose deposit -beneficiary "$BENEFICIARY_ID" \
  -payer "$PAYING_OWNER" -asset base-sepolia:eth -atoms 1000000000000 -expires "$EXPIRES_AT"
```

下例使用 TON 共享地址与备注。

```bash
go run ./tools/chain_receive -action register -network ton-testnet \
  -recipient "$RECEIVING_OWNER" -route ton_memo

go run ./tools/chain_receive -action open -network ton-testnet \
  -key "$ATTEMPT_KEY" -purpose deposit -beneficiary "$BENEFICIARY_ID" \
  -payer "$PAYING_OWNER" -recipient "$RECEIVING_OWNER" \
  -asset ton-testnet:ton -atoms 1000000 -expires "$EXPIRES_AT"

go run ./tools/chain_receipts -network ton-testnet -signature "$RECEIVING_TX" \
  -recipient "$RECEIVING_OWNER" -asset ton-testnet:ton -atoms 1000000 -record -attribute

go run ./tools/chain_receive -action match -network ton-testnet \
  -tx "$RECEIVING_TX" -kind ton_incoming -index 0

go run ./tools/chain_receive -action get -key "$ATTEMPT_KEY"
```

`chain_receipts -record -attribute` 先保存核实的到账，再尝试归属。匹配失败时错误中给出已保存的事件位置。`chain_receive match` 和 `get` 可仅凭数据库恢复和查询。TON Testnet 已接通[自动到账监听与断点补扫](TON到账监听.md)。Solana Devnet 已接通[SOL、USDC 与测试 USDT 自动监听](Solana到账监听.md)。Base Sepolia 已接通[普通 ETH、合约内部 ETH 和 USDC 自动监听](Base到账监听.md)。TRON Nile 已接通[TRX 和测试 USDT 自动监听](TRON到账监听.md)。地址生成或归集、用户端充值入口和资金入账仍待接入。使用共享地址的其他链路需要可独立核验的交易绑定，当前只提供表中两种归属方式。
