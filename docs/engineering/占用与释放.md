# 占用与释放

3.3 提供用户美元账户的内部占用命令、本人明细查询及页面，不开放提现/支付写入接口。确认依据与交付见 [3.3 工作记录](../design/工程工作记录/03-资金账户与账本/3.3-占用与释放/01讨论记录.md)。

## 写入与职责

入口为 [holds.go](../../backend/logic/account/holds.go)：

- Hold(ctx, session, HoldRequest)：美元可用转占用，返回内部占用 ID。来源仅 withdrawal/payment，一业务单据一笔；多分项由所属业务使用各自子单据 ID。
- Consume(ctx, session, id, credits)：整笔核销，业务提供金额合计相等的正额美元贷记对方；拒绝原账户自身、积分、奖励账户和不平衡明细。
- Release(ctx, session, id, reason)：整笔退回原账户可用余额。原因使用 model 的 cancelled/rejected/not_executed 具名常量；无 timeout 原因或自动释放任务。

以上方法只能用 transaction.Runner callback 提供的 context/session；调用方必须传播全部错误，不能吞错后提交业务的其他写入。真实业务负责单据存在、最新授权、目标、费用和成功/确定未执行的外部证据。仅保存来源类型不会创建真实提现或支付业务。

账户、占用、凭证、分录在同一事务写入；账本仍按单位平衡。初始凭证借可用、贷占用；核销借占用、贷对方；释放借占用、贷可用。结束凭证通过 original_voucher_id 指向初始凭证，account_hold 保存结果索引；历史分录不修改。普通 Post 无法使用 hold/consume/release 动作或构造占用分录。

用户账面总额等于可用加占用；占用余额与未结束占用金额合计一致。普通扣款只能消费可用余额。奖励申请继续在奖励业务扣减/退回，不进入此模型。商户资金归属和结算接入随商户工作项实现。

## 并发、等待与失败

Hold 借助唯一来源凭证拒绝重复；同参数和异参数重复都明确返回 ErrAlreadyHeld，不当作成功继续提交。结束动作先锁 account_hold，只有 held 能变成 consumed/released；重复或竞争失败返回 ErrHoldResolved。成功后的误操作必须由业务另建合法补偿，不重开占用。

账户统一按 user_id/kind 排序加锁；一次命令处理一笔占用。调用方先处理业务单据，再处理占用，最后进入账户锁；不得先持有资金账户锁再反向调用占用命令。多笔占用协同业务应在接入时安排完整锁序，不默认保证任意命令组合无死锁。

锁等待由 MySQL/InnoDB 处理，锁持续到整个外层事务结束，不等审核或链上确认。MySQL 会话锁等待上限及调用方 context 的截止/取消约束等待；入口没有独立无限队列或自动重试。资金写入使用有截止时间的请求/任务 context，且事务内不访问外部依赖。

余额不足、参数非法、占用缺失和已结束分别返回 ErrInsufficientBalance、ErrInvalidHold、ErrHoldNotFound、ErrHoldResolved。MySQL 1205/1213 归为 ErrAccountBusy，原始驱动错误仍在错误链；context 取消保持取消原因。全部错误向外传播，让 Runner 回滚。提交应答丢失仍按 transaction.Failure.Unknown 处理，不能猜测没有执行。

[3.4](幂等与事务.md) 已用内部互转单据落实稳定请求、同键异参、原单查询与有限重试；占用对应的提现/支付原单恢复随所属业务接入，公共事务不自动重试。可按业务类型/ID 使用 AccountHoldModel.FindOneByBusinessTypeBusinessId 查询原占用，再由业务决定恢复路径。

## 本人查询和页面

GET /v1/user/account-holds：status 可选 held/consumed/released；before 为占用 idx；limit 默认 20、最大 100，按占用创建 ID 倒序。返回金额字符串、USD、业务 idx、状态/原因、建立及处理时间、初始/结束凭证 idx。所有者来自 JWT，客户端不能指定别人的账户；游标仅决定位置。

钱包提供占用明细入口，支持状态过滤、分页和刷新，显示占用中/已扣款/已释放。无公开核销/释放按钮。原流水增加 balancePart 和 activity（posted/held/consumed/released）；占用/释放只展示可用侧活动，核销展示占用侧扣款。余额后值对应 balancePart；同一核销凭证的收款方仍显示正常入账。平台分录和对手余额不返回。

## 释放容量边界

3.3 实施复核补充：可用加占用总额必须小于 10^18，保证全部占用始终能退回可用余额列。否则两个列各自合法的新入账可能使后续释放溢出。沿用原 DECIMAL(36,18) 的字段容量，Go 金额校验与本轮数据库约束共同阻止这类入账，并验证极限金额下拒绝额外入账后仍能完整释放。
