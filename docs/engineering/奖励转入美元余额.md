# 奖励转入美元余额

4.7 已接通奖励转入本人美元余额：资格查询、幂等申请、自动到账、风控转人工、管理员通过或拒绝、申请记录及断网恢复。数据库要求 **business 14**。当前只通过本地 mock 风控与隔离依赖验证，真实评分及生产风控尚未接入。

## 开启本地流程

按 [开发与测试环境](开发与测试环境.md) 准备隔离数据库和认证配置，显式应用 business 迁移至 14。迁移不修改共享开发库或生产库，不生成用户资金。

后端配置增加以下显式测试设置；`UserID` 为隔离数据库中的内部用户 ID，不能使用客户端输入控制风控结果：

```yaml
Environment: local
Mode: dev
RewardRisk:
  Mode: mock
  DefaultDecision: allow
  Fixtures:
    - UserID: 1
      Decision: review
```

`allow` 模拟自动处理，`review` 模拟人工审核；此例为用户 1 转人工，其余允许自动处理。mock 不计算或伪造风控评分，只有 local/dev 可启用；其他环境启用会启动失败。未配置 `RewardRisk` 时不能发起新申请，历史及已受理申请的处理保留。修改配置重启生效。测试用户的 Pro 和奖励来自已接通的任务/抽奖流程，测试用例使用独立资金准备，不开放充值或公开发奖接口。

用户端入口为奖励首页「转入美元余额」，路由 `/#/reward-transfers`；记录 `/#/reward-transfer-history`。管理端 `/reward-transfers` 提供按状态分页的队列、申请详情、当次风控结果/策略/原因、审核人和审核说明。只有已完成首次改密且有效的管理员可审核；审核说明必填，提交前展示资金影响。

## 业务与风控边界

Pro、最低 $2 和可用奖励决定能否申请；本次没有新增任务或邀请门槛。换绑付款冻结不阻止奖励转入本人美元。申请处理仍复查用户状态和认证版本，禁用账户不能新申请；已经受理的资金继续审核结算，不因禁用而丢弃。

[风控接口](../../backend/logic/risk/reward.go) 独立于 [奖励转入用例](../../backend/logic/rewardtransfer/service.go)，取得结果后进入资金事务。外部调用不占用资金事务中的数据库锁；事务内重新校验用户、Pro、幂等和可用余额。风控不可用或结果不合法时明确报错，不创建新扣款申请。客户端须恢复原键，不能把网络错误或一次查询未找到理解为未执行。

每笔申请保存风控决定、策略版本和原因，后续审核、历史和重复提交使用原单。真实评分来源、尺度、阈值、结果时效与审核时限仍需后续落实，当前不默认生产放行，不把业务资格缺项与风险评分混为一谈。

## 资金与并发

美元金额精确到美分，最低 $2、手续费 0，目标固定为本人美元账户。

| 路径 | 同一事务内的资金动作 |
| --- | --- |
| 自动完成 | 扣 `reward_usd`，增加本人 `usd_balance`，保存申请和凭证 |
| 待人工审核 | 扣 `reward_usd`，贷系统 `reward_transit`，保存待审核申请和凭证 |
| 审核通过 | 借 `reward_transit`，增加本人 `usd_balance`，保存审核结果及日志 |
| 审核拒绝 | 借 `reward_transit`，退回本人 `reward_usd`，保存审核结果及日志 |

`reward_transit` 表示待审核资金，不是可用美元或额外奖励；不使用只支持美元余额的 Hold 来占用奖励账户。每个凭证按 USD 平衡，审核不再次扣奖励；拒绝退回的账单来源仍为奖励转入申请，不显示为新任务奖励。

申请锁定产品用户后复查原键；同用户同键金额不同报冲突。账本沿用统一账户锁序，竞争申请不能透支。审核锁定管理员、产品用户和申请，同一申请只从 `pending_review` 转为 `completed` 或 `rejected`。同审核人、同决定、同原因重试返回原单，不新增审核日志；相反决定或不同审核人/原因冲突，须刷新原单。审核与日志任一步失败全部回滚。

提交应答未知时查询原请求；未查到保留未知，不能自动生成新键。网页在请求发送前保存用户及 API 范围内的请求号和金额，多标签用 Web Locks 协调；刷新后只能查询或重试原申请。即使重试遇到余额不足，也不自动丢弃原键，避免更早的风控请求仍在执行时另起申请；奖励不足时保留金额，补足后可重试。审核结果未知时保留原决定，后台可刷新原单或重试该决定。

## 接口与迁移

唯一契约源为 [platform.api](../../backend/manifest/api/platform/platform.api)，生成 Go DTO/handler 和 TS 类型。用户接口使用产品 JWT，管理员接口使用独立后台 JWT；idx 不能代替归属校验。

| 接口 | 行为 |
| --- | --- |
| GET /v1/user/reward-transfer-state | Pro、最低金额、可用奖励、审核中金额、费用及是否接通风控 |
| POST /v1/user/reward-transfers | `requestKey` 与精确 `amount`，其余条件由服务端确定 |
| GET /v1/user/reward-transfers/by-request/:requestKey | 本人原请求恢复 |
| GET /v1/user/reward-transfers | 本人分页记录，before/limit |
| GET /v1/user/reward-transfers/:idx | 本人详情 |
| GET /v1/admin/reward-transfers | 按状态筛选的分页队列 |
| GET /v1/admin/reward-transfers/:idx | 申请、风控依据和审核详情 |
| POST /v1/admin/reward-transfers/:idx/review | `approve` 或 `reject`，必填审核说明 |

[000014 迁移](../../backend/manifest/sql/diff/business/000014_reward_transfer.up.sql) 与 [完整 DDL](../../backend/manifest/sql/ddl/rewardtransfer/tables.sql)、[约束](../../backend/manifest/sql/ddl/rewardtransfer/constraints.sql) 同步。已有申请时 [降级](../../backend/manifest/sql/diff/business/000014_reward_transfer.down.sql) 拒绝删除，需按迁移工具的 dirty 处理流程核对，不强制丢弃资金证据。
