# 前端公共基础

1.4 已建立用户、商户、平台三个独立 React 应用，以及请求、国际化、桌面布局共享包。2.4 已接通用户端登录、账户资料和身份管理；余额、订单、任务和支付页面仍显示“暂未开放”。已有健康联通开发样例。设计依据与验收见 [1.4 工作记录](../design/工程工作记录/01-工程基础/1.4-前端公共基础/01讨论记录.md)。

## 工程入口与依赖方向

| 位置 | 职责 |
| --- | --- |
| `frontend/apps/user/src` | Mini App/H5，Ant Design Mobile，先读取启动上下文，再创建 Hash Router |
| `frontend/apps/merchant/src`、`frontend/apps/admin/src` | 独立桌面应用、History Router、客户端和语言实例 |
| `frontend/packages/api-contract` | `.api` 生成类型，先改源定义再生成，不直接编辑产物 |
| `frontend/packages/api-client` | fetch 工厂、HTTP/envelope 校验、健康响应解码、分类错误、超时及取消 |
| `frontend/packages/i18n` | 独立实例工厂、zh-CN/en 公共资源、语言选择和精确展示 |
| `frontend/packages/ui-desktop` | 两个后台实际共用的布局和状态组件；用户端不引用 |
| `frontend/dev/DevPage.tsx` | 仅开发模式按需加载的健康联通、交互和展示检查 |
| `frontend/tests` | unit、e2e、integration 三类独立验证入口 |

调用为页面 → 本端 `api/request.ts` → api-client → HTTP。共享包不依赖应用，不存放全局会话；react-i18next 由 i18n 包直接管理，antd 由 ui-desktop 包直接管理，应用经共享包使用时不重复声明这些依赖；api-client 不依赖 React、UI 或 Telegram SDK。应用资源在各端 `locales`；页面进入 `view/<module>`。2.4 用户端 auth、api/account 与 view/login、account、identities 按实际功能接入；共享客户端只提供传输能力，不持有三端共用登录状态。

## 版本与启动

Node 24.22.1、pnpm 10.33.4 沿用既有基线。直接依赖固定版本并提交 lockfile：React/React DOM 18.3.1、React Router 7.18.4、Vite 8.3.5、Ant Design Mobile 5.43.0、Ant Design 6.6.8、i18next 26.5.11、react-i18next 17.1.9、`@tma.js/bridge` 2.3.3；TypeScript 5.9.3。React 18 适配本次移动组件的传递 peer 依赖范围，不强行忽略不兼容声明；后续升级复验整个组合。SDK 使用维护中的 tma.js 包，不额外加载官方全局脚本。

在 `frontend/` 执行（nvm 环境先加载 nvm）：

```sh
nvm use
pnpm install --frozen-lockfile
pnpm dev:user
# 在其他终端分别运行：
pnpm dev:merchant
pnpm dev:admin
```

用户、商户、管理端分别使用 `127.0.0.1:5173`、`:5174`、`:5175`，端口占用即失败。三个应用独立构建到各自 `dist/`，无需线上 Node 进程。开发检查页分别为 `/#/__dev`、`/__dev`、`/__dev`，不放入产品导航，生产构建不包含该模块。

默认客户端使用 `/api`，Vite 转发至 `http://127.0.0.1:8888` 并去掉 `/api` 前缀。`DEXWALLET_API_PROXY_TARGET` 可调整开发目标；`VITE_API_BASE_URL` 是公开的构建配置，禁止放入凭据。生产 API 代理和后台 History 回退在 1.5 落实，Vite preview 不证明线上代理正确。

## 路由、启动与状态

用户主入口为 `/#/wallet`、`/#/rewards`、`/#/records`；子页面有明确站内返回目标，缺失/非法来源回钱包，不能跳到任意外站。后台根入口转 `/overview`。各端有未知路径和路由错误页。页面草稿保留在组件内存，筛选/分页归 URL；没有全局状态库、查询缓存或敏感草稿持久化。

`user/src/app/telegram/bootstrap.ts` 在创建路由前保存原始 URL 证据，再调用 SDK 读取启动参数。SDK 负责原始参数的会话缓存；项目只保存启动指纹、启动编号和候选目标生命周期（pending/consumed/invalid），不另存原始 initData。指纹只关联同次启动，不是验签。新参数 hash 代表新启动；刷新/前进后退只有在当前应用路由、已保存生命周期和 SDK 指纹匹配时恢复。普通导航不借旧缓存伪装 Telegram 启动；没有 activated 推断逻辑。

刷新保持当前路由和已处理状态，新启动替换旧目标，新启动无目标不继承邀请。候选参数不一致或格式非法进入 invalid；这里只保留候选值，不解释业务协议、不自动执行绑定或付款。原始数据由 bootstrap 返回到启动入口的内存上下文，不加入请求默认头、路由、日志。2.4 在路由入口显式传递启动上下文给用户鉴权 Provider，Mini App 登录页交换原始材料。业务候选目标仍只保留，不在登录时消费邀请或发奖励。SDK 无法恢复时显示重新从 Telegram 打开的提示；普通浏览器仍可在存储禁用时使用。SDK 自身需要的会话缓存不可用时不伪造恢复成功。

合成启动参数已验证适配顺序和 SDK 恢复。2.2–2.4 已通过测试签名、公开接口与浏览器 mock 验证交换和站内来源恢复；真实 Telegram iOS/Android/Desktop/Web、BackButton 和 8.3 发布验证仍独立验收。

## 请求、国际化与展示

请求默认 10 秒，覆盖 fetch 和响应体读取，支持端点覆盖及调用方取消；没有自动重试。2026-10-29 起由原生 `AbortSignal.timeout` 和 `AbortSignal.any` 管理期限和取消组合，项目只映射错误分类，不再维护转发监听器、计时器和取消状态。timeoutMs 为正整数毫秒；采用浏览器活动时间语义，文档挂起期间由浏览器暂停计时。最先触发的信号决定分类，调用方自带 TimeoutError 仍算主动取消。成功同时满足 HTTP 成功、code=OK、完整 envelope 和端点数据校验。错误保留 kind/status/code/traceId/cause，未知 code 不丢失；页面按资源显示文案，不显示服务端原始 message。401 与 403 保持不同语义，用户端会话层处理 401，403 显示权限错误；公共层不跳转、不弹提示、不自动重放写请求。

语言顺序为本端手动偏好、受支持 Telegram 语言、浏览器支持项、英文。`en-*` 映射英文；`zh-Hans`、无脚本的 `zh-CN`/`zh-SG` 映射简体；繁体和裸 `zh` 继续下一来源。独立 `dexwallet:<app>:language` key，存储失败保留内存选择。切换更新组件 locale 和文档 lang，不重建路由或清空输入。所有产品文案来自资源；通用错误码用 errors 命名空间。

金额展示直接处理十进制字符串，不转 Number、不计算或舍入，保留单位、小数和未知值。时间接受明确的 epoch 毫秒，默认设备时区且显示偏移，可指定 IANA 时区。业务金额运算及统计时区由后续业务决定。

## 2.4 用户登录与身份管理

用户入口为 `/#/login`、`/#/account`、`/#/identities`。主导航新增登录/账户入口；登录成功恢复白名单中的站内目标，身份页接受 required=email / telegram 与 returnTo，成功后重新查询状态再由来源业务决定下一步。当前任务接口未实现，没有自动领奖或其他写操作重放。产品昵称支持修改，头像只展示；后续身份登录不覆盖产品资料。

身份页依据启动上下文 `mode=telegram` 禁用 Telegram 解绑按钮并展示国际化提示，解绑事件也在前端拦截。此限制只作用于 Telegram 端的 Telegram 解绑，不改变邮箱解绑、其他端身份操作或后端契约。

[session.ts](../../frontend/apps/user/src/auth/session.ts) 使用用户端独立 localStorage key `dexwallet:user:session`，仅持久保存 token 和随机认证代次，不保存用户资料。浏览器 Web Locks 串行同源标签页的写入，storage 事件同步退出/账户变更；缺少这些能力时保留内存登录并提示。普通退出、重新认证与身份变更改变代次，旧请求不能恢复已退出登录；只有同用户、同 issuer、同认证版本且更晚到期的响应头可以续签。旧 token 的迟到 401 不覆盖较新凭证。浏览器读取 claims 只用于排序，服务器仍独立验签授权。

[api-client](../../frontend/packages/api-client/src/index.ts) 仅增加每请求 headers 与成功解码后的 onSuccess 回调；用户端 [account API](../../frontend/apps/user/src/api/account.ts) 承担 Bearer、续签、解码与 401 处理。503 保留凭证、显示可重试错误；普通退出只清理本端，全部退出须等待后端成功。账户数据经 context 共享，账户切换后不展示另一用户的旧数据。

邮箱表单支持验证码、等待重发、过期提示、保留当前输入、未知结果时显式重试同一操作。验证码不写入持久存储。Telegram 复用原 SDK 材料，仅额外保存指纹与恢复请求令牌；同次启动主动退出后不自动重新登录，新的启动可以再次交换。绑定接口保持原 JWT、requestToken 与材料进行结果恢复，占用冲突不切换用户。

没有接入真实邮件/TG Bot 或原生 App Telegram 授权，也没有运行时测试凭据入口；必须按 [用户鉴权](用户鉴权.md) 配置后端能力。实现和证据见 [2.4 记录](../design/工程工作记录/02-用户与鉴权/2.4-用户接口与前端接入/03实施记录.md) 与 [验证记录](../design/工程工作记录/02-用户与鉴权/2.4-用户接口与前端接入/04验证记录.md)。
