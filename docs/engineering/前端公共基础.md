# 前端公共基础

1.4 已建立用户、商户、平台三个独立 React 应用，以及请求、国际化、桌面布局共享包。当前页面显示“暂未开放”；已有健康联通开发样例，尚无登录、余额、订单、任务或支付业务。设计依据与验收见 [1.4 工作记录](../design/工程工作记录/01-工程基础/1.4-前端公共基础/01讨论记录.md)。

## 工程入口与依赖方向

| 位置 | 职责 |
| --- | --- |
| `frontend/apps/user/src` | Mini App/H5，Ant Design Mobile，先读取启动上下文，再创建 Hash Router |
| `frontend/apps/merchant/src`、`frontend/apps/admin/src` | 独立桌面应用、History Router、客户端和语言实例 |
| `frontend/packages/api-contract` | `.api` 生成类型，先改源定义再生成，不直接编辑产物 |
| `frontend/packages/api-client` | fetch 工厂、HTTP/envelope 校验、健康响应解码、分类错误、超时及取消 |
| `frontend/packages/i18n` | 独立实例工厂、zh-CN/en 公共资源、语言选择和精确展示 |
| `frontend/packages/ui-desktop` | 两个后台实际共用的布局和状态组件；用户端不引用 |
| `frontend/dev/DevPage.tsx` | 仅开发模式按需加载的健康联通、交互和展示检查 |
| `frontend/tests` | unit、e2e、integration 三类独立验证入口 |

调用为页面 → 本端 `api/request.ts` → api-client → HTTP。共享包不依赖应用，不存放全局会话；api-client 不依赖 React、UI 或 Telegram SDK。应用资源在各端 `locales`；页面进入 `view/<module>`。本项没有创建空业务包或新增契约。

## 版本与启动

Node 24.22.1、pnpm 10.33.4 沿用既有基线。直接依赖固定版本并提交 lockfile：React/React DOM 18.3.1、React Router 7.18.4、Vite 8.3.5、Ant Design Mobile 5.43.0、Ant Design 6.6.8、i18next 26.5.11、react-i18next 17.1.9、`@tma.js/bridge` 2.3.3；TypeScript 5.9.3。React 18 适配本次移动组件的传递 peer 依赖范围，不强行忽略不兼容声明；后续升级复验整个组合。SDK 使用维护中的 tma.js 包，不额外加载官方全局脚本。

在 `frontend/` 执行（nvm 环境先加载 nvm）：

```sh
nvm use
pnpm install --frozen-lockfile
pnpm dev:user
# 在其他终端分别运行：
pnpm dev:merchant
pnpm dev:admin
```

用户、商户、管理端分别使用 `127.0.0.1:5173`、`:5174`、`:5175`，端口占用即失败。三个应用独立构建到各自 `dist/`，无需线上 Node 进程。开发检查页分别为 `/#/__dev`、`/__dev`、`/__dev`，不放入产品导航，生产构建不包含该模块。

默认客户端使用 `/api`，Vite 转发至 `http://127.0.0.1:8888` 并去掉 `/api` 前缀。`DEXWALLET_API_PROXY_TARGET` 可调整开发目标；`VITE_API_BASE_URL` 是公开的构建配置，禁止放入凭据。生产 API 代理和后台 History 回退在 1.5 落实，Vite preview 不证明线上代理正确。

## 路由、启动与状态

用户主入口为 `/#/wallet`、`/#/rewards`、`/#/records`；子页面有明确站内返回目标，缺失/非法来源回钱包，不能跳到任意外站。后台根入口转 `/overview`。各端有未知路径和路由错误页。页面草稿保留在组件内存，筛选/分页归 URL；没有全局状态库、查询缓存或敏感草稿持久化。

`user/src/app/telegram/bootstrap.ts` 在创建路由前保存原始 URL 证据，再调用 SDK 读取启动参数。SDK 负责原始参数的会话缓存；项目只保存启动指纹、启动编号和候选目标生命周期（pending/consumed/invalid），不另存原始 initData。指纹只关联同次启动，不是验签。新参数 hash 代表新启动；刷新/前进后退只有在当前应用路由、已保存生命周期和 SDK 指纹匹配时恢复。普通导航不借旧缓存伪装 Telegram 启动；没有 activated 推断逻辑。

刷新保持当前路由和已处理状态，新启动替换旧目标，新启动无目标不继承邀请。候选参数不一致或格式非法进入 invalid；这里只保留候选值，不解释业务协议、不自动执行绑定或付款。原始数据仅留在内存上下文供后续认证交换使用，不加入请求默认头、路由、日志。SDK 无法恢复时显示重新从 Telegram 打开的提示；普通浏览器仍可在存储禁用时使用。SDK 自身需要的会话缓存不可用时不伪造恢复成功。

合成启动参数已验证适配顺序和 SDK 恢复。真实 Telegram iOS/Android/Desktop/Web、签名校验、会话交换、BackButton 和来源页恢复仍属于 2.2–2.4；8.3 执行完整发布验收。

## 请求、国际化与展示

请求默认 10 秒，覆盖 fetch 和响应体读取，支持端点覆盖及调用方取消；没有自动重试。2026-10-29 起由原生 `AbortSignal.timeout` 和 `AbortSignal.any` 管理期限和取消组合，项目只映射错误分类，不再维护转发监听器、计时器和取消状态。timeoutMs 为正整数毫秒；采用浏览器活动时间语义，文档挂起期间由浏览器暂停计时。最先触发的信号决定分类，调用方自带 TimeoutError 仍算主动取消。成功同时满足 HTTP 成功、code=OK、完整 envelope 和端点数据校验。错误保留 kind/status/code/traceId/cause，未知 code 不丢失；页面按资源显示文案，不显示服务端原始 message。401 与 403 保持不同语义，后续会话层自行处理；公共层不跳转、不弹提示、不自动重放写请求。

语言顺序为本端手动偏好、受支持 Telegram 语言、浏览器支持项、英文。`en-*` 映射英文；`zh-Hans`、无脚本的 `zh-CN`/`zh-SG` 映射简体；繁体和裸 `zh` 继续下一来源。独立 `dexwallet:<app>:language` key，存储失败保留内存选择。切换更新组件 locale 和文档 lang，不重建路由或清空输入。所有产品文案来自资源；通用错误码用 errors 命名空间。

金额展示直接处理十进制字符串，不转 Number、不计算或舍入，保留单位、小数和未知值。时间接受明确的 epoch 毫秒，默认设备时区且显示偏移，可指定 IANA 时区。业务金额运算及统计时区由后续业务决定。

## 检查入口

在 `frontend/` 执行：

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium webkit
# Linux 首次缺少浏览器系统库时，按 Playwright 提示安装所需依赖。
pnpm test:e2e
```

单元检查使用 Vitest 5.0.5、Testing Library；浏览器检查使用 Playwright 1.64.1，自动启动三个开发服务和三个 preview 服务，需要 5173–5175、4173–4175 空闲。先 build 再 test:e2e。两种浏览器验证路由/语言、窄屏触控、错误恢复、真实 SDK 的合成启动和生产路由隔离。构建阶段检查实际 chunk 模块，拒绝开发样例进入生产及桌面库进入用户包；另检查产物与 manifest。

真实后端验证单独运行。1.5 已扩展为三端 dev/preview，通过 `DEXWALLET_TEST_HTTP_MYSQL_DSN` 指定精确授权的专用库；本地目标保护、准备和清理见 [开发与测试环境](开发与测试环境.md)。在 `frontend/` 执行 `pnpm test:integration`，或仓库根 `bash scripts/check.sh http`。

runner 先校验目标和端口，再构建当前 API/三端，启动自己的测试服务；覆盖 live/ready、traceId、404、路由刷新和停服后显式重试。HTTP 配置关闭 Redis/MQ，其真实操作另由 integration 验证。长期 HTTP 测试库不被创建/迁移/清理，API 不持有测试管理员凭据。运行证据位于忽略的 `.tools/http-runs/` 和 `frontend/test-results/`。

契约与文档原有入口继续有效；1.4 历史结果见 [1.4 验证记录](../design/工程工作记录/01-工程基础/1.4-前端公共基础/04验证记录.md)，本轮新增覆盖见 [1.5 验证记录](../design/工程工作记录/01-工程基础/1.5-开发与测试环境/04验证记录.md)。
