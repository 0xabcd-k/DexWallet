# 任务与奖励运营

4.8 接通邀请成果、任务配置、完成记录和抽奖版本管理。奖励首页、领奖、抽奖、奖励转入及审核沿用 4.2–4.7。当前数据库要求 **business 15**，仅完成本地 mock 开放范围；没有接入真实 Telegram 频道、真实风险评分或生产奖表。

## 页面与配置

| 入口 | 已实现能力 |
| --- | --- |
| 用户奖励首页 → 邀请成果 `/#/invitations` | 四项累计成果、绑定好友、本人助力/分成明细，好友 idx、类型、UTC 日期筛选与分页，查看本人奖励结果 |
| 管理端 `/tasks` | Telegram 频道 mock 草稿、预览、发布/暂停/恢复、完成记录分页 |
| 管理端 `/draw-versions` | 创建不可变奖表版本、预览、启用指定版本或暂停抽奖 |
| 管理端 `/reward-transfers` | 复用 4.7 的独立风控证据、人工审核、结果恢复 |

按 [开发与测试环境](开发与测试环境.md) 准备隔离依赖并应用迁移至 15。任务必须显式配置 `Environment: local`、`Mode: dev`、`Tasks.Mode: mock`，成员结果由 `Tasks.Fixtures` 的频道 ID、Telegram 数字用户 ID 与状态决定，配置方法见 [任务基础](任务基础.md)。后台只创建任务定义，不改运行时 fixture，也不会调用真实 TG API。新频道 ID 若没有匹配 fixture，检查不会冒充已关注；如需模拟关注，修改本机 fixture 并重启。

抽奖沿用 local/dev 开关；保存版本和启用版本分开，未启用时用户不能新抽奖。其他环境保留只读记录与暂停能力，不能通过后台绕过生产限制。默认显示七档候选值供填写测试，不能视为生产批准。多语言界面已接入现有资源；任务内容保持现有单套标题/说明字段，可填双语文案，按语言分别维护任务内容仍未实现。

## 任务与并发规则

草稿可修改标题、说明、基础积分、mock 频道和有效期；只支持已实现的 Telegram 频道关注类型。日期以 UTC 保存，有效期必须开始早于结束；积分沿用积分账户的精度和容量，并检查 Pro 翻倍后的单笔值；基础积分在 API 与浏览器间以整数字符串传输，避免大整数被 JavaScript 改写。

生命周期为 `draft → active ↔ paused`。发布后规则与内容不再编辑，需要变更则新建任务；这避免同一任务的参与次数、旧邀请与新奖励混用。发布、暂停和草稿修改都增加 `revision`，既有领奖事务会重新校验版本和有效期。已完成记录保留当时标题、版本、模式和受益用户。

创建键按管理员隔离，保存原始规范化请求的摘要。相同键与相同创建内容重试返回原任务，即使任务后来已被编辑；同键不同内容冲突。网页发请求前持久保存创建/编辑请求，断网或刷新后使用原键原内容重试。非确定结果不当作未创建。管理员身份变更后不会读取其他管理员的待处理草稿。

编辑与状态操作携带 `expectedRevision`。旧版本不能覆盖新修改；已应用的相同请求可以返回当前结果，不重复写审计。状态冲突后需刷新查看，页面不会自动以新版本重发。管理员锁、任务行锁、写入和审计处于同一事务，审计失败全部回滚。

## 抽奖版本

版本名唯一、内容不可变。同名相同内容返回已有版本，同名不同内容冲突；保存仅新增候选版本。七档金额、权重、图案和 RTP 由后端精确校验，权重合计 10000，期望回报必须与 RTP 相符，不使用浮点近似决定是否发布。

启用/暂停修改 `draw_control` 指针并增加版本号，携带期望版本避免“切走后又切回”的旧提交覆盖。配置事务与审计一起提交；并发抽奖仍通过原有共享锁读取版本，原单不因切换或暂停丢失，历史结果按原奖表读取。开发工具 `drawdemo` 也更新该版本号。

## 邀请成果与归属

邀请成果页四项累计值来自已鉴权的 `GET /v1/user/reward-summary`。绑定好友数（`friendCount`）统计当前用户作为直接上级的全部绑定关系，有效助力次数（`assistanceCount`）按本人收到的助力奖励笔数统计，同一好友完成不同任务可分别计次。累计助力积分（`assistancePoints`）和累计分成积分（`commissionPoints`）分别合计对应类型的实际入账积分，以整数字符串返回。无记录时四项均为零。好友、类型、日期筛选和翻页仅作用于明细。

好友列表来自本人作为直接上级的已提交绑定关系，只返回产品 idx、昵称和绑定时间；不返回邮箱或 Telegram ID。收益只能查询归属本人的 `assistance` 与 `commission` 奖励，链接指向本人奖励明细，不能读取好友私有账单。

助力收益来源是实际完成任务的帮助者；分成来源是实际取得任务积分的直接下级。下级被第三人帮助时，分成仍归属于下级贡献，不错误标为第三人的贡献。好友筛选针对此来源，日期按 UTC 自然日计算，结束日包含全天；新记录用独立游标分页。

## 契约、权限与迁移

源定义为 [platform.api](../../backend/manifest/api/platform/platform.api)，生成 Go 与 TypeScript 契约后填写手写适配层。管理员操作必须持有有效管理端身份且已完成首次改密，商户及普通用户不能访问；写操作再次锁定并验证管理员状态。

| 接口 | 行为 |
| --- | --- |
| GET /v1/user/reward-summary | 本人全量邀请统计、首任务与 Pro 状态 |
| GET /v1/user/referral-friends | 本人绑定好友，before/limit |
| GET /v1/user/invitation-earnings | 本人邀请收益，before/limit/friendIdx/reason/from/to |
| GET /v1/admin/tasks | 全状态任务列表及可写状态 |
| POST /v1/admin/task-drafts | 创建或编辑草稿，requestKey、expectedRevision、reason |
| POST /v1/admin/tasks/:idx/status | 发布、恢复或暂停，expectedRevision、reason |
| GET /v1/admin/tasks/:idx/completions | 完成事实与规则快照摘要 |
| GET /v1/admin/draw-versions | 版本列表、当前指针和 revision |
| POST /v1/admin/draw-versions | 校验并保存不可变版本，reason 必填 |
| POST /v1/admin/draw-control | 设置版本或留空暂停，expectedRevision、reason |

[000015 升级](../../backend/manifest/sql/diff/business/000015_reward_operations.up.sql) 给任务增加创建幂等键及摘要，给抽奖控制增加 revision；完整 DDL 和生成模型同步。已有任务保留 NULL 创建键，不补造历史请求。迁移不创建任务、奖表、用户资金或默认启用指针。[降级](../../backend/manifest/sql/diff/business/000015_reward_operations.down.sql) 在新创建键或控制版本已使用时拒绝抹去证据，失败需按迁移工具流程核对 dirty 状态，不能强制降级。
