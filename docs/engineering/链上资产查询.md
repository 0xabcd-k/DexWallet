## 本批范围

2026-11-16 接通 5.2 首批只读查询：App 首页/设置的「链上资产」进入 `/chain-assets`，可切换本机钱包或已恢复的 TON 外部连接、选择网络、查看数量/完整代币标识/精度/查询时间、搜索与收藏。内置钱包优先；只有 ready 且本机密钥记录存在的条目可选，查看不解锁密钥。外部 TON 连接仅允许其实际网络，不将测试地址切到主网。Mini App 不打包此页面或原生钱包模块。

完整 5.2 的收款码、直接转账、签名、广播与交易记录仍待后续批次；报价/美元估值归 5.4。持仓数量不代表可支付金额，冻结代币也可能计入持有数量；付款框沿用已确认的不展示持仓规则。不新增中心化账户入账、占用或手续费。数据库仍为 business 15。

## 接口与故障语义

源定义：`backend/manifest/api/platform/platform.api`，生成 Go handler/types/routes 与 `frontend/packages/api-contract/src/platform.ts`。两个接口都要求有效产品登录：

- `GET /v1/user/chain-assets`：返回网络、enabled、testnet 和资产目录；不返回 RPC 地址或密钥。
- `POST /v1/user/chain-assets/balances`：请求 `{network,address}`，查询该网络的全部支持资产；响应含规范化公开地址和各项 `assetId/quantity/status/errorCode/queriedAt`。时间为 Unix 毫秒。

公开地址来自钱包，但查询任意有效公开地址不证明所有权，也不授予支付权限。未登录 401，未知网络/地址无效 400，未配置网络或限流依赖失败 503，超频 429。节点单项故障仍返回目录对应项：`status=unavailable`、`quantity=""`，错误为 `UPSTREAM_UNAVAILABLE`、`UPSTREAM_INVALID` 或 `NETWORK_MISMATCH`；成功包括明确零值，`status=ok`、`errorCode=NONE`。前端不可把失败折算为零或美元金额。

App 切换钱包/网络卸载原查询，取消请求并阻止迟到响应更新新页面；刷新先清空旧数量。收藏按产品用户存入本机 NativeState 的 `dexwallet:asset-favorites:v1:<userIdx>`，只包含资产 ID。收藏与浏览不会被当成实际支付使用频次。

## 部署配置

默认所有网络未启用，不进行隐式链上请求。网络 URL 与密钥由服务器配置：环境变量前缀为 `DEXWALLET_CHAIN_`，将网络 ID 转成大写并将 `-` 换为 `_`，然后添加 `_RPC_URL`、可选 `_API_KEY`、测试网可选 `_TEST_USDT_CONTRACT`。例如：

```bash
export DEXWALLET_CHAIN_BASE_SEPOLIA_RPC_URL=https://sepolia.base.org
export DEXWALLET_CHAIN_SOLANA_DEVNET_RPC_URL=https://api.devnet.solana.com
export DEXWALLET_CHAIN_TON_TESTNET_RPC_URL=https://testnet.toncenter.com
export DEXWALLET_CHAIN_TRON_NILE_RPC_URL=https://nile.trongrid.io
```

密钥使用部署环境注入，不写入仓库或 App。`ChainAssets.Networks` 也支持 `Network/URL/TestUSDTContract` 配置，环境覆盖对应项；`APIKey` 运行时字段只从环境注入。TON URL 是兼容 Toncenter v2/v3 的根地址；TRON 是 full node 根地址；Base/Solana 是 JSON-RPC 完整端点。API key 作为 `X-API-Key` 发出，TRON 使用 `TRON-PRO-API-KEY`。有网络配置时必须启用 Redis。

`ChainAssets.Timeout` 默认 3 秒，允许大于 0 且不超过 30 秒，同时受 HTTP 请求自身截止时间限制；`PerUserPerMinute` 默认 30 次、突发 5 次。限流 Redis key 为 `rate:<namespace>:chain_assets:query:user:<internal ID>`，生产多实例共享。HTTP 最大响应 2 MiB、拒绝重定向、按网络最多并发三项，无余额缓存和自动重试。日志包含网络/公开地址/资产/错误类别，不带上游 URL、API key 或上游原始正文。

Base 每次检查 chain ID 8453/84532；Solana 每次检查主网/Devnet genesis hash。TON/TRON 本批依赖运维将网络映射到正确的官方或可信节点，没有实现链级网络身份校验，部署必须核对目标环境。TON Jetton 使用 v3 索引，可能滞后；多资产查询也不是同一区块的原子快照。这些读数只能用于展示，未来资金核验须按 5.3 的确认和真实入账标准实施。

## 实现与检查

后端 `backend/logic/chainassets` 在共享 `ServiceContext` 组装、退出关闭 HTTP 连接。地址解析使用 `tonutils-go/address v1.15.5`、`base58 v1.3.0` 和已有 `x/crypto`；避免仅为地址校验升级其他依赖。Base 调用 `eth_getBalance/eth_call`，Solana 调用 `getBalance/getTokenAccountsByOwner`，TON 调用 v2 `getAddressBalance` 与 v3 `jetton/wallets`，TRON 调用 `getaccount/triggerconstantcontract`。仅查询固定白名单资产，没有签名或广播方法。

协议依据：[Solana Token Accounts](https://solana.com/docs/rpc/http/gettokenaccountsbyowner)、[TON Jetton wallets](https://docs.ton.org/api/v3/jettons/get-jetton-wallets)、[TRON constant call](https://developers.tron.network/reference/triggerconstantcontract)。

普通检查不访问节点。真实测试网只读探测是独立 `integration` 测试，显式配置上述测试网络后执行：

```bash
cd backend
DEXWALLET_TEST_CHAIN_ASSETS_LIVE=1 go test -tags=integration ./logic/chainassets -run '^TestLiveReadOnly$' -count=1 -v
```

可选 `DEXWALLET_TEST_CHAIN_ASSETS_EVIDENCE` 将公开结果保存到指定路径。此测试仅查询代码列出的历史公开测试地址，不读取私钥、不领取测试币、不签名或广播。测试替代币身份参考 5.1 既有验证文档。真实登录/Redis 限流验证沿用隔离 `TestProductSessionHTTP`，RPC 在 HTTP 边界 fake；命令和实测结果见 [5.2 验证记录](../design/工程工作记录/05-钱包与链上通道/5.2-链上资产与直接收发/04验证记录.md)。
