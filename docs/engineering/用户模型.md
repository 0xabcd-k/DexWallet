# 用户模型与 idx

2.1 已建立用户、邮箱身份、Telegram 身份的持久化与可信内部用例。2.2 的验证码、Telegram 验签与绑定变更已由 2.3 [公开鉴权入口](用户鉴权.md)接入，内部可信方法仍不能绕过认证直接暴露。

## 表与生成

权威源为 [tables.sql](../../backend/manifest/sql/ddl/user/tables.sql) 和 [constraints.sql](../../backend/manifest/sql/ddl/user/constraints.sql)。用户和两种外部身份分别建表，身份表以可空 user_id 直接指向用户，每用户每种身份最多一个；邮箱地址和 Telegram 用户 ID 各自唯一。解绑保留身份行及 binding_version。user 表仅存数值 id，不存 idx、奖励或余额。

生成器显式读取 tables.sql，使用现有 goctl 生成 [model](../../backend/model/user/user_model_gen.go)。外键通过独立 ALTER TABLE 执行，不进入 goctl 解析器。手写 model 扩展提供 WithSession、锁定查询及用户缓存边界，纯生成 SQL CRUD 保持无缓存；完整迁移为 [business/000001](../../backend/manifest/sql/diff/business/000001_create_user_model.up.sql)。

```sh
# 仓库根；不连接数据库
python3 scripts/generate.py
python3 scripts/generate.py --check
```

迁移工具支持 `--source business`，目前仍仅接受显式本地 contract 测试库与受限账号；正式环境发布入口归 8.2。business 使用 schema_migrations_business，examples 继续使用 schema_migrations，版本记录互不覆盖。应用启动不执行迁移。命令及隔离前提见 [契约生成与迁移](契约生成与迁移.md)。

## 内部用例

[ServiceContext](../../backend/svc/service_context.go) 用同一数据库连接组装三个 model、transaction.Runner 和 Users 用例；[logic/user](../../backend/logic/user/service.go) 仅接收所需依赖，不另建依赖容器。

| 方法 | 使用边界 |
| --- | --- |
| ResolveOrCreateVerifiedEmail | 鉴权层验证邮箱后调用；去首尾空白、仅域名小写，保留邮箱本地部分大小写、点号和加号，不合并供应商别名 |
| ResolveOrCreateVerifiedTelegram | 仅接受服务端已验证且仍有效的完整资料快照；缺失可选字段置 NULL，不能传局部补丁。2.2 按来源构造完整快照后调用 |
| FindUserByID | 查询内部正数 id；启用 Redis 时按 id 缓存用户 30 秒，不存在、数据库失败和缓存不可用分别返回，禁用记录仍可用于诊断 |
| FindCurrentIdentities | 先锁定用户，在同一事务读取两种身份；缺少身份返回 nil，不把缺 TG 当成未登录 |
| CheckCurrentBindingInSession | 使用外层 session，先锁用户再锁指定类型身份，验证状态、归属和版本；不独立提交。多用户场景须先按升序锁全体用户 |

邮箱/TG 首次创建候选用户和绑定在同一事务提交。普通读只定位候选归属，事务内必须重新锁定并复查；新身份先 INSERT 再锁定读取，减少空记录查询的间隙锁竞争。身份唯一键竞争、归属变化及已回滚的死锁最多解析三次；提交结果未知、回滚失败、其他数据库错误立即向上传递。竞争失败的候选用户随事务回滚，已占用身份不会被覆盖。

正常重复登录保留用户和 binding_version；无归属身份再次认证会新建产品用户，保留原身份 ID 并增加版本。禁用账户拒绝解析登录。TG 资料只在首次创建时初始化产品昵称头像；初始昵称超过产品 128 字符容量时仅截取派生显示值，外部 first_name 完整保留，后续资料更新不覆盖产品资料。

数据库时间按 UTC 保存；ServiceContext 与隔离测试连接显式设置 MySQL session time_zone 和 Go 时间解析位置。调用方传入已验证身份是内部前置条件，不是客户端提交 verified=true 的替代认证机制。

## 用户缓存

2026-10-29 用户确认 30 秒缓存及异常时的短暂旧状态。实现位于 [cache.go](../../backend/model/user/cache.go) 和 [user_model.go](../../backend/model/user/user_model.go)，仅缓存 user 主键查询的完整已提交记录。键为 `dexwallet_<environment>:user:<id>`，ServiceContext 复用现有 go-redis 客户端、DB、超时和退出流程；Redis.Enabled 为 true 时自动组装。显式关闭 Redis 的健康测试环境仍使用无缓存 model，不是运行时 Redis 故障降级。

- 有效期固定 `UserCacheTTL = 30s`，命中不写入、不延长；没有额外进程内数据缓存。过期后由下一次请求回源，没有后台定时刷新。
- 复用 go-zero `syncx.SingleFlight` 合并同一 model/cache 实例的并发回源；它不是跨进程锁。每个调用者获取独立用户值，避免修改共享指针。
- 新快照的截止时间在 SQL 查询开始前确定；回填只写剩余 TTL，并在读取时复查快照截止时间，慢查询晚于变更/删缓存回填时不会重新获得完整 30 秒。此窗口依赖服务端时钟一致；外部运维修改也必须走约定更新路径或接受原快照过期。
- Redis 读取/写入失败、内容损坏返回 `ErrCacheUnavailable`；不能当作缓存未命中直查数据库或当作有效用户。不存在的用户不缓存，数据库错误保持原语义。
- WithSession 下的 FindOne 和 FindForUpdate 直接查询数据库，不读取或填充缓存。登录身份解析、绑定变更和未来扣款/领奖的事务校验均使用该路径。
- Update/Delete 在普通自动提交成功后删缓存；事务内通过 `transaction.AfterCommit` 登记，外层提交完成后去重执行，回滚不删。提交结果未知也尝试删除，因为数据库可能已成功；原有未知结果和禁止盲目重试语义不变。带缓存的事务写入必须传入 Runner 的回调 context，缺失时在 SQL 写入前拒绝。
- 删除缓存使用脱离请求取消的 1 秒预算，失败记录用户 id 与原因，不能把已提交业务伪装成回滚或要求重新执行。30 秒快照截止时间作为故障与旧读回填的兜底，不承诺严格即时一致。

没有直接开启 goctl 的 `--cache`：锁定版本 go-zero v1.10.3 的 [cacheNode](https://github.com/zeromicro/go-zero/blob/v1.10.3/core/stores/cache/cachenode.go) 默认对 TTL 做 ±5% 抖动，其 Redis 封装不能直接复用本项目的客户端 DB 配置和生命周期；[CachedConn](https://github.com/zeromicro/go-zero/blob/v1.10.3/core/stores/sqlc/cachedsql.go) 的写后失效也不是当前外层事务的提交回调。项目只在手写 user model 增加固定快照期限及失效时序，Redis 命令、序列化、并发合并仍使用现有库，无新依赖、SQL 或迁移。

普通鉴权可在该窗口内看到旧状态/认证版本，已由用户接受；关键写操作仍在事务中复查最新状态。2.3 鉴权中间件已在 context 中复用同一用户快照，并将缓存故障映射为 HTTP 503；当前用户接口不再重复查询。实现与证据见 [2.3 实施记录](../design/工程工作记录/02-用户与鉴权/2.3-产品会话/03实施记录.md) 和 [验证记录](../design/工程工作记录/02-用户与鉴权/2.3-产品会话/04验证记录.md)。

## idx 配置与使用

[idcodec](../../backend/idcodec/codec.go) 复用 `github.com/capitalone/fpe/ff1 v1.2.1`，格式参照 dexpoker：正数 id 至少补齐 16 位，以 UserId 类型参数编码并加 0 前缀；支持正 int64 上界。输出为字符串，接收时解码并按内部 id 查询，不需要额外映射表。编码不能替代认证、存在性和资源权限检查。

新增必填环境变量 `DEXWALLET_ID_SECRET`，值是 16、24 或 32 字节的原始密钥字符串，不做十六进制解码。启动时验证长度；缺失或非法会明确失败。生产配置保持稳定且所有副本一致，不能每次启动随机生成；变更前须处理既有 idx 兼容性。本地 prepare_local 首次准备会保存随机 32 字符值到忽略的 `.tools/local.env`；已有本机环境本轮已补齐该项，其他已有环境需单次补充后重新 source，保留原凭据与数据库。

每次编解码独立构造 FF1 cipher，避免共享库中的可变 CBC 状态；依据为 [上游 FF1 实现](https://github.com/capitalone/fpe/blob/v1.2.1/ff1/ff1.go)。空串、错误前缀、非法长度/字符、非规范编码、溢出及非正结果均明确拒绝。未来增加其他业务类型时新增具名参数，不使用外部平台账号作为产品 ID。
