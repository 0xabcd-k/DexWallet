# 后台鉴权与 super

2.5 已实现管理、商户两端登录及权限基础。与产品用户共用一个 API 服务，账户分别存储在 `admin_user`、`merchant_user`；不创建第三种设备会话或后台通用角色系统。确认依据见 [实施方案](../design/工程工作记录/02-用户与鉴权/2.5-后台登录与权限基础/02实施方案.md)。

## 数据与配置

源定义为 [后台 DDL](../../backend/manifest/sql/ddl/backoffice/tables.sql)，后台鉴权相关的最后增量为 [000004](../../backend/manifest/sql/diff/business/000004_redis_proofs.up.sql)，当前保留两张账户表和只读操作记录表；000003 创建的临时验证码表已由 000004 删除，三端验证码统一存 Redis。应用不自动迁移、不初始化默认账户。隔离库迁移继续使用 [契约生成与迁移](契约生成与迁移.md) 的显式工具；当前迁移工具只允许 `dexwallet_contract_` 库，生产迁移流程尚未开放，不能把示例命令直接用于生产库。

在现有 API 配置中增加 `Backoffice: {}`，并配置 [用户鉴权](用户鉴权.md) 中的 Auth/SMTP；两端验证码复用同一邮件适配器，验证码内容不会作为 API 返回值。至少注入以下环境变量：

| 变量 | 要求 |
| --- | --- |
| DEXWALLET_ADMIN_TOKEN_SECRET | 管理端独立随机签名密钥，至少 32 字节 |
| DEXWALLET_MERCHANT_TOKEN_SECRET | 商户端独立随机签名密钥，至少 32 字节 |
| DEXWALLET_AUTH_SECRET | 验证码 HMAC 密钥，至少 32 字节 |
| DEXWALLET_ID_SECRET | 沿用当前 idx 密钥；后台新增 AdminId/MerchantId 编码类型 |
| DEXWALLET_MYSQL_DSN | 已执行 business 迁移的明确目标库 |
| DEXWALLET_REDIS_PASSWORD、DEXWALLET_SMTP_PASSWORD | 按已有 Redis/SMTP 配置提供 |

两端 JWT 密钥必须互不相同，并且不同于产品 `DEXWALLET_TOKEN_SECRET` 和验证码密钥。三端分别验证 audience；后台账户的邮箱在各自表内唯一，不合并邮箱本地部分大小写或别名。省略 Backoffice 时后台接口返回 503；未配置邮件时可以使用服务器工具，但后台登录返回 503，不绕过验证码。

## 服务器工具

从 `backend/` 构建：

```bash
go build -o ../.tools/super ./tools/super
```

在服务器上使用与 API 一致的配置及环境变量。以下为 Bash 示例，密码通过隐藏输入和 stdin 传入，不能把密码写在命令参数或文档中：

```bash
read -r -s -p 'Temporary password: ' dexwallet_admin_password
printf '\n'
printf '%s\n' "$dexwallet_admin_password" | ../.tools/super \
  -f /path/to/platform.yaml --action create-admin \
  --email admin@example.com --reason 'Initial administrator' --password-stdin
unset dexwallet_admin_password
```

每一个管理员都由此工具创建，网页和 API 没有创建管理员的入口。密码 12–72 字节，bcrypt.DefaultCost 散列；工具输出 idx、邮箱和状态，不输出原始密码。创建、重置、启用均写操作记录，执行者为 super。工具共用 ServiceContext 和业务层，关闭不需要的 MQ，不启动 HTTP 服务。

- `--action create-admin --email <邮箱> --password-stdin`：创建临时密码账户；重复邮箱返回冲突。
- `--action reset-admin --idx <idx> --password-stdin`：重置临时密码、推进认证版本，旧凭证失效；不会自动启用被禁用的账户。
- `--action enable-admin --idx <idx>`：启用账户；重复启用不再推进认证版本。
- 所有命令必须填写 `--reason`，本机恢复不能免除之后的密码与邮箱验证码登录。

失去管理员入口时可在服务器重置/启用已知 idx，或创建新的管理员；业务 API 不提供跳过验证码的恢复凭证。工具超时或网络结果未知时先查实际账户/审计，再决定是否重试；重置密码每次提交都视为新的重置操作。

## 登录、权限和缓存

先验证邮箱＋密码并发送验证码，再提交密码＋挑战号＋验证码。验证码有效期 5 分钟、重发间隔 60 秒、最多错误 5 次；绑定所属端、邮箱及认证版本。已消费、过期、重置前或其他账户/所属端的材料不能登录。发送和校验复用 Redis 限流，HTTP 来源只采用 RemoteAddr；代理部署规则沿用用户鉴权说明。

临时密码登录成功后仍发同一种 JWT，但后端仅允许查看当前账户和改密。修改后认证版本增加，当前端收到新 token；密码重置、启禁用也使旧版本失效。普通退出只清理当前端凭证，三端均没有公开全部退出按钮或接口；产品内部 LogoutAll 保留。登录后敏感操作的额外验证已确认延期。

JWT 3 天有效，剩余不足 36 小时时通过 `X-Access-Token` 返回同版本的新 token，无累计 30 天上限。普通鉴权读取 Redis 30 秒缓存，命中不延长有效期；成功回填时设置 30 秒 TTL，变更提交后删除缓存。缓存读写失败或损坏时记录日志并查 MySQL；接受并发旧读回填后的短暂旧值，不再承诺从查询起点计算的严格 30 秒上界。验证码、限流和防重放仍在 Redis 故障时拒绝。创建、改密和状态变更在事务内锁定并复核最新账户及权限；最后一名可用管理员不能被禁用。只有管理员状态操作锁定管理员集合；创建和改密不再全量锁，涉及两名管理员的密码重置按 id 升序锁相关行。列表、审计、用户展示不启事务；写操作与普通展示采用不同一致性要求。

成功管理变更与操作记录同事务，记录失败则回滚；登录成功和失败操作记录为尽力写入，记录失败只记日志，不把登录成功改为失败，也不覆盖原业务错误；提交结果未知尽力另记 unknown，不能视为确定失败或据此自动重试；通过输入校验、进入业务处理的登录/管理失败另存失败记录，格式校验及限流拒绝由统一请求日志追踪。审计不保存密码、验证码、token，包含动作、所属端、执行/目标 idx、可记录的前后状态、原因和 traceId。表不会自动清空；当前按 id 倒序分页，50 条一页。后端 PageSize 与前端 BACKOFFICE_PAGE_SIZE 是同一固定分页约定，调整时必须同时更新；尚未引入 hasMore 契约。审计前后状态按动作国际化，人工原因保持原文。

## API 与页面

实际契约见 [platform.api](../../backend/manifest/api/platform/platform.api)：

| 路径 | 能力 |
| --- | --- |
| POST /v1/admin/auth/code、/v1/merchant/auth/code | 验证密码后发送邮箱验证码 |
| POST /v1/admin/auth/login、/v1/merchant/auth/login | 密码和邮箱验证码同时通过后登录 |
| GET /v1/admin/current、/v1/merchant/current | 当前账户 |
| POST /v1/admin/password、/v1/merchant/password | 校验原密码并改密 |
| GET /v1/admin/accounts | 按 admin/merchant 查询账户分页 |
| POST /v1/admin/merchants | 创建商户用户 |
| POST /v1/admin/accounts/status、/v1/admin/accounts/reset | 启禁用、重置临时密码 |
| GET /v1/admin/user、POST /v1/admin/user/status | 按产品 idx 查询、启禁用产品用户 |
| GET /v1/admin/audits | 只读操作记录分页 |

前端 `pnpm dev:admin`（5175）、`pnpm dev:merchant`（5174），各自 `/login`、`/settings`；平台另有 `/accounts`、`/users`、`/audits`。通过 Vite `/api` 代理访问同一个后端，启动细节见 [开发与测试环境](开发与测试环境.md)。本说明不是服务已启动的证明。

账户信息、改密、退出平铺在设置；首次登录先改临时密码，合法站内来源可恢复。401 清理匹配凭证；普通只读请求遇到 503 保留凭证，写入结果未知先查询状态或重新登录，不自动重复写入；INTERNAL_ERROR 和通用错误提示不再宣称操作未完成或直接要求重试；迟到响应不恢复已退出身份。存储不可用时降为当前页面内存登录并提示。前端会话算法复用 `packages/session`，但存储 key、锁及 audience 按端隔离；后端签名校验才是授权依据。

商户主体、订单和资金权限待 6.1 接入，目前明确显示业务待开通。真实 SMTP 投递、实际管理账户创建和部署均未执行；代码验证范围见 [验证记录](../design/工程工作记录/02-用户与鉴权/2.5-后台登录与权限基础/04验证记录.md)。
