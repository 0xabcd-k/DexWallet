# 测试网本人充值报价

5.4 首批在 Android App 的「美元余额 → 充值」提供本人充值试算。用户选择资产并填写希望到账的美元金额，可以看到每币美元汇率、含预计代付 Gas 的总支付币量、Gas 原币及其美元估值、预计净到账和有效时间。美元单价可配置为固定测试行情或 Kraken 真实美元现货成交价。App 同时显示来源及行情时间。Solana Devnet 原生 SOL、USDC 和测试 USDT 可在选择钱包后按待签交易向节点重新询价。Base Sepolia USDC 和已启用指定 MetaMask 智能账户的原生 ETH 可在选择钱包后查看签名前的网络费预估。TRON Nile 原生 TRX 可查询所需带宽，项目测试 USDT 可查询当笔转账所需的 Energy 和带宽。两者均显示预计燃烧的 TRX。TON Testnet 原生 TON 和项目指定的测试 USDT 均支持已初始化 W5R1 钱包询价。测试 USDT 还显示退回平台的 TON 和收款代币钱包新增的储备。打开弹窗、获取及刷新报价均为只读操作。Mini App 保留下载 App 的提示。

## 试算口径

首批按固定目标净到账、平台代付 Gas 从总额中结算的情形计算。它用于验证金额展示，实际通道的费用上限、失败可扣来源等仍按[费用逐项审核](../design/链上资金费用逐项审核.md)推进。钱包直付需要独立口径。

1. 目标美元为正数，最多两位小数。测试价格是每个支付资产或 Gas 资产的美元单价，稳定币也必须有自己的价格。费用估计按支付资产设置，用该网络原生币表示。
2. 预计 Gas 美元值等于预计 Gas 原币数量乘以原生币美元单价。以目标美元加预计 Gas 美元值为总预算，除以支付资产单价，向上取到链上最小单位。总支付币量已经包含预计代付成本。
3. 用实际计算出的总支付币量乘以支付资产单价，减去一次预计 Gas，再向下取整至美分，得到预计净到账。返回值使用十进制字符串，遵守对应链的整数容量和美元账户金额范围。
4. 服务端仅在行情表有效窗口内提供预览，每份结果最多展示 30 秒，并在行情表到期时提前失效。客户端切换金额、资产或付款钱包后丢弃旧结果。客户端以服务端返回的剩余时长从请求开始计时，切回前台时也检查是否到期。报价受理、可执行窗口和到账核验时限见[金额与报价](../product/02业务规则.md#金额与报价)，本批没有受理或锁价。

以 Base Sepolia 的一组测试参数为例。USDC 每枚 0.98 美元，ETH 每枚 2000 美元，转入 USDC 的预计 Gas 为 0.0001 ETH（0.20 美元）。希望到账 10.00 美元时，总支付币量为 10.408164 USDC，预计净到账为 10.00 美元。

## 本地配置

### 固定测试行情

在本地测试服务配置的 `ChainAssets` 下添加 `DepositQuotes`，随后重启。示例中的两个时间均为 Unix **秒**，使用时用当前有效的时间窗口替换。每次变更行情或 Gas 参数应使用新版本名。省略整张表时目录不开放任何充值试算。

```yaml
ChainAssets:
  DepositQuotes:
    Version: local-base-001
    AsOf: 1795305600
    ValidUntil: 1795309200
    Assets:
      - AssetID: base-sepolia:eth
        USDPerCoin: "2000"
        EstimatedGas: "0.00001"
      - AssetID: base-sepolia:usdc
        USDPerCoin: "0.98"
        EstimatedGas: "0.0001"
```

仅 local/dev 环境配合 dev 运行模式允许加载测试报价表。配置输入必须来自测试网资产目录；测试 USDT 的完整资产 ID 含当前配置的合约或 mint。每个网络需要原生币美元价用于换算 Gas。缺少费值、汇率为零、币种重复或主网资产均导致启动失败。只有明确填写 `"0"` 才表示预计 Gas 为零。固定模式的两步试算均沿用配置的汇率。生产行情与订单受理的验收要求见 [5.4 实施方案](../design/工程工作记录/05-钱包与链上通道/5.4-行情与报价/02实施方案.md)。

### 从交易所自动更新

在同一测试服务配置中启用 Redis，使用下方的 `DepositQuotes`。报价资产沿用完整的测试网 ID。交易所价格映射到对应币种，测试代币按其对应正式币种试算。Gas 估值仍按各通道配置；已启用的 Solana 钱包询价仍会向 Devnet 节点读取实际消息的费用。

```yaml
ChainAssets:
  DepositQuotes:
    Version: market-preview-v1
    Market:
      Source: kraken
      MaxAge: 5m
    Assets:
      - AssetID: solana-devnet:sol
        EstimatedGas: "0.00001"
      - AssetID: solana-devnet:usdc
        EstimatedGas: "0.00001"
```

将上述片段加入本地完整服务配置，例如 `.tools/market-local.yaml`。在 `backend/` 下使用同一配置启动报价 API 和采集进程。一次性采集可省略 `-interval`，命令会输出当前汇率表。持续采集在每轮结束后等待指定间隔，单币种失败会记录错误并继续处理其他币种。读取公开成交数据无需交易所账户或 API 密钥。

```bash
go run ./tools/market_rates -f ../.tools/market-local.yaml -interval 30s
```

采集器从 Kraken 的公开 `PostTrade` 接口读取 ETH、SOL、TON、TRX、USDC 和 USDT 各自对 USD 的最新成交。按币种保存成交价、成交时间和交易所成交 ID，API 实例从同一环境的 Redis 读取。延迟返回的旧成交无法覆盖新成交。当前提供 Kraken 一个交易所实现，币安保留为后续行情源候选。[Kraken 现货成交接口](https://docs.kraken.com/api/docs/rest-api/get-post-trade)

每次试算同时读取支付币和 Gas 币，以两条成交中较早的时间为 `asOf`。新报价有效期取 30 秒和剩余行情寿命中的较短者。一项缺价或过期就暂停依赖该币的预览，直到采集到新成交；两种价格都有效的其他资产仍可询价。读取行情库失败时，资产目录继续服务并关闭报价入口，直接询价返回 `SERVICE_UNAVAILABLE`。钱包询价期间固定使用同一组价格。

`Market` 模式省略 `AsOf`、`ValidUntil` 和各资产的 `USDPerCoin`。示例中的 5 分钟有效期与 30 秒采集间隔是本地验证参数。接口通过 `rateSource` 区分 `kraken` 与 `test_sheet`，`rateVersion` 标识本次换算使用的成交与费用配置。Redis 维护当前行情；订单受理时保存报价快照的工作归入后续资金流程。

## Solana Devnet 按钱包询价

### 原生 SOL

在 `ChainAssets.Networks` 配置 Solana Devnet RPC，并在同一张有效报价表中列出 `solana-devnet:sol`。再在 `DepositQuotes` 下添加以下配置。两个值均为专用测试公钥，收款地址只用于试算。省略 `SolanaSOL` 时仍可使用原先的固定费用预览。

```yaml
SolanaSOL:
  FeePayer: DcfKLiLsSsoJrrf3t6QXwkjfUarE4yW5sKjzF7xBQkPN
  Recipient: 7Njq3pBVPhZWEoRh8w22eC2KBcGUhhCvwFFitsyTg7A5
```

App 先按当前行情和配置的 Gas 估值试算。点「选择付款钱包」后可按名称或地址搜索本机已有的兼容钱包，点「查询此钱包的网络费用」取得本笔转账的报价。此步骤只读取钱包的公开地址。当前 App 可选内置 Solana 钱包。

后端验证 Devnet 创世哈希，获取 confirmed 区块哈希，构造一笔原生 SOL 转账。平台是第一签名人和费用支付方，用户是第二签名人并转出总支付币量。节点用 `getFeeForMessage` 对消息询价。服务端将费用计入总币量后，按同一区块哈希向节点核对最终消息的费用。两次费用不同、区块哈希失效或试算在查询过程中到期，均返回 `SERVICE_UNAVAILABLE`。用户可重新询价。此估算不包含可选优先费、代币账户租金或交易执行成功保证。节点请求沿用链查询的用户限流。整次询价共用 `ChainAssets.Timeout`（默认 3 秒，上限 30 秒），本次公网验证配置为 30 秒。充值报价路由和 App 钱包询价的等待上限也是 30 秒。[Solana RPC 文档](https://solana.com/docs/rpc/http/getfeeformessage)

### USDC 与测试 USDT

先配置 Solana Devnet RPC 和 `solana-devnet:sol` 的美元价。每种代币可以独立启用钱包询价，在对应配置项下填写平台代付公钥 `FeePayer` 和收款钱包公钥 `Recipient`。

| 支付资产 | `DepositQuotes` 下的钱包询价配置项 | `DepositQuotes.Assets[].AssetID` |
| --- | --- | --- |
| Devnet USDC | `SolanaUSDC` | `solana-devnet:usdc` |
| 项目测试 USDT | `SolanaTestUSDT` | `solana-devnet:usdt:<mint>`，与 Solana Devnet 端点的 `TestUSDTContract` 完全一致 |

测试 USDT 使用项目的 6 位精度 SPL 测试币，App 在资产选择器标明测试代币。更换 mint 时需同步更新行情行的资产 ID。只配置代币价格时可以做基础试算，启用相应的钱包询价配置后才可按钱包查询网络费。

后端按资产目录中该代币的 mint 和原版 Token Program 推导付款方与收款方的关联代币账户（ATA），在同一个节点快照中校验账户归属、mint、状态和精度。用户授权代币转出，平台签名支付 SOL 网络费。总支付量按该代币自己的美元单价换算，向上取整到 6 位。付款账户缺失或无法覆盖含费币量时返回 `INSUFFICIENT_BALANCE`。冻结、账户数据异常或节点无法估算时返回 `SERVICE_UNAVAILABLE`。

| 收款账户快照 | 待签交易 | App 费用展示 |
| --- | --- | --- |
| 已有该 mint 的可用账户 | 转账指令 `TransferChecked` | 显示网络费，开户垫资为 0 SOL |
| 收款 ATA 尚未创建 | 平台作为开户付款人，先执行幂等开户 `CreateIdempotent`，再执行转账 | 网络费和开户垫资分别显示 SOL 数量及其美元估值 |

开户垫资是留在目标账户内的存储余额。服务端向该节点查询 165 字节账户的免租最低余额。测试报价中，用户支付总额只计入网络费，平台垫资单列。若从报价到执行期间其他交易已开好账户，则实际垫资可能降至零，结算时需查回执。正式承担方、回收归属仍待 C11 审核。[Solana 账户创建](https://solana.com/docs/tokens/basics/create-token-account) · [免租余额 RPC](https://solana.com/docs/rpc/http/getminimumbalanceforrentexemption) · [费用审核清单](../design/链上资金费用逐项审核.md)

## Base Sepolia USDC 签名前估费

在 `ChainAssets.Networks` 配置 Base Sepolia RPC，在 `DepositQuotes.Assets` 启用 `base-sepolia:eth` 和 `base-sepolia:usdc`。固定测试表和 Kraken 行情均可使用。在 `DepositQuotes` 下启用 `BaseUSDC` 后，App 的充值弹窗支持选择 Base 钱包并查询费用。以下两个角色可以由同一个测试平台地址承担。

```yaml
BaseUSDC:
  FeePayer: "0xa59C992Aa84657df4EbFF6F04E11a1632f6DB1FA"
  Recipient: "0xa59C992Aa84657df4EbFF6F04E11a1632f6DB1FA"
```

这条路径使用 Circle USDC 的 EIP-3009 授权。用户签名前，服务端按当前区块和已验证路径的参考 Gas 用量计算预算。App 显示「签名前预估网络费（已计入总支出）」。普通外部账户和项目已在测试网验证的 MetaMask 委托标识可以询价，其他合约钱包暂不提供这一估算。服务端检查用户的 USDC 能否覆盖含费总额、平台的 ETH 能否覆盖预计费用。付款用户可以没有 ETH。[已验证的授权路径](../design/工程工作记录/05-钱包与链上通道/5.1-用户钱包接入/08BaseUSDC授权与代付实转验证.md)

| 项目 | 计算依据 |
| --- | --- |
| L2 执行费 | 取 `eth_feeHistory` 返回的下一块基础费，加上参考区块的中位优先费，乘以 125,823 Gas。用量参考值取自已完成的三笔代付测试中的最大交易 Gas limit。 |
| L1 数据费 | 按固定 9 参数的 `transferWithAuthorization`、零 ETH 金额和空访问列表，对最长 410 字节的未签名 EIP-1559 信封调用 `getL1FeeUpperBound`。 |
| 运营费 | 按同一参考 Gas 用量调用 `getOperatorFee`。节点明确返回零时才计零。 |

三项以 wei 相加，再用同一份 ETH、USDC 美元行情计算总支付币量。合约调用、账户代码和平台余额绑定规范区块哈希；费用历史核对区块号与基础费。报价同时受行情和参考区块的有效期限制。缺少费用数据、节点连错网络、区块过期或平台代理账户 ETH 不足时暂停该笔报价；用户 USDC 不足时返回 `INSUFFICIENT_BALANCE`。试算完成后，已启用的内置钱包可以继续[签名并提交本人充值](#base-sepolia-本人-usdc-充值)。[Base 网络费](https://docs.base.org/specifications/transactions/network-fees) · [L1 费用预估](https://specs.optimism.io/protocol/fjord/predeploys.html) · [运营费](https://specs.optimism.io/protocol/isthmus/predeploys.html)

## TRON Nile 原生 TRX 委托带宽估算

在 `ChainAssets.Networks` 配置 Nile FullNode，在 `DepositQuotes.Assets` 启用 `tron-nile:trx` 的汇率和基础估费参数。选择钱包后的估算使用该地址的实际资源状态。以下示例放在 `ChainAssets.DepositQuotes` 下。

```yaml
TRONTRX:
  ResourceOwner: TPDBmTxJWYucGk5VjDsSi6jBdvVjpCnCsH
  Recipient: TPDBmTxJWYucGk5VjDsSi6jBdvVjpCnCsH
```

`ResourceOwner` 是已向用户钱包委托带宽的账户，`Recipient` 是已激活的普通收款账户。服务端核对 Nile 创世块和近期区块，用报价的实际 sun 数量构造无 memo 的单笔原生转账，按 protobuf 交易大小计入单份 65 字节签名和 64 字节结果预留。钱包须为该来源地址自行单签的普通账户。余额须覆盖本金，来源的可用质押带宽必须能独立覆盖整笔交易。服务端比较平台到来源的 Stake 2.0 委托份额与来源收到的总份额，同时排除来源自身或旧质押提供的带宽。[TRON 资源模型](https://developers.tron.network/docs/resource-model) · [委托查询接口](https://developers.tron.network/reference/getdelegatedresourcev2)

成功时 `delegatedBandwidth` 是预计消耗的点数，`messageSha256` 是未签名原始交易的摘要。弹窗单列预计燃烧的 TRX，本路径带宽全额覆盖时为 0。用户 TRX 不足返回 `INSUFFICIENT_BALANCE`，平台带宽不足或来源无法核实时返回 `SERVICE_UNAVAILABLE`。估算不会启动质押、委托或账户激活。FullNode 的账户与资源接口读取最新状态，报价不会锁定带宽；后续受理需按实际签名和最新可用资源复核。生产对质押或租用资源如何折价仍须按[费用审核清单](../design/链上资金费用逐项审核.md)确定。[实链验证](../design/工程工作记录/05-钱包与链上通道/5.4-行情与报价/04验证记录.md#tron-nile-原生-trx-委托带宽估算)

business 40 起，单笔 Devnet 执行工具在取得 `finalized` 后，使用受理时锁定的 SOL/USD 汇率结算。先核对原消息中的 SOL 总量和订单 memo，再用「已核验收款数量减去平台实付 Gas」乘以该汇率，向下取整到美分。结果必须与原报价展示的 `netUsd` 相符。受益人取自已确认报价的 `user_id`。例如实收 0.00011 SOL、Gas 0.00001 SOL、锁价 100 USD/SOL 时，入账 0.01 测试美元。结算不再询价。

一次事务锁定充值单，借记 `usd_clearing`，贷记受益人的 `usd_balance`，并在订单保存凭证、净额和入账时刻。重复执行、提交应答丢失和并发调用均回查原凭证。余额容量超限、收款与原单不一致或事务中途失败时保留链上结果，账本和余额随事务一起回滚。已广播、待核验和链上失败的订单均不能入账。

本人订单查询继续返回链上 `executionState`。入账提交后另附 `creditedUsd`（两位小数）和 `creditedAt`（Unix 毫秒）。App 区分链上确认与余额到账，并提供美元账单入口。`GET /v1/user/account-entries?kind=usd_balance` 对应流水的 `businessType=deposit`、`action=credit_sol`、`businessIdx` 为订单 memo 中的原订单编号。用户侧仅显示本人的净额收入。

**升级及恢复。** SOL 首批使用 business 40，当前执行工具要求 business 42。先升级数据库，更新通用收款匹配器、执行工具、API 和 App，再启用测试入账。通用匹配器为该单已保存的交易签名保留第 0 条 SOL 转账指令。旧库中该事件若已关联其他收款请求，入账报归属冲突并等待核验。已确认且尚未入账的订单可以跳过签名与广播，在 `backend/` 使用原报价编号恢复。

```sh
go run ./tools/sol_deposit_devnet -settle-only -quote "$QUOTE_IDX"
```

工具读取 `DEXWALLET_TEST_ENV=local`、`DEXWALLET_TEST_MYSQL_ADDRESS`（明确的回环地址）和 `DEXWALLET_MYSQL_DSN`，使用项目的专用开发账号/库或隔离集成测试库。单独结算无需密钥或 RPC。39 的旧订单升级时保持原有状态，须执行结算才记账。[历史交易验证](../design/工程工作记录/05-钱包与链上通道/5.5-本人与代他人充值/04验证记录.md)

## Base Sepolia 本人 USDC 充值

Android App 内置钱包支持在确认钱包报价后，授权平台转入指定总量的 Circle 测试 USDC。付款钱包签署 EIP-3009 授权，平台用自己的 ETH 支付网络费。用户可在美元余额的充值入口按原报价编号查询进度。已启用指定智能账户的内置钱包可继续[原生 ETH 充值](#base-sepolia-本人原生-eth-充值)。[EIP-3009](https://eips.ethereum.org/EIPS/eip-3009)

**启用条件。** USDC 订单自 business 43 起支持，本版执行工具要求 business 44。先部署收款归属核验和执行工具，再在 local/dev 的 dev 模式下配置 Base Sepolia RPC、USDC 和 ETH 美元行情、`DepositQuotes.BaseUSDC` 的 `Recipient` 与 `FeePayer`。增设 `DepositQuotes.BaseUSDCExecutionWindow: 5m` 后，新钱包报价会附带执行授权条款。默认零仅启用已配置的询价功能。授权窗口从报价到期时开始延伸，最小一秒。签名受理仍须在报价有效期内完成。测试 API 无需持有代付密钥。

| 步骤 | 数据与检查 |
| --- | --- |
| 确认条款 | 沿用钱包报价确认接口。App 显示总支付 USDC、预计净美元、ETH 费用上限、收款地址、平台代付地址及授权截止时间。报价号同时作为本人充值单号。 |
| 本机签名 | 用设备密钥库解锁对应的钱包。EIP-712 域绑定 Base Sepolia（84532）和 Circle 测试合约。消息绑定付款地址、收款地址、USDC 最小单位总量、有效期及含订单编号的唯一 nonce。平台代付人、费用上限和美元汇率保存在服务端的同一份确认快照。 |
| 受理 | `POST /v1/user/base-deposit-orders/authorize` 接收 `quoteIdx` 和 `userSignature`。后端恢复签名人，按原单构造 calldata 并模拟。检查当前费用、受理时限及换绑冻结，同一订单重复提交原签名可恢复已受理结果。 |
| 平台执行 | 单笔工具以测试平台密钥签名。原始交易、平台 nonce 和交易哈希先写库。广播前重新模拟并按当前区块核对 L2、L1 和运营费的总预算。广播响应丢失后按已保存的同一哈希查询，仍可执行时只重发原交易。测试代付地址应由这条执行路径独占发送 nonce。 |
| 到账入账 | 从配置节点读取原交易，等待规范区块达到 `finalized`。同时核对平台签名、USDC 合约、付款人、订单授权已使用事件及唯一对应的 Transfer。按最终回执计算实际费用。本人账户、美元清算分录、凭证和订单在同一事务完成。 |
| 查询 | `GET /v1/user/base-deposit-orders/:quoteIdx` 仅允许报价本人读取。返回状态、已生成的交易哈希、已核验的实际费用（wei）和已入账净额。App 可在重开后查询最近提交的订单，通过账单查看原订单号。 |

净额等于「实收 USDC × 锁定 USDC/USD − 实付 ETH × 锁定 ETH/USD」，最后向下取至美分。实付 ETH 包含 L2 执行费、回执的 L1 数据费和交易所在区块的运营费。费用超出原上限时进入核验，暂停自动入账，保留实际费用供人工处理。通用收款匹配器也检查付款人、收款人及授权 nonce，避免本人充值被商户订单占用。生产费用政策仍按[费用逐项审核](../design/链上资金费用逐项审核.md)落实。

`awaiting_signature` 表示待签名，未受理且报价已失效时显示 `expired`。`accepted` 表示已受理，`signed` 表示已保存原交易并等待链上核验，`credited` 表示已入账。授权过期且查无交易、原交易最终回滚或实付费用超限时进入 `review`。EIP-3009 允许第三方中继相同授权。原交易回滚时，需要核验授权 nonce 的实际去向。对于暂时查无交易的订单，可以按原哈希继续查询晚到的最终回执。[Base 最终性](https://docs.base.org/base-chain/network-information/transaction-finality)

```bash
go run ./tools/base_deposit_sepolia -quote "$QUOTE_IDX" \
  -recipient "$BASE_RECIPIENT" -usdc-atoms "$USDC_ATOMS" \
  -max-fee-wei "$MAX_FEE_WEI" -sponsor-key-file "$TEST_SPONSOR_KEY_FILE"
go run ./tools/base_deposit_sepolia -quote "$QUOTE_IDX"
```

第二条命令用于已保存原始交易或已入账的订单。已入账时可离线返回结果，其余状态需要配置的 Base Sepolia RPC 在线。实转的区块、费用和恢复结果见[验证记录](../design/工程工作记录/05-钱包与链上通道/5.5-本人与代他人充值/04验证记录.md)。
