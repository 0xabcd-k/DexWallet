# 链上收款与转账准备

[文档入口](../README.md) · [资产目录与查询配置](链上资产查询.md) · [5.2 工作记录](../design/工程工作记录/05-钱包与链上通道/5.2-链上资产与直接收发/03实施记录.md)

2026-11-16 第二批：Android App 已接通链上个人收款码、扫码或手填收款目标、精确数量核对和钱包选择。**当前不能签名或广播**；最终付款按钮保持禁用。数据库仍为 business 15，没有新增订单、资金占用或流水。

## 页面行为

- 首页收款默认「收款到余额」。切换「收款到链」后，选择本机内置钱包或已连接 TON 钱包、网络、资产，显示该地址的二维码。二维码不固定金额；选择变化立即隐藏原目标的二维码和地址，迟到响应不能覆盖新目标。
- 链上资产进入所选钱包，不增加平台美元余额。二维码只表达收款目标，不证明平台账户身份或地址所有权。
- 首页付款仍先扫码；App 识别项目链上码后进入 `/chain-transfer`。裸地址只预填地址，用户必须选网络和资产，不能凭相同地址推断 Base 网络、Solana/TRON 测试网络等。
- 「转账到链上」也可手填网络、资产、地址和数量。后端核对后弹付款框，仅显示同链同资产 1:1 数量、完整收款地址、尚无费用及美元报价的提示，不显示钱包持仓或伪造零手续费。
- 再点「选择付款钱包」，列出本机内置钱包及当前已连接、网络匹配的外部 TON 钱包，内置钱包靠前，支持名称/地址搜索。选择不代表执行能力已验收；最终确认禁用。
- Android 声明 CAMERA 权限，WebView 通过现有 Capacitor 权限处理申请相机；拒绝或无摄像头时沿用扫码错误提示、重试及手填入口，不要求相机硬件才能安装。
- Android 项目链接只导航，保留登录后返回位置；不能携带身份凭证、结果或任意调用。已有结果未明的美元付款先进入恢复提示，链上准备不能覆盖原 requestKey。
- Mini App 不装载原生链上页面；切换链上收款隐藏余额码，识别链上码/地址只显示 App 引导，不发起余额收款人解析、付款或钱包调用。

## 收款码契约 v1

```text
com.dexwallet.app://chain-transfer?v=1&network=base-sepolia&asset=base-sepolia%3Aeth&address=0x0000000000000000000000000000000000000001
```

查询参数恰好为 `v/network/asset/address`，顺序不限；值采用 URL 查询编码。后端输出规范化 URI。仅支持当前版本 `1`，重复项、未知项、路径、用户信息、端口、fragment、超长输入、混用 URI 和手填字段均拒绝。`amount`、memo、订单、RPC 地址、合约调用/data、任意 token 合约都不接受；资产身份必须来自服务端目录。

这是 **DexWallet App 专用码**，不是通用钱包二维码。其他钱包应复制地址并逐项确认网络、资产。没有把所有链伪装成通用 `address + amount` 标准：[EIP-681](https://eips.ethereum.org/EIPS/eip-681) 本身允许资产调用与建议参数，不能无校验地当本项目付款授权。商户定额订单和平台充值订单需要各自交易契约，不复用个人无金额码。

Android 使用现有自定义 scheme，无域名所有权验证；遵守 [Android 深链接说明](https://developer.android.com/training/app-links/create-deeplinks)，只导航、后端重校验、用户核对，不把能打开 App 当作可信付款请求。后续公开 HTTPS App Links 需真实域名及关联文件，不在本批预建。

地址沿用 [资产查询校验](链上资产查询.md)：Base 格式/校验和、Solana 公钥长度、TRON Base58Check、TON 格式及 test-only 标记。TON 输出 non-bounceable friendly 地址，按目录附带测试网标记；不默认为未部署账户使用可退回地址。目标不要求属于平台用户，因此不按地址拼接平台用户资料。

## 已实现 API

均需当前用户会话。源定义 `backend/manifest/api/platform/platform.api`，生成 Go/TS，业务 `backend/logic/chainassets/requests.go`。

| 方法 | 路径 | 输入 | 返回 |
| --- | --- | --- | --- |
| POST | `/v1/user/chain-transfer-targets/resolve` | `{receiveCode}` 或互斥的 `{network,assetId,address}` | `{network,assetId,address,receiveCode}` |
| POST | `/v1/user/chain-transfers/preview` | `{network,assetId,address,amount}` | `{target,amount,canSubmit:false,blockReason:"CHANNEL_NOT_OPEN"}` |

不依赖 RPC 启用，也不访问链、Redis 限流或数据库资金表；登录会话沿用既有认证。纯本地校验失败返回 `INVALID_ARGUMENT`，不会回传一个可执行成功结果。客户端校验返回的网络、资产、地址和精确数量与本次请求一致。

数量用十进制字符串，禁止负数、指数、前导零、空白、超币种精度、零和溢出，不四舍五入。使用最小单位整数：TON 不超过 120 位，Solana 不超过 64 位，TRX 不超过有符号 64 位正数，Base/TRC20 不超过 256 位。这是链协议序列化边界，不新增业务限额；业务限额/费用不能用这些最大值替代。输入 `1.2300` 可规范化为 `1.23`。
