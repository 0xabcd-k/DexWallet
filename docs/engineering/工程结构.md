## 实际工程入口

| 位置 | 内容与职责 |
| --- | --- |
| [backend/go.mod](../../backend/go.mod) | 单 Go module：`github.com/0xabcd-k/DexWallet/backend`；已有样例、工具依赖与 2.1 用户模型/内部用例 |
| [frontend/package.json](../../frontend/package.json) | 私有工作区根 `@dexwallet/frontend`，记录 Node/pnpm 版本约束 |
| [frontend/pnpm-workspace.yaml](../../frontend/pnpm-workspace.yaml) | `apps/*` 为应用包，`packages/*` 预留真实共享包的发现范围，已有 api-contract、api-client、i18n、ui-desktop 四个共享包 |
| [用户应用](../../frontend/apps/user/package.json) | `@dexwallet/user`，后续承接 Mini App H5 |
| [商户应用](../../frontend/apps/merchant/package.json) | `@dexwallet/merchant`，后续承接商户工作台 |
| [平台应用](../../frontend/apps/admin/package.json) | `@dexwallet/admin`，后续承接平台管理 |
| [frontend/pnpm-lock.yaml](../../frontend/pnpm-lock.yaml) | pnpm 实际生成的八个工作区清单及前端依赖锁 |

三个应用包均为 private，包名唯一，目前没有互相引用。后续应用只能引用有实际用途的共享包；共享包不反向依赖应用。三个应用分别构建、分别管理会话，不能通过共享包混用凭证。后端 API 与后台任务使用同一 module，首版同程序/同进程运行；后台任务模块不引用 `api/internal`，由入口组装，领域包不反向依赖入口或完整 `ServiceContext`。后续确有资源隔离需求时才增加独立 worker 入口。

## 基础工具版本

| 工具 | 本项采用并验证的版本 | 记录方式与适用范围 |
| --- | --- | --- |
| Go | 1.26.10 | `go.mod` 的最低版本；复验时可用 `GOTOOLCHAIN=go1.26.10` 指定相同工具链，不将 go 指令误解为禁止更高版本 |

版本在 2026-10-26 初始化时核对官方发布信息并运行验证。Go 选用 1.26 系列补丁版本，Node 选用 24 LTS，pnpm 选用明确的 10.x 版本；这只是本项工具基线，不表示已验证 go-zero、goctl、React、Vite 或 SDK 组合。官方依据：[Go 下载清单](https://go.dev/dl/?mode=json)、[Node 发布记录](https://nodejs.org/en/about/previous-releases)、[pnpm 10 安装说明](https://pnpm.io/10.x/installation)。后续升级必须同步版本约定与验证证据。

## 准备和检查

后端在 `backend/` 执行；需要已安装支持工具链选择的 Go，首次使用相应版本可能需要下载：

```sh
GOTOOLCHAIN=go1.26.10 go version
GOTOOLCHAIN=go1.26.10 go list -m -json
```

预期 module 路径与上表一致，GoVersion 为 `1.26.10`。1.2 已建立样例和工具代码，可运行 `go test ./...`；它验证工程示例，不代表资金业务已实现。

前端在 `frontend/` 执行。使用 nvm 的环境先加载 nvm，再按下列命令准备；使用其他版本管理器时安装相同 Node/pnpm 版本即可：

```sh
nvm install
nvm use
npm install --global pnpm@10.33.4
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm -r list --depth -1 --json
```

列表包含工作区根、三个应用及四个共享包，共八项。首次安装需要网络或完整缓存。1.4 已建立 dev、build、typecheck 与独立测试入口，见 [前端公共基础](前端公共基础.md)。

仓库根目录的文档检查保持为 `python3 scripts/check_docs.py` 与 `git diff --check`。具体结果见 [1.1 验证记录](../design/工程工作记录/01-工程基础/1.1-工程结构与模块划分/04验证记录.md)。
