# 后端公共基础

1.3 已建立可运行 API、配置与依赖客户端、事务、统一 JSON 响应、日志追踪、健康检查和退出流程。正式路由目前仅有两个健康接口；鉴权、业务表、资金操作和消息消费者尚未实现。

## 本地启动

从 `backend/` 执行。通过本地环境注入下列值，命令行和仓库不保存凭据：

| 环境变量 | 要求 |
| --- | --- |
| DEXWALLET_MYSQL_DSN | 必填，MySQL Go driver DSN，明确指定已存在的项目库；应用不创建库、不运行迁移、不允许 multiStatements |
| DEXWALLET_REDIS_PASSWORD | 有认证时填写 |
| DEXWALLET_MQ_ACCESS_KEY / DEXWALLET_MQ_SECRET_KEY | 有认证时成对填写；本轮现有实例无认证路径，认证环境须另行验证 |

```sh
go run ./api -f api/etc/platform.yaml
```

默认监听 `127.0.0.1:8888`。YAML 显式选择配置，凭据在解析后从当前环境注入，然后校验；不展开 YAML 字符串，不热更新。默认连接本机 MySQL、Redis 和 RocketMQ，实际 DSN 由用户环境提供；需要其他监听端口或服务地址时使用明确的配置文件。

```sh
curl -i http://127.0.0.1:8888/health/live
curl -i http://127.0.0.1:8888/health/ready
```

成功返回 `code: OK`、`message: ""`、明确的 data.status 和 traceId；未就绪返回 HTTP 503 / SERVICE_UNAVAILABLE，省略 data。响应头 `X-Trace-Id`、响应体及上下文日志关联同一 ID。404/405、参数错误、过载、写入响应前的 panic 和超时采用相同错误结构；测试故障路由和 1.2 示例未注册到正式 API。

MySQL 为核心依赖，启动 Ping 失败则退出；运行中健康快照失败或过期则不就绪。Redis 和 RocketMQ 默认 Enabled=true、Required=false；它们仍被创建并检查，故障通过日志报告。未来依赖它们的会话、正确性判断或消息能力必须建立对应门禁；Required=true 时也影响整体就绪，不能只改变配置而绕过业务条件。

## 运行边界

- 使用 go-zero 路由、生成的注册函数和默认链中的 Timeout/Metrics/Prometheus；不再清空默认链后自建超时器。`httpx.WriteJsonCtx`、`SetErrorHandlerCtx`/`ErrorCtx` 负责输出，项目只保留错误映射与序列化失败兜底。追踪移到路由外围，404/405 同样使用框架 TimeoutHandler 和统一错误。JWT、熔断和 CPU 降载尚未接入。
- 响应开始写入后发生 panic，框架缓冲没有公开的重置能力；此时记录堆栈并通过标准库 ErrAbortHandler 中止连接，避免返回拼接损坏的 JSON 或假成功。普通 handler 必须先完成处理再统一输出；连接中断同样不能解释为业务未执行。
- 日志复用 logx，MQ SDK 日志接入相同结构化输出。充分保留原始 cause、必要堆栈和失败阶段，访问日志不转储 Authorization/Cookie/请求体。成功健康探测降低日志噪声，依赖状态变化留日志。
- provider 由 go-zero 的 Telemetry/ServiceConf 初始化，TraceHandler 创建追踪；删除项目私有 provider。样例无 exporter、Sampler=0，但每次请求仍生成有效 traceId。公共入口清除外部传播头，始终建立新的根追踪；路由模板由实际匹配记录，支持动态路径。可信网关透传、跨服务或跨消息追踪仍待部署边界明确。
- 请求默认 5 秒、依赖调用 3 秒、探测 1 秒、间隔 5 秒、快照有效期 15 秒、退出宽限期 30 秒；均由 YAML 配置。SDK 自身连接阶段可能有独立的超时行为，不能把 NameServer 探测等同于业务投递时限。
- 普通请求默认最大并发 1000，通过共享 `syncx.Limit` 计数；健康探测豁免，超时任务实际结束后才归还名额。请求体 1 MiB，标准库 MaxBytesReader 同时覆盖未知长度请求。超时、取消和迟到写入由框架处理，项目不再维护缓冲区或通用 4 MiB 响应阈值。现有两个健康响应固定大小；新增列表接口必须限制分页和字段大小，不能返回任意大集合。当前只支持 JSON，SSE/WebSocket 协议请求返回 400，防止绕过框架超时。
- 保留 Serverless 到标准库 net/http 的监听/Shutdown 协调：收到信号先停止就绪/新业务准入，再等待 HTTP 和实际 handler，超出宽限则关闭连接并记录错误；随后停止探测、关闭依赖、关闭框架追踪和日志。框架 proc 并行钩子不能直接保证这些先后关系，因此没有机械替换为 Server.Start。go-zero 自身强退预算也延长到应用宽限之后。不可取消的外部调用仍可能在超时后完成，日志不能替代业务幂等和持久恢复。
- Redis 使用 `dexwallet_<environment>:` key 命名空间；MQ producer group 为 `dexwallet_<environment>_api`，topic 由统一方法加项目前缀。现有客户端支持基础连接和显式发送入口，但没有可靠事件、消费幂等或业务投递机制；不自动创建业务 topic/消费组。
- RocketMQ 探测为只读 NameServer 协议访问加 Broker TCP 连接，不验证消息已投递或消费；1.5 进行隔离 topic 收发，3.5 验证持久事件与恢复。

事务调用使用 `Dependencies.Tx.TransactCtx(ctx, fn)`，回调显式收到 go-zero `sqlx.Session`。model 通过手写 `WithSession` 绑定；不可替换共享 model 内部连接。适配器使用同一 `sql.DB` 的 BeginTx 和 go-zero NewSessionFromTx，保留提交/回滚阶段、两个错误原因及 panic 堆栈；context 只携带嵌套检测标记，事务本身显式传递。没有通用重试，提交失败保留未知；资金锁定、隔离级别、幂等及事件表随业务实现。

## 配置迁移（2026-10-28）

配置嵌入 `rest.RestConf`，沿用 `conf.Load` 的默认值与框架校验，再执行项目依赖/预算校验。自定义配置文件须按下表更新；旧字段不再使用。

| 原字段 | 当前字段与样例 | 单位/含义 |
| --- | --- | --- |
| RequestTimeout: 5s | Timeout: 5000 | go-zero 使用毫秒整数；依赖和探测预算继续使用 duration |
| MaxInFlight: 1000 | MaxConns: 1000 | 当前适配为服务级实际工作并发，包含已超时但未结束的任务 |
| MaxBodyBytes: 1048576 | MaxBytes: 1048576 | 字节，覆盖已知和未知请求长度 |
| 隐式运行模式 | Mode: dev | 框架模式；Environment: local 仍用于业务资源命名空间 |
| 私有 tracer 默认值 | Telemetry.Sampler: 0 | 无 exporter 也生成有效 ID，生产 exporter 另行配置 |
| 代码内推导强退预算 | Shutdown.WrapUpTime: 1s / WaitTime: 37s | 框架进程退出预算；ShutdownTimeout: 30s 仍是应用等待请求结束的预算 |

项目要求 Trace、Timeout、Recover、MaxConns、MaxBytes 保持开启且 Telemetry 不禁用。Trace/Recover/MaxConns/MaxBytes 的实际入口使用上述适配，框架同职责节点关闭以避免重复。Log 开关控制项目结构化请求日志；Metrics/Prometheus 复用原生节点，管理指标监听仍需环境显式配置，不代表已部署监控平台。

Breaker、Shedding、Gunzip 必须为 false；前两者在当前版本直接写空错误响应，未纳入当前 JSON 契约，后者尚无压缩请求需求。TraceIgnorePaths 必须为空，确保每个出口都有 traceId。非法组合启动失败，不能通过开启未经适配的开关绕开统一响应。Shutdown.WaitTime 至少覆盖应用排空预算和一份依赖预算，SDK 关闭仍受其自身实现约束；不声称配置能取消所有外部调用。

## 检查与证据

仓库根执行生成与普通检查；先按 `frontend/.nvmrc` 切换 Node：

```sh
bash scripts/check_contracts.sh
python3 scripts/check_docs.py
git diff --check
```

`backend/` 下补充：

```sh
go test -race ./...
go vet ./...
go build -o ../.tools/bin/dexwallet-api ./api
```

独立集成测试按 [开发与测试环境](开发与测试环境.md) 准备 local 目标和受限账号；`DEXWALLET_TEST_MYSQL_DSN` 只授予 contract 前缀库权限，`DEXWALLET_TEST_HTTP_MYSQL_DSN` 用于账号边界验证；Redis/MQ 使用当前本地样例地址，认证值沿用前述环境变量：

```sh
go test -tags=integration ./tests/integration -v -count=1
```

测试只创建随机 `dexwallet_contract_` 前缀库与独立 Redis key，结束清理；不停止共享容器、不修改现有配置。实际通过 MySQL 9.4.0、Redis 8.2.1、RocketMQ 5.3.2 的连接验证，MQ 消息收发没有执行。SDK 为 go-redis v9.21.0、rocketmq-client-go/v2 v2.1.2，沿用 go-zero v1.10.3；依赖锁定在 go.mod/go.sum。选择 v2 remoting SDK 复用现有 NameServer/Broker，未要求更换容器或 Proxy。

具体测试与适配记录见 [1.3 实施记录](../design/工程工作记录/01-工程基础/1.3-后端公共基础/03实施记录.md) 和 [验证记录](../design/工程工作记录/01-工程基础/1.3-后端公共基础/04验证记录.md)。以上不等于生产开放或 1.5 全栈联通已完成。
