# 账单与资金记录需求

[返回产品规划](大纲.md)。关联功能：F08。负责人【待填写】；优先级与目标版本【待填写】；原型【待填写】。

原有设想包含账单页面。本模板补充查询、状态、记录关联与对账要求，具体范围待确认。

## 用户目标与范围

用户故事：作为用户，我希望知道每笔积分和资产为什么增加或减少、当前处理到哪一步，以及出现问题时如何查询。

| 候选账单类型 | 需要确认的内容 |
| --- | --- |
| 初始奖励、任务奖励、Pro 加成 | 合并或拆分展示；各自来源和关联关系 |
| 助力与邀请返佣 | 无金额变化的助力是否仅放活动记录；返佣显示依据 |
| 水果机积分消耗与奖励 | 是否两条记录；如何关联同一次参与 |
| 积分兑换 | 如支持，记录两侧单位、比例和生效规则 |
| 提现与手续费 | 申请、冻结、实际扣除、费用和失败恢复 |
| 商户支付与退款 | 原订单、付款、退款及各次链上交易的关联 |
| 调整、补发、撤销 | 原记录、原因、处理结果和可见说明 |
| 普通转账或充值 | 仅在钱包范围明确包含时纳入 |

## 列表与详情字段

| 区域 | 建议字段 | 待决策 |
| --- | --- | --- |
| 列表 | 类型、发生时间、方向、数量和单位、状态、摘要 | 默认排序、分页、统计时区 |
| 详情 | 账单 idx、相关任务或订单 idx、金额、费用、状态时间线 | 用户可见字段、说明文案 |
| 链上信息 | 网络、资产、交易标识、确认状态、查询入口 | 哪些类型适用、链接来源 |
| 关联记录 | 原始奖励、返佣、退款、调整或重试记录 | 展示方式及权限 |
| 帮助入口 | 问题类型、账单定位信息、处理进度 | 客服渠道、时效及通知 |

对外业务标识沿用 idx；字段协议和技术实现留待设计阶段确定。搜索方式【待填写】；筛选项【待填写】；展示和保存期限【待填写】；导出范围与权限【待填写】。

## 记账与展示规则

以下为建议的验收约束，采用后补充各业务的入账时点。

- 积分、美元估值和不同网络的资产分别明确单位；汇总前说明是否及如何换算。
- 同一业务重试不产生重复的有效扣款或奖励；业务成功与账单记录应能相互核对。
- 冻结、解冻与实际支出分别定义，避免将提现申请和实际到账重复计为支出。
- 更正和撤销关联原记录并说明原因，用户能够还原变化过程。
- 区分链上交易结果、内部记账结果及商户通知结果。

| 状态草案 | 待填写的余额影响 | 待填写的用户操作 |
| --- | --- | --- |
| 处理中或待确认 | 是否占用可用余额 | 查询、等待或取消 |
| 已完成 | 计入哪些余额和统计 | 查看详情 |
| 失败或已取消 | 是否及何时解除冻结 | 重试或联系客服 |
| 已撤销或已退款 | 通过什么记录冲回 | 查看原单及原因 |
| 结果待核实 | 核实期间余额如何处理 | 提交证据、查看进度 |

各业务可使用不同状态，确认后填写映射，不强制将所有业务压成同一流程。

## 对账与验收

建议按资产和账户分别核对：期初账面余额＋有效入账－有效出账＝期末账面余额；冻结与可用余额的关系另行定义。链上持有量、平台记账余额、商户应结算款如何对应【待填写】；对账频率、负责人、差异处理时限【待填写】。

| 场景 | 可观察的预期结果 |
| --- | --- |
| 完成一次任务或水果机参与 | 积分及奖励变化均有对应依据，无重复记录 |
| 提现、失败恢复或退款 | 冻结、费用、实际支出和回退符合业务规则 |
| 跨日查询和统计 | 时间与统计口径一致，列表和汇总可核对 |
| 部分退款或多次交易 | 原单与各次变动完整关联，累计结果正确 |
| 重复请求与人工补发 | 同一权益不被重复发放，调整有原因 |
| 未授权访问他人记录 | 无法读取或操作其他主体的账单 |

验收数据、实际结果和证据【待填写】。资金异常处置见[运营与维护](运营与维护.md)。
