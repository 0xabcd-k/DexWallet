# DexWallet 首版网络币种与外部钱包范围

确认日期：2026 年 10 月 18 日。App 与 Telegram Mini App 的网络、币种及外部钱包名单已由用户确定，以下内容替代此前分阶段建议。文件路径保留，便于已有文档继续引用。

首个产品载体仍按已有决议为 Telegram Mini App；本次同时确定独立 App 第一版的支持范围，不表示调整两个客户端的发布顺序。钱包收发范围已明确，具体支付及中心化余额转出规则继续在 [专项讨论清单](专项讨论清单.md) 中确定。

## 01 已确认的网络与币种

| 网络 | App 第一版 | Telegram Mini App 第一版 |
| --- | --- | --- |
| TON | TON、USDT | TON、USDT |
| Base | ETH、USDC | 不接入 |
| Solana | SOL、USDC、USDT | 不接入 |
| TRON | TRX、USDT | 不接入 |

App 共 4 条链、9 个“网络 + 币种”组合；Mini App 共 1 条链、2 个组合。本文沿用用户指定的 TON 名称表示 TON 网络原生币。

Base 上的 ETH 不代表开放 Ethereum 主网。USDT 和 USDC 在不同网络上分别管理，不自动合并为同一可转账余额。Ethereum 主网、Bitcoin、BNB Smart Chain、Arbitrum、Polygon 以及此前讨论过的其他网络不在首版范围内。

稳定币采用对应网络的官方发行版本。资产配置必须包含网络与合约或代币标识，不能仅按币种名称识别；发行依据见 [Tether 协议与合约清单](https://tether.to/en/supported-protocols/) 和 [Circle 支持网络](https://developers.circle.com/circle-mint/references/supported-chains-and-currencies)。

## 02 已确认的外部钱包

| 外部钱包 | App 第一版 | Telegram Mini App 第一版 |
| --- | --- | --- |
| Tonkeeper | 接入 | 接入 |
| Telegram 内置钱包 | 接入 | 接入 |
| MetaMask | 接入 | 不纳入本次指定名单 |
| OKX Wallet | 接入 | 不纳入本次指定名单 |
| Trust Wallet | 接入 | 不纳入本次指定名单 |
| Binance Wallet | 接入 | 不纳入本次指定名单 |

App 首版为上述 6 类钱包；Mini App 用户要求只接 Tonkeeper、Telegram 内置钱包。此前建议的 MyTonWallet、Bitget、Phantom、Rabby、TronLink 等不加入本次首版适配计划。

该表确定产品接入目标，不表示每个钱包都能通过外部连接操作全部四条链。实际可选项取“客户端已开放网络、钱包签名能力、当前设备可用连接方式”的交集。用户在 App 中选择 Base ETH 时，只展示可对 Base 交易签名的钱包；连接 TON 账户不会同时获得其他链的操作能力。

Telegram 内置钱包需要使用具备 TON Connect 能力的链上钱包入口；Telegram 登录身份、托管账户余额与链上钱包账户分开。具体入口标识和品牌显示名称根据 [TON Connect 官方注册表](https://github.com/ton-connect/wallets-list/blob/main/wallets-v2.json) 核对，保持与用户指定的钱包对应。

## 03 连接方案与兼容验证

以下是实现方向，尚未完成实际连接测试。钱包范围已确定，具体 SDK 及每个“钱包 × 网络 × iOS/Android”组合在实施时验证。

| 网络 | 连接方向 | 首版已选钱包中的验证安排 |
| --- | --- | --- |
| TON | TON Connect | 先验证 Tonkeeper、Telegram 内置钱包；App 中其他已选钱包按其 TON 接口能力接入 |
| Base | WalletConnect 或钱包官方移动端连接方案 | 验证 MetaMask、OKX Wallet、Trust Wallet、Binance Wallet |
| Solana | 钱包支持的 Solana 移动端连接与签名方案 | 在已选多链钱包中验证 Solana 能力，不另加 Phantom 等钱包 |
| TRON | 支持 TRON 的钱包连接协议或官方 SDK | 先验证 OKX Wallet 的 TRON 接口，再验证其他已选钱包；不另加 TronLink |

Reown 的网络支持随框架而异，不能将 Web 或 React Native 的能力直接视为 Swift、Android 原生 SDK 的能力。TRON 官方适配器列有 OKX 等钱包，但原生 App 仍需验证手机唤起、签名和返回流程。[Reown 能力表](https://docs.reown.com/appkit/overview)、[TRON Wallet Adapter](https://developers.tron.network/docs/tronwallet-adapter)

每条链至少验证一条完整的外部钱包路径：连接、取消授权、账户切换、交易签名、广播、返回 App、链上结果查询与断开重连。稳定币转账必须单独验收，不能仅用原生币转账代替。某个已选钱包缺少必要接口时，应记录具体缺口，不擅自扩大钱包名单。

### Mini App 的钱包选择约束

用户确定的目标是只接 Tonkeeper、Telegram 内置钱包。Telegram 当前规则要求使用 TON Connect，并明确不允许在没有功能可用性依据的情况下限制钱包选择。[Telegram 区块链指南](https://core.telegram.org/bots/blockchain-guidelines)

两者在“是否能从选择器彻底移除其他兼容钱包”上存在实现约束。实施前需核对功能筛选是否适用；若无适用依据，应提出“两者作为默认入口，保留官方其他钱包入口”等具体方案再确定。该方案尚未获得用户确认，不能把用户的“只接两个”直接改写为“仅重点测试两个”，也不能承诺官方选择器可任意裁剪。

## 04 资产用途与资金规则

本次确定网络、币种和外部钱包接入名单。付款、组合支付、中心化余额转出是否覆盖所有这些资产，仍需结合专项讨论确定；此前“只用稳定币付款”的建议不自动视为已确认规则。

| 能力 | 当前状态 |
| --- | --- |
| 链上资产查看、收款、普通转账、资产详情 | 在各客户端已确认的网络和币种范围内设计 |
| 商户付款及组合支付资产 | 在已确认资产集合内确定订单可接受的范围；报价和扣款流程继续讨论 |
| 中心化美元余额转出到链上 | 在已确认资产集合内确定到账资产、换算、费用与限额 |
| 链上充值到中心化美元余额 | 是否开放及入账规则继续讨论 |
| 任务奖励提现 | 沿用“任务待提现美元 → 中心化美元余额”，最低 2 美元、无手续费；不等同于链上转出 |

TON、ETH、SOL、TRX 为已确认支持的原生资产，其钱包收发能力不因付款规则尚待细化而排除。中心化美元余额、任务待提现美元、任务积分与链上资产继续独立管理。

## 05 对页面规划的影响

| 页面或组件 | App 第一版 | Telegram Mini App 第一版 |
| --- | --- | --- |
| 钱包首页及资产列表 | 按网络展示已确认的 9 个资产组合 | 展示 TON 网络的 TON、USDT |
| 网络选择 | TON、Base、Solana、TRON | 固定 TON，避免无意义的网络切换操作 |
| 外部钱包连接 | 6 类指定钱包，按网络与设备能力显示可用入口 | 指定 Tonkeeper、Telegram 内置钱包；选择器限制按上文处理 |
| 收款、转账及资产详情 | 明确所选网络、币种、钱包地址、余额和费用 | 仅 TON、USDT 对应操作 |
| 支付确认及链上转出 | 在当前客户端资产范围内展示本笔业务可用资产 | 资产范围限制在 TON 网络；具体付款与到账币种按资金规则确定 |
| 交易记录 | 每条记录包含网络、币种、状态和交易凭据 | 同样保留网络字段，便于账户后续跨端使用 |

客户端范围需要同时约束页面入口和业务请求，不能只隐藏按钮。内置钱包创建、导入与外部钱包连接继续并列提供，不强制创建内置钱包才能做任务或连接外部钱包。

## 06 后续细化项

网络与钱包名单不再重复询问。剩余工作是钱包逐链兼容验证、Telegram 内置钱包具体入口、Mini App 选择器限制的落实，以及 [专项讨论清单 01–03](专项讨论清单.md) 中的资金进出、支付、报价、结算与异常处理。

## 07 同类项目研究参考

以下保留最初草案的官方资料对比，只用于理解同类产品，不作为本项目首版范围。项目范围以上文已确认名单为准。


以下列出与本项目有关的代表性支持范围，不是各产品的完整币种目录，也不是市场份额排名。钱包资产管理范围、对外连接能力和商户收款范围分别比较。

| 项目 | 官方公开的相关支持范围 | 对 DexWallet 的参考价值 |
| --- | --- | --- |
| Keeper，原 Tonkeeper | 官网已从 TON 钱包扩展为多链钱包，列出 TON、TRON、Ethereum、Bitcoin、Base、Solana、BNB Chain 等；多链先在移动端推出 | 可先从 Telegram 与 TON 场景起步，再扩展资产管理；不同客户端不一定同时具备相同能力。[官网](https://keeperwallet.com/) |
| My Wallet，原 MyTonWallet | 官网展示 TON、TRON、Ethereum、Bitcoin、Solana 等多链资产管理及多个账户 | 一个钱包入口可以容纳多个链上账户，无须把每条链做成独立产品。[官网](https://mywallet.io/) |
| MetaMask | 当前官方网络说明包含 Ethereum、Base、Arbitrum、Polygon、BNB Chain，也包含 Bitcoin、Solana、TRON 等 | 不能再按“只支持 EVM 的钱包”理解；但接入时仍需逐链验证签名接口和客户端能力。[网络说明](https://support.metamask.io/configure/networks/how-to-add-a-custom-network-rpc) |
| Phantom | 多链账户包含 Solana、Ethereum、Base、Polygon、Bitcoin 等网络地址；开发文档分别提供 Solana 和 EVM 接入方式 | 适合后续覆盖 Solana 用户，也可承接部分 EVM 网络；钱包能持有某资产，不代表该资产具有相同的 DApp 接口。[账户说明](https://help.phantom.com/articles/45465816962579)、[开发文档](https://docs.phantom.com/solana/integrating-phantom) |
| Telegram Wallet 的 DeFi Account | TON 资产账户支持通过第三方兑换接收部分其他链的资产，再转换为 TON 链上的资产 | “支持其他链转入”可能是兑换通道，不能直接理解为持有对应链的原生资产。[转账说明](https://help.wallet.tg/article/666-transactions) |
| Rabby | 定位为 Ethereum 和 EVM 钱包 | 独立 Web 版可列为 EVM 钱包的重点适配对象。[官网](https://rabby.io/) |
| Stripe 稳定币支付 | 接受 USDC 的网络包含 Ethereum、Solana、Polygon、Base、Tempo；付款币种与商户最终收到的本币余额分开 | 支付可以只开放少量稳定币，商户结算另行设计。[稳定币支付说明](https://docs.stripe.com/payments/stablecoin-payments) |
| NOWPayments | 收款目录包含 BTC、ETH、SOL、TRX，以及不同网络的 USDT、USDC 等 | 广覆盖支付是另一条路线，但需要更多网络监测、报价和异常处理；公开目录不等于每条通道随时可用。[币种目录](https://nowpayments.io/supported-coins) |
