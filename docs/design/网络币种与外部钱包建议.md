# DexWallet 网络币种与外部钱包建议草案

日期：2026 年 10 月 18 日。状态：供讨论，尚未确定首版范围。

建议把 DexWallet 的支持范围分成两层：钱包可以逐步管理多链资产，支付与中心化余额转出则优先使用指定网络上的 USDT、USDC。首版基于 Telegram Mini App，建议先完成 TON 网络、官方 USDT 和 TON Connect 钱包连接；后续独立 Web 或 App 再扩展多链支付。

本文承接 [待确认功能清单 02.2](待确认功能清单.md) 和 [专项讨论清单](专项讨论清单.md)。以下优先级是产品建议，费用、资金流向、报价和商户结算规则仍按专项讨论确定。

## 01 同类项目支持情况

以下列出与本项目有关的代表性支持范围，不是各产品的完整币种目录，也不是市场份额排名。钱包资产管理范围、对外连接能力和商户收款范围分别比较。

| 项目 | 官方公开的相关支持范围 | 对 DexWallet 的参考价值 |
| --- | --- | --- |
| Keeper，原 Tonkeeper | 官网已从 TON 钱包扩展为多链钱包，列出 TON、TRON、Ethereum、Bitcoin、Base、Solana、BNB Chain 等；多链先在移动端推出 | 可先从 Telegram 与 TON 场景起步，再扩展资产管理；不同客户端不一定同时具备相同能力。[官网](https://keeperwallet.com/) |
| My Wallet，原 MyTonWallet | 官网展示 TON、TRON、Ethereum、Bitcoin、Solana 等多链资产管理及多个账户 | 一个钱包入口可以容纳多个链上账户，无须把每条链做成独立产品。[官网](https://mywallet.io/) |
| MetaMask | 当前官方网络说明包含 Ethereum、Base、Arbitrum、Polygon、BNB Chain，也包含 Bitcoin、Solana、TRON 等 | 不能再按“只支持 EVM 的钱包”理解；但接入时仍需逐链验证签名接口和客户端能力。[网络说明](https://support.metamask.io/configure/networks/how-to-add-a-custom-network-rpc) |
| Phantom | 多链账户包含 Solana、Ethereum、Base、Polygon、Bitcoin 等网络地址；开发文档分别提供 Solana 和 EVM 接入方式 | 适合后续覆盖 Solana 用户，也可承接部分 EVM 网络；钱包能持有某资产，不代表该资产具有相同的 DApp 接口。[账户说明](https://help.phantom.com/articles/45465816962579)、[开发文档](https://docs.phantom.com/solana/integrating-phantom) |
| Telegram Wallet 的 DeFi Account | TON 资产账户支持通过第三方兑换接收部分其他链的资产，再转换为 TON 链上的资产 | “支持其他链转入”可能是兑换通道，不能直接理解为持有对应链的原生资产。[转账说明](https://help.wallet.tg/article/666-transactions) |
| Rabby | 定位为 Ethereum 和 EVM 钱包 | 独立 Web 版可列为 EVM 钱包的重点适配对象。[官网](https://rabby.io/) |
| Stripe 稳定币支付 | 接受 USDC 的网络包含 Ethereum、Solana、Polygon、Base、Tempo；付款币种与商户最终收到的本币余额分开 | 支付可以只开放少量稳定币，商户结算另行设计。[稳定币支付说明](https://docs.stripe.com/payments/stablecoin-payments) |
| NOWPayments | 收款目录包含 BTC、ETH、SOL、TRX，以及不同网络的 USDT、USDC 等 | 广覆盖支付是另一条路线，但需要更多网络监测、报价和异常处理；公开目录不等于每条通道随时可用。[币种目录](https://nowpayments.io/supported-coins) |

从这些样本可见，Ethereum、Solana、Bitcoin、Base、TRON、BNB Chain 等是值得考虑的覆盖对象；Telegram 场景还需要优先处理 TON。支付产品的范围则存在明显差异：既有以 USDC 为主的稳定币方案，也有覆盖大量资产的聚合方案。结合 DexWallet 已有美元余额和小额奖励，我建议先采用稳定币支付方案，不把完整钱包币种目录同时开放为付款币种。

## 02 Telegram 首版的适用边界

Telegram 当前要求 Mini App 的钱包交互使用 TON Connect；其他连接协议仅在允许的跨链桥场景下例外。官方也允许以钱包为主要功能的 Mini App 在自身界面管理其他链资产，但这不等于允许接入其他链的外部应用付款。TON Connect 钱包选择不能任意限制，只有功能可用性等原因可以作为筛选依据。[Telegram 区块链指南](https://core.telegram.org/bots/blockchain-guidelines)

因此建议按以下范围规划：

| 产品入口 | 建议支持范围 |
| --- | --- |
| Telegram Mini App 首版 | TON 资产管理、TON Connect 外部钱包连接；链上付款与中心化余额转出的候选资产为 TON 链官方 USDT |
| Mini App 后续钱包能力 | 可评估增加其他链的内置钱包收发功能；是否适用钱包场景规定，需要结合最终产品形态判断 |
| 后续独立 Web 或 App | 规划多链外部钱包连接和多链支付，按下文逐步开放 |

独立产品的扩展不设计成 Mini App 内的绕行入口。DexWallet 同时包含任务和商户支付，不能仅凭产品名称有 Wallet 就认定所有多链场景都适用钱包条款。

## 03 网络与资产优先级

P0 为首版建议；P1 为后续多链优先候选，可按实际需求分批开放；P2 为按用户与商户需求补齐；P3 暂不排入近期支付范围。这里的 P1–P3 多链支付以独立 Web 或 App 为前提。

| 网络 | 钱包基础资产 | 建议付款与链上转出资产 | 优先级 | 取舍依据 |
| --- | --- | --- | --- | --- |
| TON | TON 原生币、官方 USDT | USDT | P0 | 与 Telegram 首版及 TON Connect 配套，先完成一条完整资金路径 |
| Base | ETH、原生 USDC | USDC | P1 | 作为第一条 EVM 支付网络候选；Circle 与 Stripe 均有对应 USDC 支持 |
| Solana | SOL、原生 USDC、官方 USDT | USDC 优先，USDT 可同批评估 | P1 | 覆盖另一类钱包用户；Phantom 等有成熟连接入口 |
| TRON | TRX、官方 USDT | USDT | P1 | 补齐 TRC20 USDT 收发场景；开放顺序取决于真实需求和每笔资源成本 |
| Ethereum 主网 | ETH、原生 USDC、官方 USDT | USDC、USDT | P2 | 补充主网资产入口；小额订单需评估网络费占比 |
| Arbitrum One | ETH、原生 USDC | USDC | P2 | 在已有 EVM 接入基础上按需求扩展 |
| Polygon PoS | 原生手续费币、原生 USDC | USDC | P2 | Circle 与 Stripe 已覆盖相关 USDC 场景，可作为补充支付网络 |
| BNB Smart Chain | BNB；其他资产按合约逐项配置 | 稳定币版本确认后再定 | P2 | 可列入钱包覆盖范围，但不能仅凭 USDT 或 USDC 名称直接开放收款 |
| Bitcoin | BTC | 暂不作为默认付款或美元余额转出资产 | P3 | 先评估纯钱包收发；加入支付还需单独确定报价、确认与退款规则 |

稳定币发行依据：Tether 的支持协议列出 TON、TRON、Ethereum、Solana 上的 USDT；Circle 的支持列表包含 Base、Solana、Ethereum、Arbitrum、Polygon 等网络的 USDC。实际配置应以发行方的网络及合约清单为准。[Tether 支持协议](https://tether.to/en/supported-protocols/)、[Circle 支持网络](https://developers.circle.com/circle-mint/references/supported-chains-and-currencies)

TON 的名称需要注意：查询时 TON 官网将原生币称为 Gram，说明其也曾称为 Toncoin。设计中先使用“TON 原生币”，上线时核对各钱包与行情源的名称映射，避免把更名误识别为新增资产。[TON 官网](https://ton.org/)

TRON 转账涉及带宽，代币合约执行还涉及能量；资源不足时可能消耗 TRX。不能直接把“TRON USDT”写成固定低手续费通道，尤其本项目有小额转出场景。[TRON 资源说明](https://developers.tron.network/docs/bandwidth-and-energy)

如果希望第一轮多链范围尽量小，我建议按 **TON → Base → Solana** 推进；若用户或商户明确主要持有 TRC20 USDT，则将 **TRON 提到 Base、Solana 之前**。Ethereum、Arbitrum、Polygon、BNB Chain 暂不一起堆入首轮。

## 04 币种使用范围

### 先开放稳定币付款

| 资产类别 | 建议用途 | 是否默认开放付款 |
| --- | --- | --- |
| 指定网络的官方 USDT、原生 USDC | 钱包收发、商户付款、中心化美元余额转出的候选资产 | 按网络逐项开放 |
| TON 原生币、ETH、SOL、TRX、BNB 等 | 钱包收发与网络手续费 | 首版不默认开放；后续再确定波动报价规则 |
| BTC | 后续钱包资产管理 | 暂缓 |
| 桥接或封装稳定币，如部分 USDC.e、其他跨链版本 | 另行核对发行和兑换机制 | 不因名称相近自动接受 |
| Meme 币、项目代币、NFT | 暂不纳入基础产品范围 | 不开放 |

“原生 USDC”指 Circle 在对应链直接发行的 USDC，不是链的原生手续费币。支付资产按“网络 + 合约或代币标识”识别；同名资产不自动合并。USDT、USDC 与中心化美元余额也保持独立账目，不能因为通常接近 1 美元就省略实际换算和费用规则。

### 首版能力建议

| 能力 | TON 原生币 | TON 官方 USDT | 中心化美元余额 |
| --- | --- | --- | --- |
| 查看余额、资产详情、交易记录 | 支持 | 支持 | 使用独立余额与流水页面 |
| 链上收款、普通转账 | 支持 | 支持 | 不适用；产品账户间转账另议 |
| 商户付款 | 暂不默认开放 | 建议开放 | 已确定可消费，具体流程待讨论 |
| 与中心化余额组合付款 | 暂不默认开放 | 建议作为首个组合支付资产 | 按专项讨论确定金额分配和扣款流程 |
| 中心化美元余额转出到链上 | 暂不默认开放 | 建议作为首个到账资产 | 转出来源账户 |
| 链上充值到中心化余额 | 暂缓 | 可作为候选，是否做仍待回答 | 充值入账目标账户 |

奖励提现仍是“任务待提现美元 → 中心化美元余额”，不因为新增链上资产而改变。任务提现已定的最低 2 美元、无手续费，也不直接套用到后续链上转出。

## 05 外部钱包连接建议

### Telegram 首版

采用官方 TON Connect 接入；下表是重点兼容测试名单，不是限制用户选择的钱包白名单。钱包列表与能力以官方注册表和连接时返回的信息为准。[TON Connect 接入说明](https://docs.ton.org/applications/ton-connect/get-started)、[官方钱包注册表](https://github.com/ton-connect/wallets-list/blob/main/wallets-v2.json)

| 钱包 | 建议测试优先级 | 关注点 |
| --- | --- | --- |
| Keeper，原 Tonkeeper | 首批 | 手机跳转授权、返回 Mini App、USDT 转账 |
| My Wallet，原 MyTonWallet | 首批 | 多账户选择、签名及交易结果查询 |
| Telegram 内的钱包入口 | 首批 | 按官方注册表实际入口测试，不能把 Telegram 账户或托管余额视为已连接链上钱包 |
| OKX Wallet | 首批兼容测试 | 通过其 TON Connect 能力连接 TON 账户 |
| Bitget Wallet | 首批兼容测试 | 区分移动钱包与 Mini App 等不同入口 |
| Tonhub、OpenMask | 补充测试 | 分别覆盖其他手机钱包及浏览器插件场景 |

查询时注册表存在 Telegram、Gram Wallet、Walt（ex. Wallet）等不同入口。产品文案应采用实际入口名称，不统一写成一个含糊的“Telegram Wallet”。Keeper、My Wallet 等更名也应与稳定的钱包标识分开维护。

OKX、Bitget 等在此表中只表示其 TON Connect 连接能力需要测试，不表示 Mini App 可以同时调用其 EVM、Solana 等签名功能，也不构成对所有钱包的推广授权。

### 后续独立 Web 或 App

| 网络类别 | 首批建议适配钱包 | 建议接入方式 |
| --- | --- | --- |
| EVM，包括 Base、Ethereum 及后续扩展链 | MetaMask、Rabby；随后增加 OKX Wallet、Trust Wallet | 浏览器钱包连接配合 WalletConnect；按钱包、网络和客户端逐项验证 |
| Solana | Phantom；随后评估 Solflare、Backpack | Solana Wallet Adapter 或兼容钱包标准的连接层；手机端验证深度链接或钱包内浏览器 |
| TRON | TronLink；随后覆盖 OKX Wallet、Bitget Wallet | TRON Wallet Adapter，按适配器支持使用插件、手机跳转或 WalletConnect |
| TON | 延续首版 TON 钱包 | TON Connect |
| Bitcoin | 待决定是否开放 BTC 支付后再选 | 接收地址、普通转账和 DApp 签名能力分开规划 |

EVM 的通用连接层可参考 Reown AppKit，其网络与功能支持按框架分别列出；不能据此认定任意钱包支持所有链。Phantom 官方提供 Solana 直接接入和 Wallet Adapter 方案；TRON 官方适配器文档列有 TronLink、OKX、Bitget 等连接对象。[Reown 能力表](https://docs.reown.com/appkit/overview)、[Phantom 接入](https://docs.phantom.com/solana/integrating-phantom)、[TRON Wallet Adapter](https://developers.tron.network/docs/tronwallet-adapter)

这里列的是适配候选名单，不是已经通过 DexWallet 实测的钱包。首批测试至少覆盖连接、取消授权、切换账户、断开重连、签名拒绝、广播后等待，以及手机跳转返回；USDT 等代币支付不能只用原生币转账代替验收。

## 06 对页面规划的影响

| 页面或组件 | 建议表现 |
| --- | --- |
| 钱包首页 | 中心化美元余额与链上资产分区；资产行显示币种和网络，不只显示 USDT 总额 |
| 钱包选择 | 区分内置钱包、已连接外部钱包和新增连接；显示当前钱包地址及适用网络 |
| 收款页 | 先确定网络和资产，再展示收款地址、二维码及必要提示 |
| 转账页 | 根据资产选择对应网络和钱包，展示金额、余额、网络费及必要手续费币 |
| 付款确认页 | 只列当前订单可接受的资产；显示中心化支付金额、链上支付金额、网络及费用 |
| 链上转出页 | 到账币种与网络成组选取，单独显示到账数量、费用和限额 |
| 交易详情 | 展示网络、币种、金额、费用、状态和区块浏览器入口；订单状态与链上交易状态分开 |

内置钱包与外部钱包应共享资产展示和订单规则；签名方式随钱包来源变化。创建内置钱包不作为连接外部钱包或参与任务的前置条件，继续沿用已有决议。

## 07 供后续确认的建议

这些选择可以随专项讨论一起回答，不需要现在中断其他问题。

| 编号 | 建议 | 用户意见 |
| --- | --- | --- |
| N01 | Telegram 首版只开放 TON 链上支付；内置钱包先支持 TON 原生币及官方 USDT 收发 | 待填写 |
| N02 | USDT 作为首版链上付款和中心化余额转出的候选资产，原生币先用于收发及手续费 | 待填写 |
| N03 | TON Connect 完整接入，重点测试 Keeper、My Wallet、Telegram 内钱包入口、OKX、Bitget | 待填写 |
| N04 | 后续多链先考虑 Base、Solana、TRON；根据 TRC20 USDT 实际需求调整顺序 | 待填写 |
| N05 | BTC、波动币付款、桥接币及任意自定义代币暂不进入首版支付范围 | 待填写 |

资金最终到哪里、是否支持充值、组合支付是否限定同一钱包、稳定币如何换算美元，以及商户如何结算，继续在 [专项讨论清单 01–03](专项讨论清单.md) 中确定。
