# DexWallet 页面规划

基于 [产品页面功能拆分](../产品页面功能拆分.md)，首版建议采用「钱包 / 任务 / 邀请」三个底部导航入口，钱包为默认首页。页面按移动端单列布局规划，适用于后续移动端原型设计；最终运行载体尚待确定。

整体包含 13 个页面、3 类弹层，以及复用在页面内的任务和提现结果状态。页面结构可以据此开始设计；金额、奖励资格与结算方式继续沿用功能拆分中的待定项，不把布局示例当作已确认的业务规则。

## 导航与页面层级

```text
底部导航
├─ 钱包首页
│  ├─ 扫码
│  │  └─ 支付确认
│  │     └─ 支付结果
│  ├─ 提现
│  │  └─ 提现确认弹层 → 账单详情中的提现进度
│  ├─ 账单列表
│  │  └─ 账单详情
│  └─ Pro 权益
├─ 任务列表
│  ├─ 任务详情 → 页面内的任务结果
│  │  └─ 邀请弹层
│  ├─ 邀请弹层
│  ├─ 水果机 → 页面内的抽奖结果
│  └─ Pro 权益
└─ 邀请统计
   ├─ 好友列表 / 收益明细
   ├─ 账单详情
   └─ 选择任务 → 邀请弹层

外部入口
└─ 任务邀请链接 → 受邀任务页 → 页面内的助力或任务结果
```

### 导航规则

- 仅三个一级页面展示底部导航。二级页面使用顶部返回按钮，提交类页面在底部固定主操作区。
- 切换底部导航时保留各页的滚动位置和筛选状态；返回列表时恢复原位置。
- 直接打开邀请链接时优先展示受邀任务，不先跳钱包首页。若需要建立身份，完成后回到同一任务并保留邀请上下文。
- 普通二级页面返回来源页；外部直达且没有站内历史时，返回任务列表或钱包首页等明确的归属页。
- 提交成功后的返回路径不回到可重复提交的表单。支付结果返回钱包，提现提交后返回账单列表或钱包。
- 邀请入口始终关联具体任务。邀请统计页的「邀请好友」先带用户进入任务列表选择任务。

## 页面清单

| 页面 | 主要入口 | 页面形态 | 核心操作 |
| --- | --- | --- | --- |
| 钱包首页 | 默认启动、底部导航 | 一级页面 | 扫码支付 |
| 任务列表 | 底部导航、钱包任务入口 | 一级页面 | 选任务自己做或邀请好友 |
| 邀请统计 | 底部导航、邀请弹层 | 一级页面 | 查看好友贡献及收益 |
| 任务详情 | 任务卡片 | 二级页面 | 执行任务、查看结果 |
| 受邀任务页 | 外部邀请链接 | 可直接访问的二级页面 | 完成受邀任务或助力 |
| 水果机 | 任务列表 | 二级页面 | 单次参与、查看结果 |
| Pro 权益 | 钱包或任务进度卡 | 二级页面 | 了解权益、继续任务或提现 |
| 提现 | 钱包、已解锁的 Pro 权益页 | 二级表单 | 填写并确认提现 |
| 扫码 | 钱包 | 全屏功能页面 | 识别商户订单 |
| 支付确认 | 扫码识别成功 | 二级确认页面 | 核对订单并授权付款 |
| 支付结果 | 发起付款、账单中的处理中订单 | 二级结果页面 | 跟踪付款状态 |
| 账单列表 | 钱包近期账单、奖励记录入口 | 二级列表 | 查找资金和积分变化 |
| 账单详情 | 账单列表、任务奖励、邀请收益、提现提交 | 二级详情 | 查看业务来源与处理进度 |

三类弹层为「任务邀请」「提现提交前确认」「规则说明」。任务结果复用任务详情和受邀任务页，提现结果复用账单详情，水果机结果留在水果机页。身份识别及钱包接入是条件流程，选定账户和钱包形态后补充，不计入这 13 个页面。

## 三个主页面的布局

### 钱包首页

首屏优先回答“有什么资产”和“怎样付款”。任务奖励放在独立区块，不与支付资产合计成一个总余额。

```text
┌─────────────────────────────┐
│ 钱包              账户状态  │
├─────────────────────────────┤
│ 支付资产                    │
│ 币种 / 可用数量 / 网络       │
│ 其他支持的资产行            │
│ [        扫码支付        ]   │
├─────────────────────────────┤
│ 我的奖励                    │
│ 任务积分       可提现金额   │
│ [查看奖励记录]    [提现]    │
├─────────────────────────────┤
│ Pro 状态与解锁进度      >   │
│ 当前进度 / 门槛说明         │
├─────────────────────────────┤
│ 近期账单            全部 > │
│ 类型 / 金额与单位 / 状态    │
│ 类型 / 金额与单位 / 状态    │
├─────────────────────────────┤
│ 通过任务获取奖励    去看看 >│
├─────────────────────────────┤
│ ● 钱包     任务      邀请   │
└─────────────────────────────┘
```

| 区块 | 设计要求 | 点击去向 |
| --- | --- | --- |
| 顶部账户状态 | 展示当前身份或钱包准备状态；首版不默认增加个人中心 | 未满足使用条件时进入待补充的接入流程 |
| 支付资产 | 币种、数量、网络同时可辨识；余额不明时显示加载或错误状态 | 扫码支付进入扫码页 |
| 我的奖励 | 积分与可提现金额分栏；若另有奖励余额，再依据账户模型补充 | 奖励记录进入账单奖励分类；提现按资格进入表单或 Pro 页 |
| Pro 卡片 | 未解锁展示进度，已解锁缩为权益状态行 | Pro 权益页 |
| 近期账单 | 建议最多显示 3 条，标明金额单位和处理中状态 | 单条进入详情，全部进入账单列表 |
| 任务引导 | 放在资产和账单之后，保持首屏支付操作突出 | 切换任务导航 |

首次无资产时保留扫码入口，付款条件在支付流程中检查。未完成钱包准备时，点击扫码先引导完成必要接入。奖励区无法加载时保留独立重试，不影响已可用的资产区。

### 任务列表

首屏优先让用户看到奖励进度和至少一张任务卡。水果机使用紧凑入口卡，避免占据整个首屏。

```text
┌─────────────────────────────┐
│ 任务                        │
├─────────────────────────────┤
│ 当前积分      Pro 进度   >  │
│ 初始奖励状态提示            │
├─────────────────────────────┤
│ 水果机 · 参与门槛      进入 >│
├─────────────────────────────┤
│ 可参与任务                  │
│ ┌─────────────────────────┐ │
│ │ 任务名称      奖励数量  │ │
│ │ 简述 / 参与条件         │ │
│ │ 当前状态                │ │
│ │ [自己做] [邀请好友做]   │ │
│ └─────────────────────────┘ │
│ 其他任务卡片                │
│ 已完成任务              展开│
├─────────────────────────────┤
│   钱包   ● 任务      邀请   │
└─────────────────────────────┘
```

| 区块 | 设计要求 | 点击去向 |
| --- | --- | --- |
| 积分与 Pro 概览 | 数量、单位、解锁进度有独立标签 | 进度进入 Pro 权益页 |
| 初始奖励提示 | 自动发放时展示到账状态；有领取动作时再显示领取按钮 | 根据最终发放规则确定，不预设“注册即到账” |
| 水果机入口 | 展示当前参与条件，未确认扣分规则前不写可抽次数 | 水果机页 |
| 任务卡 | 名称、奖励、条件、状态、两种参与入口 | 卡片和自己做进入详情；邀请好友做打开邀请弹层 |
| 进行中任务 | 在可参与任务之前展示，按钮随状态变为继续或查看进度 | 任务详情对应进度 |
| 已完成任务 | 列表底部折叠，保留结果回查能力 | 展开后进入任务详情结果 |

任务较少时不增加分类和搜索。自己做与邀请好友做使用清晰的主次按钮样式；两者是否可同时参与由业务规则决定，禁用入口时应就近解释原因。

### 邀请统计

首屏展示已经产生的邀请结果，下方切换好友和收益两个视角。新用户无邀请时用一个明确按钮引导选择任务。

```text
┌─────────────────────────────┐
│ 邀请                  规则  │
├─────────────────────────────┤
│ 累计到账分成 · 积分         │
│ 已绑定好友数   有效助力数   │
│ [        邀请好友        ]  │
├─────────────────────────────┤
│ [好友列表]       收益明细   │
├─────────────────────────────┤
│ 好友名称      贡献积分      │
│ 绑定时间 / 最近参与状态     │
│ 其他好友或收益条目          │
├─────────────────────────────┤
│   钱包     任务    ● 邀请   │
└─────────────────────────────┘
```

| 区块 | 设计要求 | 点击去向 |
| --- | --- | --- |
| 收益概览 | 已到账分成使用积分单位；有处理中收益时单独列示 | 收益明细标签 |
| 邀请数量 | 绑定人数和有效助力数分开，统计口径确定后定稿标签 | 对应列表视图 |
| 邀请好友 | 文案说明先选择想邀请好友完成的任务 | 切换任务导航，并显示选择任务提示 |
| 好友列表 | 好友信息、绑定时间、累计贡献；无贡献显示零贡献状态 | 切换收益明细并按该好友筛选，可清除筛选 |
| 收益明细 | 来源好友、任务、积分、时间和状态 | 已产生账单时进入账单详情；未入账时保留处理状态 |
| 规则 | 说明绑定条件和任务奖励 20% 分成 | 规则说明弹层 |

不单独增加好友详情页。好友已绑定但尚未产生收益时，好友列表仍显示该记录，收益明细展示对应空状态。

## 任务与奖励页面

### 任务详情

**入口：** 任务卡片、自己做按钮。**返回：** 原任务列表位置。

从上到下依次为：返回与标题 → 奖励和任务状态 → 任务介绍 → 完成步骤 → 当前进度及校验反馈 → 参与规则。底部固定「开始任务」主按钮与「邀请好友做」次按钮。

| 当前状态 | 主操作区 | 内容变化 |
| --- | --- | --- |
| 可参与 | 开始任务 | 展示完成条件及奖励 |
| 进行中 | 继续任务；需手动检查时显示检查完成情况 | 当前步骤置于说明之前 |
| 待验证 | 查看进度 | 显示等待原因，避免重复提交 |
| 完成且奖励处理中 | 查看奖励进度 | 顶部切换为完成结果，奖励注明处理中 |
| 奖励已到账 | 查看奖励记录；次操作继续做任务 | 展示到账数量、单位与账户；触发 Pro 时显示解锁提示 |
| 未通过或失效 | 按规则重试或返回任务 | 显示具体原因 |

结果沿用本页，避免新增一个只有成功图标的页面。查看奖励记录在账单可用时进入详情；继续做任务返回任务列表。

### 受邀任务页

**入口：** 外部任务邀请链接。**返回：** 有站内来源则返回来源，否则进入任务列表。

复用任务详情布局，在任务内容之前增加「邀请者与邀请说明」和「本次参与权益」两个区块。页面内容顺序为：邀请背景 → 本人权益 → 任务要求 → 完成步骤 → 当前进度 → 固定主操作。

- 身份未确定：展示邀请背景，按钮为「继续参与」，在必要时进入身份识别；不提前显示已获得奖励。
- 新用户：展示原方案所述 1 美元奖励及领取条件，实际入账单位待定。
- 老用户：突出「帮助好友完成任务」，本人有无额外奖励按规则展示。
- 已完成：展示本次助力或任务结果，不再次展示可领取奖励的按钮。
- 链接无效或任务结束：说明原因，提供「查看其他任务」。

邀请关系绑定和本次助力结果分别反馈。完成结果里的「查看我的任务」进入任务导航。

### 水果机

**入口：** 任务列表入口卡。**返回：** 任务列表。

布局顺序为：标题与规则入口 → 积分余额与参与门槛 → 水果机主区域 → 本次结果 → 开始按钮 → 奖励记录入口。

| 状态 | 页面行为 |
| --- | --- |
| 可参与 | 开始按钮可用，明确单次投入与产出单位 |
| 积分不足 | 原按钮位置显示去做任务及不足原因 |
| 本次处理中 | 显示进度，阻止重复发起，允许离开页面 |
| 结果已确定 | 展示本次结果及余额变化，可查看记录或再次参与 |
| 结果暂无法查询 | 显示查询中或重试入口，不重新发起一次抽奖 |

本次结果在同页展示，重新进入时恢复尚未展示完的结果。奖励记录跳转账单列表并筛选水果机相关记录。规则弹层解释单次参与条件和奖励规则；期望值不作为单次保底收益文案。

### Pro 权益

**入口：** 钱包与任务进度卡、未解锁时的提现入口。**返回：** 来源页。

布局顺序为：Pro 当前状态 → 解锁进度 → 提现权益与积分翻倍说明 → 统计口径和生效条件 → 主操作。

未解锁时主按钮为「继续做任务」，已解锁时为「去提现」。达到条件但尚在处理时展示处理状态，不能提前标记权益已生效。解锁成功提示内嵌在当前页面，完整权益可点击查看。

进度条保留数值和说明位置，2 美元门槛的累计口径、翻倍范围以及解锁后是否永久有效，待规则确定后填入。该页面不设置购买按钮。

### 提现

**入口：** 钱包、已解锁的 Pro 权益页。**返回：** 提交前返回来源页；提交后按账单详情导航。

布局顺序为：可提现余额及处理中金额 → 提现金额输入 → 收款信息 → 费用及预计到账金额 → 条件说明 → 底部「下一步」。收款信息的具体字段随提现方式确定；链上提现时才展示网络、币种和收款地址。

点击下一步，校验已明确的资格、余额、金额限制及收款信息，再展示提现确认弹层。用户确认提交后进入对应账单详情的提现状态，显示待处理、已到账或失败。

金额或收款信息有误时在字段附近解释，保留已填内容。提交结果不明时先查询原请求状态，不能让用户直接重复提交。失败记录说明金额是否已恢复可用。

## 支付与账单页面

### 扫码

**入口：** 钱包的扫码支付。**返回：** 钱包。

使用全屏相机区域，顶部关闭按钮，中央识别框，下方简短提示。相机不可用时原位展示授权说明及可执行的恢复操作。

识别成功后暂停继续扫描，查询订单并进入支付确认；内容无效时留在扫码页提示重扫。已支付订单进入支付结果，过期或关闭订单展示不可支付状态，并提供重新扫码入口。

### 支付确认

**入口：** 扫码查询到可支付订单。**返回：** 扫码页。

```text
┌─────────────────────────────┐
│ ‹ 支付确认                  │
├─────────────────────────────┤
│ 商户名称                    │
│ 订单金额与计价单位          │
│ 订单号 / 有效状态           │
├─────────────────────────────┤
│ 支付币种与网络          >   │
│ 应付数量 / 可用余额         │
│ 所需费用                    │
│ 总计支付数量及单位          │
├─────────────────────────────┤
│ 收款信息与订单说明          │
│ 错误或不足原因提示区域      │
├─────────────────────────────┤
│ [         确认支付       ]  │
└─────────────────────────────┘
```

币种选择优先在页内展开，仅列出该订单支持的币种与网络。选择变化后同步更新应付数量、费用及余额校验。费用使用不同资产支付时分别列出数量，不合计不同币种的数值。

用户确认后进入授权过程；取消授权返回本页并保留选择。付款发出后进入支付结果。订单过期、余额不足或费用不足时说明原因，不能继续发起付款。

### 支付结果

**入口：** 付款发出、已支付订单扫码、账单中处理中的支付记录。**主要退出：** 返回钱包；具备有效商户返回入口时提供返回商户。

布局顺序为：付款状态 → 金额与商户 → 支付进度 → 订单及交易信息 → 操作区。

| 状态 | 主信息 | 操作 |
| --- | --- | --- |
| 已发送待确认 | 付款正在确认 | 返回钱包、查看账单；保留状态查询 |
| 支付已确认且商户已确认 | 支付成功 | 返回商户或钱包、查看账单 |
| 支付已确认但商户处理中 | 已付款，商户订单确认中 | 查看进度、查看凭据；不出现再次支付 |
| 明确付款失败 | 未完成本次支付及原因 | 订单仍可支付且已确认没有成功付款时，返回支付确认 |
| 状态未知或匹配异常 | 已有付款需要继续核实 | 查询状态、查看凭据，后续处理入口随业务方案确定 |

付款结果和商户处理结果分开表达。查询失败不显示为付款失败。已发出的订单退出后，可从钱包账单恢复跟踪。

### 账单列表

**入口：** 钱包全部账单、奖励记录、水果机记录。**返回：** 来源页。

布局顺序为：标题 →「钱包资金 / 任务奖励」分类 → 类型筛选 → 按时间排列的账单行。默认按最近时间展示，来自奖励或水果机入口时自动应用对应筛选。

每行包括业务名称、数量及单位、时间、状态；金额变化标记收入或支出，处理中用文字标识。空状态根据当前分类说明暂无记录，加载失败提供重试。点击行进入账单详情，返回后保留分类、筛选和滚动位置。

首版不增加搜索、导出和复杂统计图表。两类账单的账户归属以最终账户模型为准。

### 账单详情

**入口：** 账单列表、任务已到账奖励、邀请收益、提现提交。**返回：** 原来源；提现提交后返回账单列表，提供返回钱包的快捷操作。

共用结构为：业务类型与状态 → 数量及单位 → 时间与业务标识 → 组成明细 → 关联业务入口。按业务补充以下信息：

| 账单类型 | 专属信息 | 关联操作 |
| --- | --- | --- |
| 任务奖励 | 任务、基础奖励、适用的翻倍奖励、到账情况 | 查看任务 |
| 邀请分成 | 来源好友、关联任务、计算基数、分成积分 | 查看邀请收益 |
| 水果机 | 本次参与投入、产出、各自单位和处理情况 | 返回水果机；两笔关联记录可互相查看 |
| 提现 | 收款信息、申请金额、费用、到账金额、处理进度 | 查看资金恢复情况，必要时按规则重新申请 |
| 商户支付 | 商户、订单、币种与网络、支付与商户状态、交易凭据 | 处理中可进入支付结果继续跟踪 |

提现待处理、成功、失败均在这里表达，不再新增提现结果页面。对失败后的重试，仅在原请求状态和可用余额已明确时开放。

## 弹层规划

| 弹层 | 触发入口 | 内容顺序 | 操作与关闭行为 |
| --- | --- | --- | --- |
| 任务邀请 | 任务卡、详情的邀请按钮 | 任务名称 → 好友要做的事 → 双方权益 → 邀请链接 | 复制链接为主操作；可选系统分享；查看统计切换邀请导航；关闭后回到原任务 |
| 提现确认 | 提现表单下一步 | 金额 → 收款目标 → 费用 → 预计到账 → 条件提示 | 确认提交或返回修改；提交中防重复，状态不明时引导查询 |
| 规则说明 | 邀请、水果机等页面规则入口 | 与当前场景相关的参与规则和结算说明 | 关闭后保持原页面状态 |

移动端建议使用底部抽屉，长规则可在抽屉内滚动。复制成功使用短暂提示；链接生成失败在弹层中提供重试。Pro 解锁使用页面内提示，避免用户完成任务时同时出现多个弹窗。

## 通用布局与交互约定

| 项目 | 规划 |
| --- | --- |
| 内容层级 | 标题、核心数字或状态、解释、操作依次明确；金额始终带单位 |
| 布局 | 主页面纵向卡片布局；表单单列；底部按钮避开系统安全区域与软键盘 |
| 操作权重 | 每个关键步骤突出一个主操作，次操作使用较轻样式；任务卡保留两种参与入口 |
| 加载 | 列表和金额区域使用占位；金额未知时不显示为零；各区块支持独立失败反馈 |
| 禁用 | 不仅变灰，还显示不能操作的原因及可用的后续入口 |
| 状态 | 处理中、成功、失败使用文字加图形共同区分，不仅依赖颜色 |
| 恢复 | 离开后重新进入，恢复任务进度、支付和提现状态、未完成展示的水果机结果 |
| 文案 | 页面名称和金额术语保持一致；实现时统一纳入国际化资源，预留较长文本空间 |
| 适配 | 以移动端为主要画板；窄屏单列不横向溢出，大屏可将一级导航移至侧边，页面关系不变 |

## 原型出图与检查顺序

| 批次 | 画板范围 | 必须覆盖的状态 |
| --- | --- | --- |
| 第一批 | 钱包、任务、邀请三个主页面 | 有数据、首次使用、空数据、加载失败；Pro 已解锁与未解锁 |
| 第二批 | 任务详情、受邀任务、邀请弹层、水果机、Pro | 本人参与、新老用户受邀、待验证、奖励处理中、已到账、参与失败或资格不足 |
| 第三批 | 提现、提现确认、扫码、支付确认、支付结果 | 资格不足、表单错误、取消授权、处理中、成功、失败、商户确认中 |
| 第四批 | 账单列表与各类详情、跨页面返回和恢复 | 筛选无记录、资金或积分单位、处理中记录、失败恢复、外部链接直达 |

检查完整路径：任务到奖励记录、邀请到好友参与结果、水果机到对应记录、Pro 到提现进度、扫码到支付凭据。每条路径都应能退出并重新查看结果。

## 待业务确定后填入的内容

| 待定内容 | 当前页面处理 | 确定后调整的位置 |
| --- | --- | --- |
| 身份及钱包接入方式 | 保留必要接入入口和任务上下文恢复规则 | 首次使用流程、钱包顶部、支付授权 |
| 积分与可提现金额关系 | 分区展示，未定义的账户类别不画入余额汇总 | 钱包奖励区、水果机、提现、账单分类 |
| 初始奖励与受邀奖励关系 | 分别预留状态，不默认发两笔 | 任务概览、受邀权益、奖励结果 |
| Pro 累计口径与翻倍范围 | 预留进度说明与权益条件位置 | Pro 卡片、权益页、任务奖励明细 |
| 邀请参与资格与分成基数 | 保留新老用户分支和双方权益说明 | 邀请弹层、受邀任务、邀请收益明细 |
| 水果机扣分和产出规则 | 预留投入、产出及单位，不写固定可抽次数 | 水果机入口、玩法界面、账单 |
| 提现方式与费用限额 | 先确定单列表单和确认流程，字段待填 | 提现、确认弹层、提现账单 |
| 支付网络与订单规则 | 先确定核对、授权、处理中和结果流程 | 币种选择、费用、有效期、异常处理入口 |

这些待定项影响页面数据、文案和部分分支，不妨碍先完成导航、内容层级和低保真原型。接入方式或资金流转若增加新的用户操作，再补充对应页面。
