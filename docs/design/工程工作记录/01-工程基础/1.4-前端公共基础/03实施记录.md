## 实现选择与边界

- React/React DOM 18.3.1 与 React Router 7.18.4 满足本次组件组合 peer 范围；没有强行忽略移动组件传递依赖的 React 版本声明。直接版本和 pnpm lockfile 可追溯，工具链 Node/pnpm 未变更。
- 使用 `@tma.js/bridge` 2.3.3；已核对依次读取 URL/navigation entry/SDK 会话缓存的源码行为。只使用这一套原始启动缓存，项目另存目标生命周期，不逐字段合并新旧启动。无服务端验签、身份确认或业务目标副作用。
- 公共请求包不包含 React/UI；api-contract 类型仍由既有 `.api` 生成。健康响应解码属于手写协议边界，没有修改源契约或生成文件。
- 桌面布局由共享包提供，导航定义由各应用传入；移动布局留在用户端。没有给未来业务批量建空目录，也没有全局状态库、查询缓存或认证状态。
- 开发样例只在 DEV 条件下延迟导入；构建插件检查真实 chunk 模块，额外检查 manifest 和产物。生产没有开发工具页；业务尚未完成时明确显示未开放。

## 问题修复与遗留

首次浏览器检查发现移动 NavBar 将 back 内容放入 aria-hidden 区域，导致返回链接缺失可访问名称；改为语义明确的原生 header/Link，并验证键盘和触控。延迟路由增加本地化加载态。合成 Telegram fixture 补齐所选 SDK 要求的 signature 字段；该字段没有被当成已验证签名。

WebKit 下载首个官方地址持续缓慢，切换 Playwright 官方 CDN 后完成；安装本机缺少的 libgstreamer-plugins-bad1.0-0、libavif16 及所需依赖，未升级或移除无关系统包。

两个后台当前主 JS 约 605 kB（gzip 约 201 kB），Vite 给出 500 kB 提示。此项未掩盖提示或提高阈值；业务页面随模块引入时按路由拆分，当前不以人工拆 vendor 包代替性能验收。没有宣称完成线上性能或真实设备兼容。

1.5 继续处理干净环境重放、测试数据库、Redis/RocketMQ 隔离、部署代理及环境联通；2.2–2.4 处理真实 Telegram、鉴权、BackButton 和来源恢复；8.3 执行完整发布验收。未实现鉴权、账本、支付、任务或其他后续业务。
