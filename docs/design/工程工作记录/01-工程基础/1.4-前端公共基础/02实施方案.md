## 目标与工作边界

在现有三个应用 workspace 和生成类型之上，建立可独立启动与构建的前端入口，完成路由、请求与错误处理、国际化、页面布局和实际使用的基础组件。沿用 [开发规范](../../../../engineering/开发规范.md)、[工程结构](../../../../engineering/工程结构.md)、[契约生成与迁移](../../../../engineering/契约生成与迁移.md) 和 [后端公共基础](../../../../engineering/后端公共基础.md)。

信息架构遵循 [信息架构与交互原则](../../../01信息架构与交互原则.md) 和 [商户与平台界面](../../../03商户与平台界面.md)。本项验证页面承载能力，不实现登录、钱包连接、权限判断、资金数据、任务、支付、账本和消息订阅。无数据库迁移、服务端业务事务或新增业务 API。

1.4 负责前端本身的开发代理、构建和浏览器验证；1.5 负责干净环境、部署代理、域名及全栈联通。健康接口只用于技术验收，不能表示业务能力已经完成。

## 设计与实现步骤

### 1. 应用与共享模块（Q01）

建议目录如下；仅创建本项实际使用的目录和包，不为未来模块批量建立空壳：

```text
frontend/
  apps/
    user/src/
      main.tsx
      app/                 # 本端 provider、路由与移动布局
      api/                 # 本端客户端实例和手写端点适配
      components/          # 本端基础状态组件
      view/<module>/       # 页面 index.tsx 与 style.less
      locales/             # 本端文案
    merchant/src/          # 同样分层，独立路由和实例
    admin/src/             # 同样分层，独立路由和实例
  packages/
    api-contract/          # 已有生成类型，继续由 .api 生成
    api-client/            # 不依赖 React/UI 的请求、解析与错误类型
    i18n/                  # 初始化工厂、公共文案与错误码翻译
    ui-desktop/            # 商户/管理实际共用的后台布局与状态组件
```

用户端使用 Ant Design Mobile；后台使用 Ant Design。移动端组件留在 user，暂不建立只有一个消费者的移动 UI 包。共享包不反向依赖应用，不持有全局会话，不引入业务路由；user 的依赖树和构建产物不携带桌面组件库。

用户端承接钱包／奖励／记录三个主入口，仅主页面展示底部导航；子页面使用返回入口，并有明确站内回退目的地。未实现页面显示未开放状态，不显示假余额、假订单或把未知值显示为零。商户与管理端各自提供桌面侧栏、标题区和内容区；导航定义留在各自应用，仅注册本项实际提供的入口，其余业务菜单随业务增加。

库组件直接使用；只有形成项目行为或布局约定时才增加封装，不为每个 Button/Input 添加透传包装。加载、空态、筛选无结果、错误和未开放分别表达。配色不作为唯一状态提示，可访问名称也通过国际化资源提供。

### 2. 路由与状态（Q02）

每端独立使用 React Router 的 createBrowserRouter 与 RouterProvider，采用客户端 Data Mode，保留现有 Vite SPA 构建。选择 Data Mode 是为了集中定义嵌套布局、路由错误边界和后续表单离开保护；本项不强制把所有请求迁入 loader/action，不增加 SSR 或 Node 线上服务。

使用 History 路由，提供根路径跳转、未知路由页、受控的站内返回入口。生产部署必须将页面路径回退到所属应用的 index.html，但 API 与静态资源错误不能被改写为 HTML；此部署规则进入 1.5。Telegram 的启动参数、返回按钮及认证恢复在对应接入项设计，不将浏览器路由当成 Telegram 集成完成。

可分享的筛选、分页状态归 URL；表单草稿和弹层状态归所属页面；语言等少量应用设置通过 provider 传递。默认不引入全局状态库或 TanStack Query；后续出现服务端数据缓存、失效和轮询需求时按实际页面引入，避免在本项另造查询缓存。刷新不承诺恢复未提交表单，不把敏感草稿默认存入 localStorage。

### 3. 请求与错误边界（Q03）

调用关系为：页面／后续业务 hook → 应用 api 适配 → 共享 api-client → HTTP；api-contract 为客户端和应用提供生成类型。路由与 UI 不进入共享请求库。各应用通过工厂创建独立客户端，配置 base URL、有限超时及调用方取消信号；会话和认证回调以后由所属应用注入。本项不增加 token 存储、自动刷新或登录跳转。

基于 fetch 实现；必须同时检查 HTTP 状态与响应协议，不能把收到 HTTP 响应等同于成功。成功需符合 HTTP 成功状态及 code=OK，失败保留 status、code、traceId 和诊断原因。返回 JSON 首先作为 unknown 处理，校验公共 envelope；端点适配负责具体 data 校验，不能通过泛型断言把未检查的数据当作生成类型。手写校验不修改生成文件，接口字段变化仍先改 .api。

错误区分有结构的业务拒绝、无标准响应的 HTTP 错误、网络不可达、超时、调用方取消和协议不符。未知业务码保留原字符串及 traceId，显示通用本地化提示；不将未知码强制转换为生成的已知错误码联合类型。即使 HTTP 成功，错误 envelope 或损坏数据也不能成为正常 data。

请求库只返回结果或抛出明确错误，不弹 Toast、不路由跳转。页面决定内联错误、页面错误或一次性提示；主动取消不提示失败。公开界面按 code 映射文案，不直接展示服务端原始诊断 message；开发诊断保留足够上下文且不输出凭据。traceId 可用于问题定位。

首版不自动重试请求，尤其不自动重复提交写操作。超时不表示服务端已撤销；后续资金页面依据原请求标识查询状态，由所属业务项落实幂等与恢复。并发查询应取消或忽略过期结果，不能让旧响应覆盖新选择。

开发时建议每端默认请求同源 `/api`，Vite 代理去掉该前缀后转发到本地后端，因此 `/api/health/live` 对应现有 `/health/live`。三个应用采用独立开发端口并启用 strictPort。公开的 `VITE_API_BASE_URL` 只配置地址，不存放凭据；生产 `/api` 代理由 1.5 配置，不把本项开发代理当作已完成的线上部署。

### 4. 国际化与展示（Q04）

i18next 已确认；本项建议使用 react-i18next，首版资源为 zh-CN 和 en。选择顺序为本端已保存的用户偏好、浏览器支持语言、英文；只将明确的简体中文变体映射到 zh-CN，不把繁体语言自动当成已支持。语言偏好存储使用带应用名称的具名 key，存储不可用时仍可正常运行。

公共命名空间维护通用操作和错误，应用命名空间维护导航和本端文案。分别创建 i18n 实例，语言切换同时更新组件库 locale、文档 lang、日期等展示；缺失翻译有明确回退，测试检查两种语言 key 一致。静态文案、错误提示、占位符和可访问标签均使用资源。

金额沿用 API 十进制字符串及单位，禁止统一转成 Number 后计算；本项仅按实际组件需求提供展示，不提前建立金融计算库。时间明确时区；未知金额、空列表和零值保持区别。语言集合与兜底语言仍待确认，不沿用归档原型作为新增决议。

### 5. 验证与实施顺序（Q05）

确认 Q01–Q05 后再安装依赖。实施时核对 React、React DOM、Vite、路由、组件库和测试工具的兼容范围，固定可复现版本及 pnpm lockfile；保留已经确认的 Node/pnpm 工具链，必要升级单独说明依据。

依次补齐三个入口及构建配置、布局路由、国际化、请求与错误处理，最后补充验收。基础组件只在实际用到时引入。采用 Vitest 与 React Testing Library 验证客户端和组件的可观察行为，网络边界用 fake；少量 Playwright 浏览器用例验证路由、语言与布局，真实后端联通单独运行。

开发样例用于验证健康接口、加载、故障和恢复，不放在产品导航中；采用独立开发入口或仅开发环境加载的模块，并检查生产构建不能访问该样例。生产骨架只展示明确的页面状态，不暴露内部工具、技术诊断面板或虚构业务数据。健康接口成功仅证明请求链可达。

## 验收条件

以下是确认后的目标，不代表本轮已经通过：

| 范围 | 可观察的通过标准 |
| --- | --- |
| 工程 | 三端可分别启动、类型检查和构建，lockfile 安装可复现；生成契约检查无手改漂移 |
| 路由 | 主入口、子路由、返回、未知路由可用；验证移动主页面底栏与子页面区别；部署路径回退要求明确移交 1.5 |
| 布局 | 用户端在窄屏可操作，桌面两端布局可用；键盘焦点、可访问名称、空态与错误态有实际验证 |
| 类型与协议 | 合法健康响应可消费；缺失字段、损坏 JSON、HTML 错误页、非成功 HTTP、未知业务码均不能伪装成正常结果 |
| 请求生命周期 | 超时与取消可区分；不自动重试写操作；过期请求结果不覆盖新状态；失败可在显式操作后恢复 |
| 国际化 | 中文和英文切换覆盖导航、公共错误与组件文案；不支持语言按约定回退；业务界面不显示裸翻译 key |
| 隔离 | 三端路由、客户端、语言实例独立；用户构建不带桌面 UI；生产入口不能访问开发样例 |
| 范围 | 不新增业务鉴权、余额、订单或任务 API；未实现状态与真实空数据有区别；真实健康联通与模拟网络测试分别记录 |

执行命令、版本、结果与剩余限制在 [验证记录](04验证记录.md) 中维护；本轮仅运行文档和差异检查。
