## 实际交付

1. `backend/goctl.yaml`：配置 decimal/dec/numeric 的 Decimal、NullDecimal 与包路径；配置读取固定在临时 backend module，固定 GOCTL_EXPERIMENTAL=on。没有修改 model 模板、生成器源码或生成后类型。
2. `backend/manifest/api/examples/`：根契约导入 shared 类型，生成 Go 样例及前端类型；包含嵌套、数组、可选字段、枚举和金额字符串。样例位于 `backend/tests/codegen/example`，未建立正式 backend/api，也未接鉴权或业务接口。
3. `backend/manifest/sql/ddl/examples/` 与 `diff/examples/`：完整示例结构、建表及新增 note 的两步迁移；无缓存 model 位于 `backend/model/example`，手写 WithSession 扩展已验证随调用者事务回滚。
4. `scripts/prepare_tools.py`、`tools.json`：局部固定安装 goctl 1.10.2；go.mod/go.sum 锁 go-zero 1.10.3、decimal 1.4.0、golang-migrate 4.19.1、MySQL driver 1.10.0。TS 编译器为 5.9.3，pnpm 锁文件新增共享类型包。
5. `scripts/generate.py` 与 `generated-files.json`：临时目录生成；4 个纯生成文件带校验、8 个手写骨架只创建缺失项；检测本地手改、删除和额外未跟踪产物；个人模板、输入自动格式化和备份不影响仓库源。
6. `frontend/packages/api-contract`：仅类型导出，strict 与 exactOptionalPropertyTypes 检查；未发布生成请求客户端或会话能力。Go 回显样例保留原始金额字符串，空数组返回 []。
7. `backend/internal/migration` 与 `tools/migrate`：薄工具封装调用 golang-migrate；DSN 由环境提供，显式目标必须匹配，目前只接受 examples 与项目测试库。仅 up/version，不提供自动 down/force；应用不在启动时迁移。
8. `scripts/test_codegen.py`、Go 单测、TS 类型断言与独立 MySQL 集成测试；`scripts/check_contracts.sh` 提供不连接外部服务的统一检查。

实际路径和命令集中在 [契约生成与迁移](../../../../engineering/契约生成与迁移.md)。新增代码遵循单后端 module，未实现用户、账本、支付、缓存、消息或前端页面。

## 偏差、处理与遗留

- goctl v1.10.3 是前期源码评估候选，但其工具子模块没有对应可安装版本；改用已发布 v1.10.2，运行库锁 v1.10.3，生成与编译组合已通过。不升级或覆盖全局 goctl 1.9.0。
- goctl 将 GOWORK=off 误判为存在工作区；生成入口清除继承的 GOWORK，并在独立临时目录使用单 module。未创建持久 go.work 或第二个 go.mod。
- 直接 TS 生成未证明可保留任意 JSON null；入口明确拒绝指针/interface{}，样例使用缺省省略和非空数组。未来业务需要显式 null 时应先补表示法/工具验证，当前不伪称支持。
- 首次失败迁移测试只放入第三步，迁移器在校验当前第二版来源时已拒绝，未进入 SQL；测试修正为保留前两步再追加失败步骤，实际验证 DDL 部分提交、dirty 与重复执行被阻止。
- 本轮执行的数据库验证全部使用既有本地 MySQL 的隔离库并清理，最后核对 `dexwallet_contract_` 前缀库剩余为 0。未改变已有容器、用户业务表、服务配置或凭据。
- 生产 MySQL 版本、正式迁移集、完整响应/错误规则与客户端运行时仍归 1.3–1.5 及业务项；样例没有替代这些工作。
