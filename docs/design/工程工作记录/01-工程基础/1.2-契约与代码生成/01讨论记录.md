## 目标与沿用结论

1.1 已完成最小工程初始化，基线为 `ebdf91f`。本项要建立可重复的 `.api → Go/TS`、`SQL DDL → model` 和独立迁移流程，并证明手写扩展不会被生成覆盖。具体方案见 [实施方案](02实施方案.md)。

沿用 [1.1 决议](../1.1-工程结构与模块划分/01讨论记录.md)：Go/go-zero/goctl、MySQL/InnoDB、SQL-first；`.api` 是 HTTP 唯一权威源，前端类型从同源派生；完整 DDL 与增量迁移同时维护；一个后端 module、三个前端应用，前端共享包不含会话；Redis/RocketMQ 已纳入架构。这些不重新选型。

沿用 [开发规范](../../../../engineering/开发规范.md)：精确金额不经浮点转换，API 金额用带单位语义的字符串，对外 ID 沿用 idx；生成与手写分开，数据库操作不藏在代码生成中。金额精度、状态全集、错误码、鉴权、账本等业务细节仍随所属项确定。

## 已核对事实与关键顾虑

- 本机已有全局 `goctl 1.9.0`，帮助中包含 `api go`、`api ts`、`model mysql ddl`。这只证明本机工具存在，不是项目版本已选定，也不是生成已通过。
- 官方 CLI 文档与源码提供直接 TS 生成；命令还会生成请求辅助代码。因此建议在临时目录生成并按明确清单提取类型，不能声称它有一个已核实的“仅类型”开关。请求执行、登录态和错误处理归 1.4。
- 已查阅 v1.10.3 源码：SQL 默认 DECIMAL 映射为 float64；自定义类型映射受实验开关路径影响。需要把配置和开关固定进项目生成入口，验证配置缺失时不能悄悄退回浮点。精确表示的原则已确认，具体映射实现仍需验证。
- TS 生成器对指针与 optional/omitempty 的处理不等于自动保留 JSON null 语义。示例必须对照实际 JSON 与生成类型；不支持的必要语义应明确失败并调整工具路线，不能用 any 或断言掩盖。
- MySQL 的部分 DDL 会隐式提交，迁移工具不能把它们变成普通可整体回滚事务。迁移失败须保留版本/失败信息并核对实际结构，不能自动 force 清状态或假装回滚成功。

具体官方来源及适用限制集中在实施方案。上述是方案依据，没有写入实施、验证记录冒充工程验收。
