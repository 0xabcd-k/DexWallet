## 2026-10-28 实施批次

- 新增 tooling-only `internal/testenv`：用 MySQL driver 解析 DSN，连接前校验本地显式目标及账号/库用途；示例迁移、后端 integration、前端 HTTP runner 共享保护。
- 新增 `prepare_local.py` 显式准备长期开发库与 HTTP 测试库、受限账号；随机密码只保存在忽略的 0600 文件。测试管理员只有 contract 前缀库权限，HTTP 账号只有指定库 SELECT；API 不持有建库凭据。
- 后端 integration 使用随机运行目录/资源清单，正常精确清理；`tools/testenv run/cleanup` 提供中断恢复，文件锁防止清理仍在运行的 suite。增加权限隔离、强杀恢复、清理失败保留与跨 run 拒绝验证。
- MQ 通过现有 Apache SDK 真实生产/消费；公开 SDK 缺少消费组删除，使用现有 broker 5.3.2 自带 mqadmin 删除确切组及 offset，SDK 清理 retry/DLQ/topic 并核对元数据。
- `check.sh` 编排 common/browser/integration/http/all，保留既有底层工具。默认不连接中间件，错误非零且保留阶段日志。
- Vite 收紧 `/api` 路径匹配；HTTP runner 验证独立凭据、创建本次产物/日志、管理自己的进程组；补齐三端 dev/preview 的健康、trace、404 和页面刷新验证。
- 运行说明见 [开发与测试环境](../../../../engineering/开发与测试环境.md)。本轮没有引入新依赖、业务接口、业务表、Nginx 或生产发布。

实施细节：HTTP 使用明确允许的长期外部测试库，符合 Q02 保留长期资源分支；contract 随机库按次回收。本机 MySQL root 只在显式准备工具的容器内授权步骤使用，不传给测试/API。当前本地工具固定既有 Redis/MQ 地址及 broker 工具路径，远端环境支持属于后续配置工作。
