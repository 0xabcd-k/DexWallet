方案状态：Q01 本地开发方式及 8.2 正式部署基线已确认；Q02 已确认并以生产数据库不被测试污染为前提；Q03 按用户本地轻量化意见修订为 Vite 代理与构建预览，Q04–Q05 继续讨论。已有工程决议沿用，确认依据记录在 [讨论记录](01讨论记录.md)。下列路径和新增入口为拟议位置，不是已实现命令。

## 目标与工作边界

把 1.1–1.4 的工程能力收敛为可重复的准备、开发、构建、隔离集成和本地联通流程。能够在干净 checkout 中按记录准备工具、生成契约、运行检查，并通过 Vite 原生代理访问现有 API、检查三端构建产物。

包含：本地运行配置、独立测试数据库、现有 Redis/RocketMQ 的隔离接入、构建与自动化入口、三端构建产物本地预览及可观察的验收记录。

不包含：新增登录/会话、业务表、账本、资金通道、业务消息消费者、outbox、生产发布与容灾。MQ 收发使用测试消费者，不建立正式 worker；HTTP 继续使用现有健康契约，不为验收新增公开故障或回显接口。

## Q01：运行方式

建议保留宿主机 Go/Vite 开发和现有 Docker 中间件。现有开发端口继续为 API 8888、用户端 5173、商户端 5174、管理端 5175。配置默认绑定 127.0.0.1；端口冲突即退出，不查找并杀死占用者。

本地构建检查沿用三个独立 dist 和 Vite preview，复用已有浏览器配置的 4173–4175 端口。真实联通使用独立测试 API，优先沿用已有 18888 入口；共享固定端口的测试串行运行。通过 `DEXWALLET_API_PROXY_TARGET` 显式指定本次 API，测试入口不得静默回退到正在开发的 API。端口冲突即退出，只结束本次启动的进程。不再新增原拟议的 Nginx 容器、18080–18082 站点和 18889 API。正式部署配置和容器网络在 8.2 验证。

| 拟议位置 | 职责 |
| --- | --- |
| `scripts/` | 少量准备检查、开发进程启停、分层检查、本地联通入口；调用现有命令，不实现通用调度器 |
| `.tools/local/` | 忽略的运行配置、日志、产物和本次资源清单；异常退出后保留必要诊断 |
| `backend/tests/integration/` | 真实 SQL/Redis/MQ 集成用例，继续通过独立标签运行 |
| `frontend/tests/` | Vite 开发/构建预览下的浏览器请求、路由刷新和错误恢复检查 |
| `docs/engineering/开发与测试环境.md` | 实施后写入真实可执行的准备、运行、复验和清理命令 |

凭据由现有环境变量提供；无凭据样例描述必填项和作用。工具不扫描用户其他项目配置、不输出 DSN，不为每个用途复制一整套长期配置。开发库准备、测试资源分配、迁移和启动分别显式执行。

## Q02：资源隔离与清理

已确认：为持久开发和每次测试建立不同资源归属，测试不得接入或污染生产数据库：

| 资源 | 建议策略 | 边界 |
| --- | --- | --- |
| MySQL 开发库 | 专用开发库/账户，按明确准备步骤创建一次 | 日常启动不建库、不迁移、不清空数据 |
| MySQL 集成库 | 沿用 `dexwallet_contract_` 随机库测试机制；其他测试用途独立命名并记录 run ID | 应用账户与建库/迁移测试权限分开；不使用业务库做迁移故障注入 |
| Redis | 通过现有 Namespace/RedisKey 方法生成环境与 run ID 下的 key；加有限 TTL | 不用 FLUSHDB/FLUSHALL，不清理其他运行的 key；DB 编号不能替代命名空间 |
| RocketMQ | 每次创建明确归属的独立 topic 和 consumer group，测试消息携带 run ID 和唯一消息标识 | 不使用默认/业务 topic，不修改 broker 全局配置，不干扰其他订阅者 |
| 进程与端口 | 记录自己启动的进程/容器及监听地址 | 退出只回收本次资源，不用全局 pkill 或停止共享容器 |

MySQL 迁移沿用 golang-migrate。当前用 examples 在隔离库证明空库初始化、旧版升级和失败 dirty 状态；没有业务迁移集时如实报告，不把示例部署到开发业务库凑验收。

MQ 测试优先调用已锁定 Apache SDK 的公开 admin、producer、consumer 能力：显式建立 topic，启动订阅，发送少量无业务含义消息，等待收到匹配标识并返回消费结果。验收要求至少观察到目标消息，不能把重复投递判为“库不可靠”，也不声称 exactly-once 或业务幂等已实现。发送超时保留未知，不通过无界重发掩盖问题。

测试限时退出；停止消费者和生产者后清理本次 topic 等资源。SDK 的公开 admin 已有 CreateTopic/DeleteTopic，消费组、重试/死信元数据的实际清理方式还需核对当前版本支持的公开工具；不提前承诺全部自动删除。清理失败记录资源名、阶段和后续处理方式，结果不能显示为完整通过。强杀残留依照 run ID 清单核对，不按宽泛前缀批量删除。

### Q02 细化：准备、运行与清理

以下为 Q02 已确认实施方向，不是已经提供的脚本；命名样例和服务能力仍按实施结果核对：

1. 开发配置保持 `Environment: local`，独立开发库建议 `dexwallet_dev`；名称是环境配置，不写死在领域代码。应用启动只校验并连接，首次建库和后续迁移另走显式准备入口。
2. 每次测试分配运行标识（安全随机值，不只依赖秒级时间），与代码版本、测试类型及资源清单一同记录在忽略的本地目录。沿用已有随机库前缀和 SDK 命名方法，测试类型分工不被统一包装隐藏。
3. MySQL 契约用例继续自行创建随机 `dexwallet_contract_` 库；前端联通使用准备入口创建的专用测试库。现有两个入口都使用 `DEXWALLET_TEST_MYSQL_DSN`，但分别要求建库能力/指定库运行权限，说明中必须区分；不要让前端联通意外继承管理员凭据。
4. 使用配置提供的管理连接执行测试资源准备，给应用进程注入限定测试库的运行连接；不从其他项目配置中搜凭据，不把特权连接放入应用 YAML。实现时验证账户/授权是否能按测试库范围限制，不能仅靠名称前缀声称已有数据库权限隔离。
5. Redis 环境可形如 `integration_<run_id>`，通过现有方法得到 `dexwallet_integration_<run_id>:...`；topic/group 使用对应项目前缀和运行标识。完整资源名记录到清单，进程实例身份避免同机多个客户端冲突。样例是拟议约定，具体长度/字符约束按锁定 SDK 与实际服务验证。
6. 共享端口的浏览器/联通测试先串行执行，冲突明确失败；资源命名独立不等于现有端口、日志目录已支持并行。后续有并行需求再参数化端口和工作目录，不预先建立通用环境调度器。
7. 清理按依赖顺序执行：停止本次 API/消费者/生产者，释放连接，再删除完整名单内的 key、topic、测试库和临时账户。正常/测试失败均尝试清理；清理失败保留原因和资源名，并以非零结果结束。TTL 只覆盖相应 Redis 临时数据，不代表 SQL/MQ 资源有自动过期机制。
8. 进程强杀时，按本次清单核对后恢复清理；不能误删用户指定的长期测试库、开发库或另一轮仍活跃的资源。已有外部资源不是本轮创建就不自动纳入删除名单。MQ 消费组/重试元数据的清理继续按公开工具能力验证，失败残留不能隐藏。

Q02 验收补充：正常结束和测试失败都不影响开发库及其他 key/topic；相同场景重复运行不复用上次脏状态；缺少准备权限时报错而非换用开发库；提供外部长期库时不会被自动删除；清理失败可定位且不误报完全通过。现有迁移/事务测试和前端健康用例继续复用，只在真实依赖边界补必要验证。

### Q02 补充：生产数据库保护

用户明确要求以保持生产数据库干净为前提。实施时需落实并验收：

- 开发、测试、生产使用独立连接配置和账户；正式数据库处于独立实例/网络访问边界，测试进程和测试准备工具不持有生产凭据。资源创建权限也仅面向明确的测试目标。
- 连接前校验测试入口的目标地址、数据库用途及显式允许的测试配置；禁止使用 production 配置或静默回退到普通应用/生产 DSN。随机测试库前缀和 `Environment` 字符串只是辅助检查，不代替真实账户和网络权限隔离。
- 自动化用例、examples 迁移、初始化样例和清理命令均不能指向生产库；不以在生产实例上另建一个随机库作为默认隔离方式。测试数据由样例构造，不默认复制生产数据。
- 清理只处理已登记且由本次运行创建的资源，外部指定的长期库不自动删除。真正的生产 schema 迁移属于 8.2 显式发布流程，不能混入测试入口或 API 启动。
- 误传非测试配置、缺少专用凭据、目标不在测试允许范围时，必须在发起数据库连接前拒绝。使用 fake/本地隔离目标验证拒绝与权限边界，不通过尝试连接真实生产库证明保护有效；检查生产内容是否“没变”也不能当作测试流程的一部分。

当前文档仅确定要求，现有测试入口尚未实现全部保护校验；后续不能在这些保护完成前宣称可以安全向任意 DSN 运行测试。

## Q03：本地代理与构建预览

按用户轻量化意见调整：日常开发和本地自动化使用 Vite 的公开代理能力，不增加 Nginx 服务。现有 `frontend/vite.shared.ts` 已配置 `server.proxy`，三端共用规则；后端不需要为此修改契约路由或额外封装代理。

| 用途 | 入口与行为 | 验证边界 |
| --- | --- | --- |
| 日常开发 | 用户/商户/平台分别使用 5173/5174/5175；API 默认 8888 | 热更新、Hash/History 路由、同源 API 联调 |
| 独立真实联通 | 显式设置 `DEXWALLET_API_PROXY_TARGET` 指向本次测试 API，使用 Q02 专用库 | 不复用日常 API，不连接生产；三端健康请求、错误及恢复逐项验证 |
| 构建产物检查 | build 后用现有 preview 入口 4173–4175；需要真实请求时代理到测试 API | 独立 dist 可加载、后台深链接刷新、开发模块生产隔离 |
| 正式部署验收（8.2） | 已确认的 Nginx 静态站点、同源 API 和 HTTPS | 静态资源 404、缓存、代理超时、真实域名、TLS、滚动发布等另行验收 |

浏览器继续请求相对 `/api`，例如用户端的 `/api/health/live` 经 Vite 转成后端 `/health/live`。代理目标来自服务端配置，数据库凭据不进入前端；无需增加宽泛 CORS。用户端 Hash Router、后台 History Router 和 Telegram 启动上下文规则继续沿用。

使用原生 `server.proxy` 与 `preview.proxy`，后者按 Vite 官方说明默认继承前者。当前仓库已有开发代理和 preview 浏览器入口；现有真实集成配置主要运行用户端 dev，不能声称三端 preview 真实联通已经通过。实施时按锁定版本验证，复用已有能力，不建立自写代理中间件或新增依赖。

本地代理需保持请求方法、查询、请求体和后端 HTTP 状态/JSON/traceId；后端 404/失败不能被 SPA 页面吞掉。代理连接失败按现有客户端规则呈现，恢复后显式重试，不自动重放写请求。准确匹配 `/api` 路径边界，避免把 `/apix` 等页面误当 API；实施时核对已有前缀匹配并用必要用例验证。普通浏览器 fake 测试与真实健康联通继续分开。

构建产物中的开发页面仍不得开放。preview 的页面回退和静态文件行为按工具实际能力记录，不为了模拟 Nginx 建立自定义静态服务器。正式缺失资源 404、入口 HTML/带哈希资源缓存、代理超时及发布切换在 8.2 使用实际部署配置验收。Vite preview 只用于本地构建预览，不能部署为正式服务器；localhost 检查也不替代真实 Telegram HTTPS/实机验证。

依据：[Vite server.proxy](https://vite.dev/config/server-options#server-proxy)、[preview.proxy](https://vite.dev/config/preview-options#preview-proxy)、[本地构建预览用途](https://vite.dev/guide/static-deploy.html)。本轮核对现有配置和官方说明，仅调整方案，未运行新的联通验收。

## Q04：自动化入口

不替换已有生成器、Go 测试、pnpm/Vitest/Playwright 或迁移工具。建议组织以下入口，名称随实施确定，文档只发布已经可执行的命令：

| 层次 | 检查内容 | 依赖与失败行为 |
| --- | --- | --- |
| 准备/预检 | 工具版本、锁文件、依赖安装、浏览器、必要端口与配置 | 缺少工具/变量明确指出；准备过程不启动业务、不迁移数据库 |
| 普通检查 | 文档、契约生成、Go 单测/竞态/vet、前端类型/单测/构建 | 不连接真实 MySQL/Redis/MQ；新鲜环境允许下载锁定依赖 |
| 浏览器检查 | 既有 Chromium/WebKit 用例与开发样例生产隔离 | 仅启动自己的服务，明确浏览器系统依赖 |
| 真实依赖 | 隔离迁移/事务、Redis 往返、MQ topic 消息收发 | 显式提供环境配置；缺依赖失败，不把 skip 算通过 |
| 本地联通与构建预览 | 独立 API、Vite 原生代理、三端 dist/preview、健康请求、History 刷新、停止/恢复 | 使用专属资源，拒绝端口冲突；只管理本次进程，清理结果可查 |

先形成可本地复现的命令，再复用于后续 CI；本轮草案不绑定新的托管 CI、凭据服务或发布平台，不在 CI 中隐式连接开发机中间件。

## Q05：验收条件

1. 在独立干净 checkout 中按锁定版本准备工具与依赖，生成结果无漂移，普通/浏览器检查通过；记录使用的外部服务和缓存来源，不把复用中间件称为从零安装整台机器。
2. 对自己的隔离 MySQL 库完成空库迁移、保留数据的升级、失败状态与重复执行验证。正式业务迁移未建立时明确说明。
3. Redis 使用本次 key 完成读写和清理；MQ 实际收到本次独立 topic 的消息，发送、消费与清理各有证据。Broker TCP 成功不代替收发。
4. 三端构建通过 preview 可访问；两个后台深链接刷新有效，生产产物没有开发检查页面。Nginx 静态资源 404 和缓存规则归 8.2。
5. 三端各自经 Vite 原生代理请求真实健康接口；响应状态/契约/traceId 保持一致，API 不被 HTML 回退吞掉。覆盖开发联通与构建预览所需场景，不把开发工具页重新放入生产包。
6. 只停止本次测试 API，验证错误显现与恢复后显式重试成功；SIGTERM 正常退出，超时工作沿用后端测试边界。不停止共享数据库或 MQ 制造故障。
7. 配置缺失、端口冲突、测试超时和清理失败均给出非零结果及足够诊断；没有遗留本次进程，资源残留如实列明。
8. 完成记录分别列出本地联通/构建预览、远端测试、Telegram 实机和生产开放状态；未执行项不计通过。Q05 建议仅交付可复验的本地开发与隔离测试环境，正式部署验收归 8.2，不要求本地安装 Nginx。
