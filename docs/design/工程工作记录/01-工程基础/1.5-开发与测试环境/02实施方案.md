## 目标与工作边界

把 1.1–1.4 的工程能力收敛为可重复的准备、开发、构建、隔离集成和测试部署流程。能够在干净 checkout 中按记录准备工具、生成契约、运行检查，并通过实际静态服务和代理访问现有 API。

包含：本地运行配置、独立测试数据库、现有 Redis/RocketMQ 的隔离接入、构建与自动化入口、三端构建产物部署及可观察的验收记录。

不包含：新增登录/会话、业务表、账本、资金通道、业务消息消费者、outbox、生产发布与容灾。MQ 收发使用测试消费者，不建立正式 worker；HTTP 继续使用现有健康契约，不为验收新增公开故障或回显接口。

## 现有基础与缺口

| 现有能力 | 1.5 需要补齐的证据 |
| --- | --- |
| Go module、pnpm workspace、锁定生成器和生成检查 | 干净 checkout 的准备顺序、版本检查和统一执行入口 |
| MySQL 随机库迁移/事务测试，Redis key 往返，MQ NameServer/Broker 诊断 | 持久开发库与临时测试库的分工、资源所有权、MQ 真实隔离收发及清理 |
| Vite 代理访问真实 API，健康联通、停服与显式重试恢复 | 三端构建产物通过 Nginx 的真实代理和刷新行为，不能拿 Vite 结果替代 |
| 后端 RestConf、超时/追踪、依赖策略与有序停机 | 测试配置复用新字段，独立部署进程启停、资源回收、故障诊断 |
| Chromium/WebKit 与开发样例隔离测试 | 部署后浏览器验收与构建产物一致，不能将本机浏览器等同于真实 Telegram |

当前只读核对未改变服务：mysql/redis 为 host 网络，RocketMQ 为已有独立 Docker 网络；Compose 子命令不可用。MySQL/Redis 的历史服务版本见 1.3 验证记录，本轮未重新查询服务版本，不能仅凭镜像标签推断运行版本。实施时记录实际版本、镜像标识及网络地址来源，不输出容器环境中的凭据。

## Q01：运行方式

建议保留宿主机 Go/Vite 开发和现有 Docker 中间件。现有开发端口继续为 API 8888、用户端 5173、商户端 5174、管理端 5175。配置默认绑定 127.0.0.1；端口冲突即退出，不查找并杀死占用者。

部署验收使用编译后二进制、三个独立 dist 和项目专用 Nginx 容器，不使用 Vite preview 充当部署服务器。建议测试 API 默认 18889、静态站点 18080–18082，可显式配置；不占用现有前端真实集成入口的 18888。Linux 本机可用 host 网络连接宿主机测试 API，Nginx 各监听显式绑定回环地址。跨主机/非 Linux 部署另设明确 upstream，不将 host 网络写成通用平台保证。

| 拟议位置 | 职责 |
| --- | --- |
| `scripts/` | 少量准备检查、开发进程启停、分层检查、部署验收入口；调用现有命令，不实现通用调度器 |
| `deploy/local/` | 无凭据 Nginx 模板、明确版本/摘要的镜像配置与运行说明所需参数；不包含共享 MySQL/Redis/MQ 的重建定义 |
| `.tools/local/` | 忽略的运行配置、日志、产物和本次资源清单；异常退出后保留必要诊断 |
| `backend/tests/integration/` | 真实 SQL/Redis/MQ 集成用例，继续通过独立标签运行 |
| `frontend/tests/` | 实际静态部署下的浏览器请求、路由刷新和错误恢复检查 |
| `docs/engineering/开发与测试环境.md` | 实施后写入真实可执行的准备、运行、复验和清理命令 |

凭据由现有环境变量提供；无凭据样例描述必填项和作用。工具不扫描用户其他项目配置、不输出 DSN，不为每个用途复制一整套长期配置。开发库准备、测试资源分配、迁移和启动分别显式执行。

## Q02：资源隔离与清理

建议为持久开发和每次测试建立不同资源归属：

| 资源 | 建议策略 | 边界 |
| --- | --- | --- |
| MySQL 开发库 | 专用开发库/账户，按明确准备步骤创建一次 | 日常启动不建库、不迁移、不清空数据 |
| MySQL 集成库 | 沿用 `dexwallet_contract_` 随机库测试机制；其他测试用途独立命名并记录 run ID | 应用账户与建库/迁移测试权限分开；不使用业务库做迁移故障注入 |
| Redis | 通过现有 Namespace/RedisKey 方法生成环境与 run ID 下的 key；加有限 TTL | 不用 FLUSHDB/FLUSHALL，不清理其他运行的 key；DB 编号不能替代命名空间 |
| RocketMQ | 每次创建明确归属的独立 topic 和 consumer group，测试消息携带 run ID 和唯一消息标识 | 不使用默认/业务 topic，不修改 broker 全局配置，不干扰其他订阅者 |
| 进程与端口 | 记录自己启动的进程/容器及监听地址 | 退出只回收本次资源，不用全局 pkill 或停止共享容器 |

MySQL 迁移沿用 golang-migrate。当前用 examples 在隔离库证明空库初始化、旧版升级和失败 dirty 状态；没有业务迁移集时如实报告，不把示例部署到开发业务库凑验收。

MQ 测试优先调用已锁定 Apache SDK 的公开 admin、producer、consumer 能力：显式建立 topic，启动订阅，发送少量无业务含义消息，等待收到匹配标识并返回消费结果。验收要求至少观察到目标消息，不能把重复投递判为“库不可靠”，也不声称 exactly-once 或业务幂等已实现。发送超时保留未知，不通过无界重发掩盖问题。

测试限时退出；停止消费者和生产者后清理本次 topic 等资源。SDK 的公开 admin 已有 CreateTopic/DeleteTopic，消费组、重试/死信元数据的实际清理方式还需核对当前版本支持的公开工具；不提前承诺全部自动删除。清理失败记录资源名、阶段和后续处理方式，结果不能显示为完整通过。强杀残留依照 run ID 清单核对，不按宽泛前缀批量删除。

## Q03：静态服务、代理与测试部署

建议使用 Nginx 的公开配置能力，固定实施时验证过的镜像版本和摘要，不用浮动 latest。三个应用独立静态根目录和 origin；本机先用三个端口，不要求改系统 hosts 或绑定真实域名。

- `/api/` 独立 location 转发到测试 API，并与现有 Vite 行为一致去掉 `/api` 前缀；保留方法、查询参数、请求体、HTTP 状态、JSON 和 X-Trace-Id。
- 商户/平台 HTML 导航使用 `try_files` 回退各自 index.html；静态资源缺失保持 404，API 请求不进入 SPA 回退。用户端继续 Hash Router，启动 URL 查询/hash 不能被代理自行重写。
- 不拦截后端业务错误并改成 200；代理自身的 502/504、连接失败由既有 api-client 分类，不假装来自后端统一 JSON。代理连接/读取预算与后端 5 秒请求、前端 10 秒默认超时配合，具体值实施验证后记录。
- 三端产物不含开发样例和凭据；API 连接由同源代理提供，不向浏览器暴露本机数据库或中间件地址。静态资源的缓存行为随构建产物验证，入口 HTML 避免长缓存阻止更新。
- 本机部署只证明配置和构建产物链路。远端测试主机、域名、证书、访问权限尚未提供；需要外网联调时单列配置与验收。真实 Telegram HTTPS 接入归 2.2–2.4 和 8.3，不拿 localhost HTTP 冒烟替代。

配置依据：[Nginx try_files](https://nginx.org/en/docs/http/ngx_http_core_module.html#try_files) 的文件检查/回退语义，以及 [proxy_pass](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass) 带 URI 时替换匹配路径的语义。本轮已读取官方说明，具体配置尚未运行验证。

## Q04：自动化入口

不替换已有生成器、Go 测试、pnpm/Vitest/Playwright 或迁移工具。建议组织以下入口，名称随实施确定，文档只发布已经可执行的命令：

| 层次 | 检查内容 | 依赖与失败行为 |
| --- | --- | --- |
| 准备/预检 | 工具版本、锁文件、依赖安装、浏览器、必要端口与配置 | 缺少工具/变量明确指出；准备过程不启动业务、不迁移数据库 |
| 普通检查 | 文档、契约生成、Go 单测/竞态/vet、前端类型/单测/构建 | 不连接真实 MySQL/Redis/MQ；新鲜环境允许下载锁定依赖 |
| 浏览器检查 | 既有 Chromium/WebKit 用例与开发样例生产隔离 | 仅启动自己的服务，明确浏览器系统依赖 |
| 真实依赖 | 隔离迁移/事务、Redis 往返、MQ topic 消息收发 | 显式提供环境配置；缺依赖失败，不把 skip 算通过 |
| 部署冒烟 | 编译 API、三端 dist、Nginx、健康请求、History 刷新、停止/恢复 | 使用专属资源，拒绝端口冲突；只管理本次进程，清理结果可查 |

先形成可本地复现的命令，再复用于后续 CI；本轮草案不绑定新的托管 CI、凭据服务或发布平台，不在 CI 中隐式连接开发机中间件。

## Q05：验收条件

1. 在独立干净 checkout 中按锁定版本准备工具与依赖，生成结果无漂移，普通/浏览器检查通过；记录使用的外部服务和缓存来源，不把复用中间件称为从零安装整台机器。
2. 对自己的隔离 MySQL 库完成空库迁移、保留数据的升级、失败状态与重复执行验证。正式业务迁移未建立时明确说明。
3. Redis 使用本次 key 完成读写和清理；MQ 实际收到本次独立 topic 的消息，发送、消费与清理各有证据。Broker TCP 成功不代替收发。
4. 三端静态构建可访问；两个后台深链接刷新有效，缺失静态资源仍 404，API 不被 HTML 回退吞掉。生产产物没有开发检查页面。
5. 三端各自经 Nginx 请求真实健康接口；响应状态/契约/traceId 保持一致。健康请求可由浏览器测试在同源上下文发起，不把开发工具页重新放入生产包。
6. 只停止本次测试 API，验证错误显现与恢复后显式重试成功；SIGTERM 正常退出，超时工作沿用后端测试边界。不停止共享数据库或 MQ 制造故障。
7. 配置缺失、端口冲突、测试超时和清理失败均给出非零结果及足够诊断；没有遗留本次进程，资源残留如实列明。
8. 完成记录分别列出本机部署、远端测试、Telegram 实机和生产开放状态；未执行项不计通过。Q05 需确定本项是否仅交付可复验的本机测试部署，或还包含指定远端环境。
