## 每个工作项的文件

每个工作项目录均已实际创建以下四份文件，可从阶段入口直接进入。

```text

├── 01讨论记录.md
├── 02实施方案.md
├── 03实施记录.md
└── 04验证记录.md
```

| 文件 | 维护内容 | 何时填写 |
| --- | --- | --- |
| 01讨论记录.md | 当前状态、问题、备选方案、确认依据、未决事项和下一步 | 开始讨论并持续更新 |
| 02实施方案.md | 工作边界、数据与接口、实现步骤、验收条件、方案变更 | 讨论中逐步完善，确认后执行 |

## 使用与归档规则

1. 从工作清单选择编号，再进入对应目录，按「讨论 → 确定 → 落地 → 验证」填写。已有确认继续有效，不重复要求确认。
2. 每项当前状态只在 `01讨论记录.md` 维护，使用待讨论、讨论中、已确定、实施中、待验证、已完成、阻塞；阶段索引不复制状态，避免更新遗漏。完成需有对应实施提交与验收证据。
3. 本目录位于 `docs/design/`，单项详细方案及 `/pre` 方案统一写入对应的 `02实施方案.md`；`/pre` 方案确认后再实现。跨项设计在所属设计文档维护并链接，不复制多份。
4. 业务规则仍由产品文档维护，界面设计与全局验收场景保持原有归属。讨论改变规则时同步所属文档和决议台账，本目录记录原因及链接。
5. 需要图示、接口样例或验证报告时，在对应工作项目录按需创建 `attachments/`，并从相关记录链接。代码、契约源定义、自动化测试和迁移放在实际工程目录，此处只引用；不保存凭据和含敏感数据的原始日志。
6. 调整阶段顺序保留工作编号；拆分或合并先修改工作清单，再补目录和索引。旧目录保留历史与新位置链接，不因合并删除确认或验证证据。
7. 文档建立、实现完成、验证通过和生产开放分别记录；不把空模板或文档检查通过视为功能完成。
