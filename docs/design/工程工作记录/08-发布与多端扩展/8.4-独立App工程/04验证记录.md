## 问题与复验

| 问题 | 修正与结果 |
| --- | --- |
| WebView 的 localStorage 在强退后未可靠保留刚写入的登录/连接状态 | App 初始化先恢复原生持久状态，业务使用同步缓存；资金请求标识写入完成后才发 API。TON 协议会话单独保存在原生 Preferences；强退恢复已复验 |
| Preferences 插件使用 `apply()`，调用完成不等于磁盘写入成功 | 产品会话/请求改由小型 `NativeState` 插件以 `commit()` 确认落盘；失败阻止后续 API。协议连接仍用 Preferences，可重新授权连接 |
| 将原生初始化放在共同异步入口，影响 Mini App 启动时序 | 原生构建使用独立 `native-main.tsx`，Mini App 保留静态入口；绑定和路由失败用例复验通过 |
| Keeper 目录公布的 `tonkeeper-tc://` 无法唤起实测安装包 | APK 与官方文档核对后使用 `tonkeeper://ton-connect`；实际打开、批准和自动返回通过 |
| 无窗口软件 GPU 的模拟器进程退出 | 软件 GPU 和 host GPU 均曾发生图形上下文错误退出；host GPU 重启后继续验证。该环境问题仍保留，不视为 App 崩溃，也不视为长期稳定性验收 |

原生提交保证参考 [Android SharedPreferences.Editor.commit](https://developer.android.com/reference/android/content/SharedPreferences.Editor#commit())；钱包与构建依据见 [工程说明](../../../../engineering/Android应用基础.md)。卸载、清除数据、设备存储损坏不在本轮恢复保证内。

## 暂停点与恢复顺序

用户要求本批完成后暂停，本次不启动下一项功能。临时后端与 manifest 隧道在收尾时停止，本次模拟器已因图形错误退出；独立数据库/Redis 资源按测试日志精确清理，保留本地复现材料。

恢复工作先复验 Keeper 断开后的冷启动，再验证 My Wallet 的实际连接、切换、断开和回跳，再推进 5.1 内置钱包与 App 独立 Telegram 授权。相机权限/原生扫码、真实设备/iOS、正式图标/域名/签名/发布、真实通知、链上资产查询、充值/Gas/付款及服务端地址归属证明均未在本批交付。不能把外部钱包显示了主网地址视为主网支付可用。
