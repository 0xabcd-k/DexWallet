当前状态：已完成（3.3 范围），内部资金操作、本人查询及页面已实现，必要验证通过。

## 确认依据

2026-10-30 用户先要求下一步方案，进一步讨论数据库锁等待并要求调研成熟方案，随后明确“好，采纳你的建议”。采用 MySQL 短事务与行锁，参考 TigerBeetle 预留、入账、撤销的业务语义，不引入独立账本数据库或自定义排队机制。

## 已确认范围

- 新增每笔占用的业务关联、金额、状态、初始及结束凭证；占用、核销、释放与余额和账本同事务。
- 首版仅用户美元账户、整笔核销或整笔释放，结束结果互斥。积分不占用；奖励申请仍按原规则扣奖励和拒绝退回。
- 占用在短事务提交后释放数据库锁；审核、链上调用不在持锁事务内。结果未知保留占用，无自动到期释放。
- 提供内部写入和本人只读占用明细，流水区分资金占用与实际扣款。提现、组合支付、商户结算随各自业务接入；商户资金模型尚未建设，本项不虚构商户资金账户。
- 并发不超支、来源防重、终态互斥及全部回滚随本项验证。请求同键异参、原单恢复及业务层有限重试在 3.4 统一完成；公共事务不自动重试。

## 调研依据

- [MySQL 死锁处理](https://dev.mysql.com/doc/refman/8.4/en/innodb-deadlocks-handling.html)：短事务、固定顺序与错误处理。
- [TigerBeetle 两阶段资金处理](https://docs.tigerbeetle.com/coding/two-phase-transfers/)：预留、一次性结束、追加历史；不照搬其可选自动到期释放。
- [Modern Treasury 余额与版本校验](https://docs.moderntreasury.com/ledgers/docs/lock-on-account-balance-or-version)：余额条件与冲突语义。
