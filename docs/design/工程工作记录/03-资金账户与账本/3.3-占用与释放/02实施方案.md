## 数据与账务

新增 account_hold：美元账户、业务类型与单据 ID、正额、held/consumed/released、初始凭证、结束凭证、结束原因及时间。每业务单据一笔占用；需要多分项的业务应使用各自分项单据。当前来源为 withdrawal/payment，仅表示内部来源类别，不表示已开放对应业务。

ledger_entry 新增 balance_part：用户分录为 available/held，系统分录为空。历史用户分录回填 available，不改原金额。普通 Post 仅可改可用余额，占用相关动作保留给内部占用入口。

| 动作 | 借记 | 贷记 | 用户总额 |
| --- | --- | --- | --- |
| Hold | 本人可用 | 本人占用 | 不变 |
| Release | 本人占用 | 本人可用 | 不变 |
| Consume | 本人占用 | 所属业务提供的美元对方分录 | 减少占用金额 |

核销对方分录只能为正额美元贷记，合计恰好等于占用金额，不允许退回本人可用余额冒充核销。平台清算科目不是链上执行证明。核销/释放凭证关联初始凭证；不修改历史分录。

## 事务、并发与错误

三个命令复用调用方 transaction.Runner 的同一 session，错误必须传播并整笔回滚。Hold 使用来源唯一凭证，余额锁按 user_id/kind 固定顺序；结束动作先锁占用记录，再按同一顺序锁资金账户。每次命令处理一笔占用；调用方不得在已持有账户锁后再调用占用命令，涉及多个动作的业务须另行规划整体锁序。

同一来源重复占用返回已占用错误，已结束占用拒绝再次核销或释放，包括同方向重复；查询原记录后由业务层恢复，不把冲突当作成功继续提交其他写入。余额不足、非法参数、占用不存在、已结束与数据库锁竞争有不同错误语义。保留 MySQL 原因供诊断；不改变公共事务的提交结果未知语义。

等待由数据库管理，受数据库锁等待设置及调用方 context 的截止/取消约束；不增加自定义队列、无限重试或独立事务。事务中不调用外部服务。内部入口负责金额及状态不变量，调用业务负责真实单据、最新授权、目标及确定成功/未执行的证据。

余额不为负；每账户 held_balance 等于所有 held 记录金额合计。通过原子写入维护，不在每次操作中全量汇总。缺失美元账户不能凭空占用。

## 查询与界面

.api 先定义本人 account-holds 分页查询，支持状态过滤，返回业务 idx、金额、状态、原因、时间及两阶段凭证 idx；不开放占用写入 HTTP。所有者来自登录身份。

原流水补充余额部分及活动类型。占用/释放只展示可用侧的一条活动，避免把同一金额的内部搬移显示两次；核销展示占用侧实际扣款，对方入账仍按普通收入显示。分录本身完整保留；3.6 再做跨业务账单聚合。

钱包提供占用明细入口；明细支持过滤、分页、刷新和失败重试，退出/切换时取消旧请求。金额保持字符串，所有文案使用国际化资源。

## 生成、迁移与验证

SQL-first 更新完整 DDL/约束与 business/000007，旧迁移不变；更新 .api 后运行生成器，手写 model/logic/page 保持边界。回滚若存在 held 分录或占用历史应明确失败，避免抹掉资金事实；空升级可回退。

验收覆盖：占用/释放/核销的金额与流水；普通 Post 不可绕过占用；非法来源/精度/对方金额；重复占用；并发超支与核销/释放竞争；数据库后写失败、调用方失败的整体回滚；等待期间取消、锁释放后继续；同用户查询及分页隔离；旧数据升级和迁移约束；前端资金语义和会话失效。真实 MySQL/HTTP 使用受限隔离环境，普通检查不连接中间件。

## 释放容量边界

3.3 实施复核补充：可用加占用总额必须小于 10^18，保证全部占用始终能退回可用余额列。否则两个列各自合法的新入账可能使后续释放溢出。沿用原 DECIMAL(36,18) 的字段容量，Go 金额校验与本轮数据库约束共同阻止这类入账，并验证极限金额下拒绝额外入账后仍能完整释放。
