## 关键行为

- 100 美元占用 30 后为可用 70、占用 30；整笔核销后 70/0，释放后 100/0；普通扣款不能动占用部分。
- 8 个相同来源并发仅一笔占用；不同金额重试拒绝。竞争核销/释放只产生一个终态及一张结束凭证；重复结束明确报错。
- 余额不足或非法参数不留账户/占用/凭证；第二条分录失败、终态更新失败、外层业务失败均完整回滚。
- 持有账户锁时真实 MySQL 超时返回 ErrAccountBusy；取消 context 停止等待且无资金残留，锁释放后同一原来源可以成功执行。
- 占用余额、所有 held 记录金额、held 分录净额一致，available 分录净额与可用余额一致，所有凭证按单位平衡。
- 接近 10^18 的账户占用后，新入账若破坏可释放容量会被 Go/SQL 拒绝；原占用仍能完整释放。
- 拒绝本人回流、奖励/积分对方、错误方向和不足额核销；付款来源支持多条美元对方分录，收款用户查询仍为普通入账。
- 6→7 保留旧金额并回填 available，完整 DDL/升级一致；无占用历史可退回 6，有历史时拒绝回退；旧库非零无来源占用会在升级前拒绝，不编造记录。
- HTTP 所有者来自 JWT，userId 和他人游标不越权；状态/分页/idx/时间正确；表故障明确 500，恢复后可查询；禁用或无登录拒绝访问。
- 浏览器金额不转浮点；占用与实际扣款使用不同文案和余额标签，分页失败保留旧数据，过滤/刷新/退出取消旧响应；中英文与移动宽度已验证。

## 发现与修正

- 原迁移检查使用临时表，需要测试账号未持有的权限。改用普通检查表，未扩大账号授权；成功时删除，失败保留诊断与 dirty 状态。
- MySQL ALTER 会将 ASCII 字段约束的文字引入符从 utf8mb4 规范化为 ascii；结构比较规范化这两种等价显示，不忽略实际金额/状态约束。
- 3.1 旧结构测试原先停留在版本 5，与新版完整账户 DDL 比较不再成立。改为先升到当前版本比较，再退回 5 验证原阶段的约束/回滚；没有修改旧迁移。
- 后写入失败的 fixture 最初约束也拒绝已有充值分录，改为仅拒绝占用第二条分录，确保真正验证“写到一半后失败”。
- 退出浏览器测试改为等待退出完成后再导航，保留真实未完成请求，不增加 sleep 或测试重试。
- 既有管理/商户构建大于 500 kB 的块警告保留，构建通过；未扩大为打包优化。
