# 3.5 持久化后台任务 实施方案

[阶段目录](../README.md) · [全部工作记录](../../README.md) · [工作范围清单](../../../../engineering/工程阶段与工作清单.md)

方案状态：已确认并实施，确认依据见 [讨论记录](01讨论记录.md)。实际接口与参数集中维护在 [持久化后台任务](../../../../engineering/持久化后台任务.md)。

## 目标与边界

为资金业务提供事务事件与持久任务基础。内部转账成功写入 transfer.completed 事件；MQ 应答丢失、重复投递、多实例竞争、进程被杀或重启都保留同一业务身份。资金仍由原业务单据及账本事务一次完成，不能拆成消息步骤。

本轮不开放转账 API、页面、真实通知、链上执行或通用补偿框架。处理器只执行传入 session 中的同库 SQL；外部副作用需要所属业务单独定义幂等及结果核实。

## 实现安排

1. 新增 event_outbox 与 background_task 完整 DDL、business 9 增量及有历史时的回滚保护；先改源定义，再生成 model。
2. 转账单据完成后在同一事务追加稳定来源事件。MQ 消息携带 idx，消费者从主库读快照，任务按事件和处理器唯一。
3. 短事务领取事件，提交租约后调用 RocketMQ，确认后记录 published。消费者持久保存全部匹配任务后 ACK，worker 单独执行 SQL 任务。
4. 使用数据库时钟、到期索引、SKIP LOCKED 和递增代次保护并发。只有领取事务用 READ COMMITTED；执行仍锁任务行，结果与 succeeded 同事务提交。
5. 发送失败及明确可重试的 SQL 失败有限退避。dead 保留诊断并允许人工按原身份恢复；blocked 拒绝通用重试；未知提交不立即覆盖或重执。
6. 共享 ServiceContext 显式组装，主入口与模板同步停机排空。正式注册表暂为空，只启动发布角色；测试注册隔离 SQL 处理器。
7. 提供运维查询、原身份重试及操作人/原因记录，不新增公开管理 API。

## 验收条件

| 场景 | 必须观察到的结果 |
| --- | --- |
| 正常转账、同号重放、晚期事件写入失败 | 只有一份事件；事件失败导致单据与账本全部回滚 |
| 发送应答丢失、发送后回写失败、重复接收 | 原事件身份保持；接收去重，成功任务不再执行 |
| 多实例、租约过期、旧实例迟到 | 跳过已锁行，不重复拥有任务；旧代次无法回写 |
| 处理器失败、panic、重试耗尽 | SQL 效果回滚，按语义进入 ready/dead/blocked；人工恢复保留代次与错误 |
| 提交结果未知 | 不用失败状态覆盖可能成功的结果，不立即重试处理器 |
| 进程被强杀与正常停机 | 未提交效果回滚，后续恢复一次；正常停止等待已接收工作结束 |
| 真实 MQ、运维工具和迁移 | 收发链路可达；工具实际查询/重试；完整 DDL 与迁移一致，有历史拒绝降级 |

## 实施调整依据

真实并发测试发现复合 OR 查询锁定过多行，改成按状态分别走索引；默认隔离下范围扫描出现间隙锁死锁，因此仅任务领取改 READ COMMITTED。真实 MQ race 测试发现原 SDK 的订阅数据竞争，固定 Apache 上游修复提交后复验。两项调整均服务当前并发正确性，不改变资金事务隔离与业务范围。
