## 关键行为证据

- 8 个不同来源并发首次入账均成功，仅一个用户/种类账户；8 个相同来源并发只有一个成功，其余明确 ErrAlreadyPosted。
- 同一账户只有 $10 可用时，两笔 $7 并发扣款只有一笔成功；占用余额不补可用缺额；反向互转使用相同账户锁顺序，余额与分录核对相符。
- 真实 MySQL 临时 CHECK 拒绝第二条分录，验证在余额更新及第一条分录已执行之后整笔回滚；外层业务更新后失败同样无账户/凭证/分录残留。
- $2.35 奖励及 9007199254740993 积分分别按单位平衡并精确读回；拒绝跨单位抵销、零/负数、越界、错误精度和未知种类。原凭证关联保留原金额，拒绝以自身为原凭证。
- 新库迁移、5 升 6 与完整 DDL 相符；6 回滚至 5 保留原账户和余额，再升级不虚构历史；外键、来源唯一、目标互斥和金额约束有效。
- HTTP 的所有者取 JWT，附加 userId 无效；同一互转凭证只返回本人一侧，外部游标不能改变归属。数据库表不可用返回 500，恢复后能查询原记录，不用空列表掩盖失败。
- 页面超出 JS 安全整数范围仍保持金额字符串；加载下一页失败保留已有条目，重试不重复追加；筛选或退出取消旧请求，权限消失后不展示原流水。

## 发现与修正

- 首次前端类型检查使用了 goctl 的空请求 body 类型；改为从同一源生成的 AccountEntriesRequestParams 后 common 完整通过，未手改生成产物。
- 首次 HTTP 续签 fixture 把 token 期限设为 49 小时，违反现有固定 72 小时契约；修正为 iat + session.Lifetime 后完整 integration 和最终 race HTTP 均通过，未改变生产鉴权政策。
- 终检补充原凭证自关联拒绝并通过专项真实复验；退出浏览器场景补充实际待完成请求，避免仅验证普通退出却声称覆盖迟到响应。
- 既有管理/商户构建存在大于 500 kB 的块警告，构建通过；没有在本项扩大为前端打包优化。

## 验收结论

3.2 的内部记账、来源唯一约束、按单位平衡、基本并发/回滚保护、本人查询与最小记录页已交付。生产业务需在外层事务落实真实单据、请求同键异参及最新权限校验，并正确传播记账错误；本项没有完成这些尚未接入的业务。
