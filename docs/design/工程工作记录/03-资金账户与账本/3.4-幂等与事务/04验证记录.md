专项覆盖：

- 12 个同键并发请求返回同一业务 ID，仅一张转账凭证及两条分录；10 与 10.00 返回同一结果，金额/收款人变化冲突，发送方之间请求号隔离。
- 不同请求并发扣款不能超支；正反向互转不产生单边记账。
- 余额不足、第二条分录失败、补齐单据凭证失败均整笔回滚，原请求号可重试成功。
- 最新发送方状态/auth_version、收款方状态、本人查单权限；收款人后来禁用不改变已提交单据。
- 注入提交应答丢失：实际已提交则恢复原单；实际未提交且查不到仍返回未知；原事务尚未结束时重提等待，结束后仍只执行一次。
- 死锁边界注入在完整写入后触发真实回滚，再执行一次只保留一笔；普通测试另验证两次上限、锁超时/业务拒绝/清理异常不自动重试、取消停止重试、未知提交与主库读取失败原因保留。
- 真正持有 MySQL 行锁触发 1205，返回繁忙且不重试；context 取消不留下单据或资金变动，释放锁后原号成功。

首次专项测试的两个子场景复用了同一个隔离库标签，被测试运行器正确拒绝；改为独立标签后完整重跑通过，未放宽隔离保护。浏览器与三端真实健康 HTTP 检查本轮未运行：没有修改前端、页面或公开 API 契约。
