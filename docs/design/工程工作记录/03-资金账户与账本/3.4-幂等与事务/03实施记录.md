实施日期：2026-10-30。按 [已确认方案](02实施方案.md) 完成内部入口；验证结果单独记录。

| 交付 | 实际行为 |
| --- | --- |
| transfer_order | 请求身份、双方、精确金额、凭证与时间；发送方/请求号及凭证唯一 |
| transfer.Service.Submit | 最新身份与双方状态检查，同键同参返回原单、异参冲突；新转账完整原子记账 |
| FindByRequest | 本人发送的原单查询；主库读取，未找到不证明旧事务失败 |
| 锁与失败 | 固定用户和账户顺序；余额不足/晚期异常整笔回滚；1213 最多重试一次，1205 返回繁忙 |
| 未知提交 | 按原键恢复已提交单据；未找到或读取失败保留未知，不自动再执行 |
| 生成与组装 | SQL-first 新 model；共享 ServiceContext.Transfers 使用原有 MySQL、Runner 与 Accounts |
| business 8 | 新建单据约束，回滚拒绝删除任何转账历史；只在隔离库执行验证 |

实际调用方式、错误及迁移注意事项见 [幂等与事务](../../../../engineering/幂等与事务.md)。
