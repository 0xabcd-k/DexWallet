## 业务验收

| 范围 | 实际验证 |
| --- | --- |
| 原子互转与幂等 | 同键并发只记一次、异参冲突、失败回滚、提交响应丢失、原请求未提交时查不到仍未知、死锁重试和锁等待取消；凭证平衡与双方余额一致 |
| 限额及日界 | 最后一分日额度 8 个并发请求仅一个成功；换方案保留已用金额、降到已用以下剩余为零；数据库 UTC 23:59:59/00:00:00 的单据与用量归属一致 |
| 旧单与权限 | 降额/冻结后原成功单继续恢复；请求伪造 senderIdx 不改变付款人；新写复核最新 auth_version，第三方查详情与不存在均不可访问 |
| 换绑 | 直接与分步换绑均轮换认证版本并限制付款；过期预览冲突；首次绑定/恢复原身份不新增限制；重复绑定不延长；解绑/绑回不清冻结；已有更长限制不被缩短；预览不泄露其他邮箱的账户归属 |
| 迁移 | 当前绑定回填为实际身份 ID，旧缺失归属明确为 -1；新注册已知空历史为 0；部署默认方案可切换，缺失方案不创建孤立用户；全量 DDL/迁移一致，资金历史回滚保护继续有效 |
| 收款码 | 原始码、准确 Web/Bot 链接解析成功；篡改、跨环境/换密钥、未知类型、多余金额/字段、重复参数、其他域名/Bot/路径拒绝 |
| 后台 | 创建同号同参返回原方案、异参冲突；分配携带原方案和原因，重复分配无重复有效审计；产品/商户 JWT 无管理权限；界面显示前后限额与用量 |
| 前端恢复 | 提交前可读回原请求；网络失联后刷新查回成功且不重发；查无记录保留未知，手动重试保持同号；邮箱/TG 登录回到收款目标不自动扣款；余额不足/冻结禁用确认 |
| 前端变更 | 换绑提醒可取消而不发 mutation；个人码无金额输入；携带固定金额的个人链接拒绝；改变扫码目标后，迟到的旧预览不弹付款框 |

## 问题与复验

- 初次 SQL 集成发现 go-zero 对 time.Time/decimal 聚合值的结构扫描不匹配，改为有明确列别名的结果结构；资金、换绑、日界测试复验通过。
- 全量 DDL 与迁移的索引顺序不同，已对齐；不是忽略迁移差异。
- 登录返回地址原白名单缺少新页面，已补上；非收款 TG 启动参数仍保持原语义。
- WebKit 偶发空白页的 trace 显示 localhost 静态资源被环境代理返回 502；直连本机后完整 88 项通过。另修正新增页面使旧测试选择器含糊的问题。
- 最后复核发现改变收款目标时迟到预览需要失效，已补版本判断和交互禁用，16 项专项浏览器复验通过。

## 开放边界

本轮通过代码和隔离依赖验收。正式使用仍须执行 business 10 迁移、核实历史未知项，并配置独立收款码密钥和真实 Web/Bot 基址；相机权限和实际手机扫码留待设备验收。商户订单、链上资产/Gas/组合付款、App 原生钱包和真实通知继续按所属阶段推进。
