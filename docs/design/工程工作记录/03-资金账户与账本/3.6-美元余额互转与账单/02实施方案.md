# 3.6 美元余额互转与账单 实施方案

[阶段目录](../README.md) · [全部工作记录](../../README.md) · [工作范围清单](../../../../engineering/工程阶段与工作清单.md)

更新：2026-11-13。用户采纳方案复核意见，明确分步换绑判定、组合付款安全终止、报价受理、Gas 失败结算边界及签名责任。付款继续采用有效登录态下核对并确认，无付款密码或每笔验证码。本文为修订后的实施方案，公开资金接口和页面尚未实现；阶段 5/6 的链上参数及逐场景费用仍须落实，不能把方案修订视为真实通道已经验收。历史见 [讨论记录](01讨论记录.md)。

## 最新方案摘要

| 范围 | 最新规则与方案 |
| --- | --- |
| 付款授权 | 有效登录态下核对目标、金额和费用，用户确认后提交；不设独立付款密码或每笔验证码 |
| 个人收款码 | 无固定金额、可重复使用，付款人输入金额；删除个人定额码设计 |
| 商户收款码 | 固定为商户创建订单的金额，从服务器查单，付款人不可修改；归阶段 6 |
| 限额 | 可创建多个方案并分配给不同用户，每个用户默认一个；默认最低 $0.01、单笔 $100、每日 $500 |
| 身份冻结 | 按实际身份变化判定换绑，包括先解绑再绑定同类型不同身份；提交前提醒，成功后限制 24 小时；首次绑定、单纯解绑、恢复原身份不新增限制 |
| 费用 | 中心化流转为 0；链上交易收回平台代付的 Gas，钱包已自行支付的同笔网络费不重复扣取 |
| 签名责任 | 用户钱包出资由用户钱包签名；美元余额链上转出由用户产品确认、平台资金钱包签名 |
| 组合付款 | 余额先占用，链上实收确认后原子结账；每通道须有失效/取消证据、处理责任和退款路径，未落实不开放组合付款 |

本表业务方向来自用户明确要求；24 小时时长及方案管理方式是沿用的设计值，不声称用户逐项指定。登录及身份绑定验证继续采用既有规则，不因简化付款而移除。

## 范围与已有基础

3.6 实现美元余额互转、个人收款码、付款确认、本人账单和必要的限额方案后台入口。App 为完整用户端、Mini App 为精简先行版，两端共用身份、资金账户和限额；钱包/链上操作归阶段 5、商户订单归阶段 6。

[内部转账](../../../../engineering/幂等与事务.md) 已有原子记账、请求幂等及原单恢复；[鉴权](../../../../engineering/用户鉴权.md) 已有 JWT、邮箱验证码及 TG initData 验签。付款直接复用产品会话，资金事务复核最新权限；不新增独立付款凭证或授权会话。

## 付款确认与服务端校验

个人流程：扫码/填 idx → 输入金额 → 核对收款人、金额及费用 → 确认付款 → 查询结果。商户流程使用服务端订单固定金额。首次和后续付款采用同一流程，不先设置付款密码，也不发送付款验证码。

未登录或会话失效时走现有登录验证；成功后返回原业务，重新查询目标、金额、限额及费用，由用户重新确认，不能因扫码、登录返回或打开弹窗自动扣款。目标或金额变化使此前页面确认失效，提交前重新展示当前内容。

服务端只从已验证产品会话取得付款人，不能信任客户端 senderIdx 或 confirmed=true 代表资金授权。输入金额、收款目标、当前账号状态、auth_version、换绑限制、限额及可用余额必须在相应信任边界校验；账户扣增、凭证和事件仍在同一事务提交。前端按钮只是提交入口，不能代替这些保护。

本方案的授权基础是有效产品会话与当前业务权限，付款框确认不是独立身份凭据，不宣称拥有二次身份验证。直接复用原请求号恢复同笔操作，不新增通用付款 token 或免密开关。

用户链上钱包出资（充值、直接转账、商户链上付款及组合付款的链上部分）须在 App 选择钱包、核对费用授权并取得该钱包签名；平台代付仍校验签名内容再提交。美元余额转到链上则由用户在产品内确认目标、金额及费用，平台资金钱包签名出款，不要求用户连接有资产的钱包或提供用户钱包签名。两类来源均不因取消付款密码而改变资金归属与执行权限。

## 个人码与商户订单码

个人码只确定账户/到账类型和版本，不含固定 amount，不建个人定额请求及其创建、期限、撤销管理。展示昵称、idx 和二维码，付款人扫码后填金额；每次付款独立 requestKey，展示/扫描不建资金单。个人码夹带 amount 时提示不支持，不能当定额请求执行。

建议静态格式为 base64url(JSON([1, "account", idx, mac]))，完整 HMAC-SHA256 绑定规范化版本、类型、idx 和环境，独立用途密钥；外层无 padding、最长 512 字符，未知版本/多余字段/超长输入拒绝。更换密钥使旧码失效，账户状态仍由服务端检查。合法码可能被替换为他人的合法码，付款人仍需核对真实 idx/昵称；签名不证明张贴者身份。

商户码定位商户创建的订单 idx，金额、商户、期限和状态从服务器读取。付款人不能用 URL 参数改价；已支付订单展示原结果，不能像个人码一样重复收款。商户订单创建/查询归阶段 6，当前阶段不伪造开单能力。

Mini App 分享使用配置的官方 Bot startapp 入口，H5 继续 Hash Router，App 扫码读取同一目标。严格匹配允许的 origin、路径及 Bot 标识，拒绝重复参数和未知链接，不抓取任意外部网址。登录后恢复目标并重新查询；Mini App 遇链上需求只引导 App。

## 可分配的限额方案

| 默认 USD 互转方案参数 | 初始值 | 口径 |
| --- | --- | --- |
| 最低金额 | 0.01 USD | 正数，最多两位小数 |
| 单笔最高 | 100.00 USD | 含上限 |
| 每日转出最高 | 500.00 USD | 同用户、所有端、所有收款人的成功互转毛额合计 |
| 日界 | UTC 自然日 | 返回 resetAt，界面显示本地重置时间 |

可创建多个具名方案，每个用户分配一个当前方案。现有用户迁移补默认方案，新用户注册写入默认方案 ID；缺失或无效方案报错，不按无限额处理。默认标识由统一部署配置指向已有方案；切换默认只影响之后新用户，既有用户需明确重新分配。

建议方案创建后金额参数不可原地覆盖，要调参则复制新方案并分配目标用户，不增加草稿/审批状态机。校验 0 < min <= perTransferMax <= dailyMax，金额为 USD 两位小数；用户不能自行挑宽松方案，商户管理员不能给用户提额。名称仅展示，对外仍用 idx。

最小后台提供列表/新建方案、查看用户当前方案、给指定用户分配已有方案。展示原/新限额及今日用量，填写原因；分配在用户行锁内检查 expectedPlanIdx 并更新，记录操作者、前后值、时间和原因。先支持单用户明确分配，批量规模及原子性另定，不预建调度系统。

policy 返回实际 planIdx、名称、各限额、今日已用/剩余及 resetAt。用量按用户和日期统计，不按方案分桶：已转出 $400 后改到日限额 $300，剩余为 0；改到 $600，则余 $200。收款、重登、换端、换方案均不重置用量。

仅成功互转计入，失败/回滚/查单不占额，同键恢复不重复计数。新提交在既有双方用户行锁下读取最新方案及日累计，校验后同事务写单记账，不建 Redis 金额计数器。新增 (sender_id, created_at) 索引，日界与写单采用锁后的同一 UTC 时刻，先核实历史时间语义。

转账单记录采用的方案 ID，不受后来分配变化影响；查回成功原单先于新限额检查。此批方案明确覆盖 USD 互转；商户支付、链上出金的金额口径及是否共享日预算随所属阶段定义，不能称本项已覆盖全平台出款总额度。

## 换绑冻结与提醒

换绑按同一产品用户、同一身份类型的实际身份变化判定，不按 Bind/Replace 接口名称判定。本版时长沿用 24 小时，规则如下：

| 操作 | 是否新增付款/转出限制 |
| --- | --- |
| 首次绑定该类型身份、注册 | 否 |
| 单纯解绑，仍保留另一登录身份 | 否；保留该类型最近一次已验证绑定的身份记录 |
| 解绑 A 后重新绑定同一个 A | 否；仍需验证身份及归属，不解除或缩短已有冻结 |
| 当前 A 直接换成 B，或解绑 A 后绑定同类型的 B | 是；两种路径均属于换绑，在 B 绑定成功时开始限制 |
| 取消、失败、重复绑定当前同一身份 | 否；不重新延长已完成操作的限制 |

直接换绑仍要求当前已有两种身份；分步操作的解绑须保留另一身份，再以保留身份进入原账户并验证新身份。分步绑定不同身份在业务上执行同样的换绑限制和 auth_version 轮换，不能通过先解绑规避。解绑后的外部身份直接登录可能创建另一个产品账户，不等于回到原账户绑定，不能合并账户或迁移资金。

身份写事务在用户锁内比较当前/最近绑定身份，原子保存新绑定、最近身份记录、认证版本与 payment_restricted_until。真实换绑设为 max(原限制时刻, 本次成功时间 + 24 小时)；无实际变化不得更新限制。最近身份记录不随解绑清除，也不依赖可能丢失的日志、Redis 或前端记录。当前绑定及可核实历史在迁移时回填；历史缺失先核实，不能把未回填当作首次绑定。

直接换绑及分步绑定不同身份，都须先从服务端取得判定，在提交前明确显示：“更换绑定后，付款/转出将暂停 24 小时，收款和查账不受影响。”用户确认后才提交，取消不变更；提交绑定目标、预期身份版本及确认过的换绑影响，事务复查，目标或身份基线变化时返回冲突并重新展示，不能沿用旧提示。后端强制判定并执行限制，confirmed 不能代替身份验证或绕过限制。返回实际 restrictedUntil，普通资料修改不能改变它。

冻结是暂停平台内新付款/转出，不把全部余额搬进一笔账本 Hold；收款、查账、奖励转入正常，已有单据继续核验，不能撤销已广播交易。3.6 执行余额互转限制；阶段 5/6 平台出金/余额付款复用，避免换入口绕过。平台不能冻结用户外部自托管钱包的自主交易。

换绑限制展示明确原因及到期时间，不清空日用量，切 App、登录身份、再次解绑或绑回原身份均不能解除已有冻结。收款、查账不因最近身份记录的保留而增加门槛。

## 费用口径

中心化互转、奖励转入、纯余额商户付款与余额退款费用为 0；限额方案不附带中心化收费选项。

链上交易收回平台代付 Gas，确认前列出金额、Gas、总支出、净到账及费用资产；代付不等于免费补贴。充值及美元链上转出按对应报价结算扣费；固定订单金额不能被改写成扣费后的金额，链上通道须明确另付费用或净结算规则。钱包自己已支付的同笔网络费不重复收取。

本轮确认成本收回原则，不批准额外服务费/加价或所有失败退款费用。预估与实耗差额、费用资产、上限、预留退回及逐场景最终承担人，仍见 [费用逐项审核](../../../链上资金费用逐项审核.md)；3.6 不硬编码 Gas，也不把链上成本变成中心化手续费。

11 月 13 日确认：通道报价须明确费用资产、预计费用、授权上限、成功及失败时可扣来源。平台已付 Gas 而未收到本金时，不能假定仍可从到账款扣费；须有已授权且可执行的费用结算路径，或明确获批的平台承担额度，否则不开放该代付路径。不能静默扣其他余额或把无法收回成本伪装为用户已付。具体失败/退款承担人及退币数量仍按费用清单逐项审核，不阻塞零手续费的 3.6。

## 链上与组合付款的后续实施边界

阶段 5/6 按 [金额与报价](../../../../product/02业务规则.md#金额与报价) 区分报价受理期限、交易可执行期限和核验转人工时限；有效受理保存原报价，确认慢不重定价，过期新付款不自动补扣。

组合付款只支持一钱包、一网络、一资产：先原子保存唯一有效付款尝试和余额占用，再取得签名、执行链上部分；平台确认实收后，在一个数据库事务中核销余额、分配链上实收、记商户应付款、更新整单结果和待通知事件。同一实收不能再用于充值或其他订单，结账与释放互斥；交易未知不换号重付，链上已到而数据库失败只重试结账。过程及费用分列见 [商户付款与异常处理](../../../../product/03钱包与支付.md#商户开单与收银台)。

开放某条组合通道前必须验证真实失效/取消机制、原交易核验完整性、晚到账退回路径及处理责任。签名过期只表示不能再执行，还需排除它此前已执行；报价倒计时、RPC 查无记录或转人工时限都不是释放证据。条件不完整时该组合方式不可选，纯余额及其他独立通过验收的通道仍可用。这些属于阶段 5/6，不增加 3.6 的链上实现范围。

建议新增 transfer_limit_plan（不可变参数、创建者及请求号）。user 增加当前方案 ID、payment_restricted_until 及按邮箱/TG 类型保存的最近已验证绑定身份 ID；既有身份版本需覆盖解绑后再绑定的冲突检测。transfer_order 增加采用的方案 ID、昵称快照及日统计索引。不新增个人定额请求表，也不保留付款密码安全表、哈希、密码版本或尝试计数字段。

## 提交与恢复

1. 查询目标与当前限额方案，展示实际收款人、金额和费用；受限或不足说明原因，仅打开弹窗不占款。
2. 用户明确确认后，提交前按本人持久化原 requestKey、目标和金额；恢复信息不能可靠保存时不提交，持久化内容不包含登录凭据副本。
3. 认证后先查原号：同键同参已成功返回原单，异参冲突；未找到不证明此前请求未执行。
4. 按既有顺序锁双方用户，复查 actor/auth_version，优先恢复成功原单；新单复查换绑限制、当前方案/用量、目标状态及可用余额。付款人与权限始终以服务端为准。
5. 单据、双边余额、凭证分录及事件同事务提交，失败不留半笔账。请求已接收或前端点击成功不等于资金已提交。
6. 超时/提交未知先查原号，不自动换号重付；确需重提时由用户继续原操作、沿用原号。换绑或降额后的旧成功单仍可查，新付款按当前规则验证。

错误使用具名业务码，区分登录失效、权限不足、换绑受限、限流、金额/日限额、余额不足、原号异参及结果未知。断网不等于未扣款，非参与人查详情与不存在统一 404。日志保留主体/业务 idx 与 traceId，不暴露登录凭据；不保留已删除付款密码功能的错误码。
