## 目标与工作边界

以最少的固定权限接通平台、商户后台登录，管理账户独立于产品用户。交付登录/改密/退出、后台账号管理、产品用户状态管理、操作记录查询和两端页面接入。

依赖已完成的契约生成、数据库事务、idx、统一响应、Redis 和前端基础。企业/商户主体、资金操作、细粒度角色、多级审批、设备会话管理、二次验证及后台自助注册不在本轮；尚无主体的商户账号只能使用本人账户相关功能。

## 设计与实现步骤

### 数据与代码边界

建议新增管理账户和操作记录两张表。管理账户平铺内部 id、后台类型、账户名、密码散列、状态、认证版本、首次改密标志及时间；账户名在同一后台类型内唯一。商户主体绑定待 6.1 的真实模型确定后增加约束，不创建虚拟商户占位。

操作记录保存明确动作、执行者、目标、允许记录的前后状态、原因、结果和 traceId。密码、token 等材料不进入该表；当前仅覆盖已实现的管理动作，后续业务按需增加动作类型。对外账户使用 idx，并新增具名编码类型，不能混用产品用户编码上下文。

先改 SQL DDL 和 business 增量迁移，再运行现有 model 生成；手写查询、事务和缓存扩展留在保护边界。沿用公共 ServiceContext、transaction.Runner、API 错误语义和 Redis 命名规则，不再建立通用鉴权框架或另一套 HTTP 服务。

### 认证与授权

密码验证使用成熟库；按后台类型、账户名和来源限流，失败提示不泄露账号是否存在。第一位平台管理员使用显式本机初始化命令，命令不输出密码散列或长期凭证；业务服务不在启动时自动创建默认账号。

后台 token 与产品 token 的签名配置分开，平台/商户 audience 分开，每次请求核对后台类型、状态和认证版本。复用已有 JWT 和响应头续签所需能力，角色权限从当前管理账户状态判断，客户端传入的账户或商户 ID 不赋予权限。

首次改密状态下仍只有一种 token，后端仅允许当前账户查询、改密和退出，不增加一套临时凭证。改密成功更新认证版本，当前端获得新 token；其他端旧 token 失效。普通鉴权缓存固定 30 秒，禁用/改密等提交后清缓存；Redis 异常返回暂不可用，不穿透数据库。管理写入在事务内复核最新权限，不能靠过期缓存完成操作。

开通/禁用/重置/恢复等接口有明确可重复调用语义；账号唯一约束由数据库保证，重复禁用不能反复推进认证版本。并发禁用平台管理员时保护最后一个可用管理员，具体锁定顺序在实现中统一。成功业务变更与操作记录同事务；写入记录失败不得伪装管理操作成功。

### API 与页面

在现有 `.api` 中分开 `/v1/admin` 和 `/v1/merchant` 路由域：登录、当前账户、改密；普通退出沿用客户端清理。不开放全部退出按钮或公开接口，已有产品用户内部能力保留，后台不为尚无需求的整体退出增加接口。平台额外提供后台账户列表/开通/状态/重置、产品用户查询/状态、操作记录列表/详情。按真实字段生成 Go 和 TypeScript，草案路径不视为已实现 API。

两端复用现有 Ant Design 桌面布局和请求能力，增加登录页、个人账户与改密入口；平台增加管理账号和记录页面。凭证存储、来源恢复、401/503 和迟到响应处理按端隔离，只提取确有重复的实现，不复制产品用户的邮箱/TG 表单或写一个全局三端会话容器。所有可见文案进入国际化资源。

登录后恢复合法站内页面并重新查权限；必须改密时先完成改密。商户主体尚未接通时明确显示待开通，现有资金和业务页面继续按未开放显示。

## 验收条件

1. 显式初始化首个平台管理员；平台可开通其他后台账号，未通过平台注册创建的身份不能登录后台。
2. 正确密码登录，错误密码和不存在账号行为一致且受限流；首次改密前不能调用管理/商户业务接口。
3. 产品 token、平台 token、商户 token 互相不能越权；商户访问平台路由失败，未绑定主体无商户业务权限。
4. token 的 3 天期限、36 小时续签边界、并发响应、普通退出符合 Q04，且无全部退出入口；改密/禁用旧凭证失效，缓存窗口与关键写入实时校验分别验证。
5. 并发禁用不能移除最后一名可用平台管理员；管理状态、认证版本与成功操作记录同事务，失败不留下成功记录。
6. 禁用产品用户后拒绝新登录和业务操作，恢复不重新激活旧 token；既有数据和已受理业务不被删除。
7. 操作记录成功/失败均可追踪，只读查询不泄露凭据；两端直达、刷新、过期、无权限与依赖不可用显示正确状态。
8. 生成漂移、Go race/vet、前端类型/构建及行为测试通过；真实数据库/Redis 独立验证，运行环境凭据不提交。当前 TG 开发环境的数据和配置保持隔离。
