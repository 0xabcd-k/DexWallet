## 已有依据与当前代码

- 2.1–2.4 已接通产品用户登录、身份管理与产品 JWT；平台及商户端仍是页面骨架，没有后台认证接口或管理账户表。
- [业务规则](../../../../product/02业务规则.md) 已明确后台账户与产品用户独立，商户只能访问所属数据。
- [商户与平台](../../../../product/05商户与平台.md) 的本版方案为平台开通商户主操作账户、一个商户一个主账户、单人维护可用且不建设复杂角色配置。
- [后台界面](../../../03商户与平台界面.md) 已描述账户/密码、临时密码修改和按账户要求二次验证，但不是已确认的后台认证实施规则；“登出结束对应会话”也需随本项确定具体语义。
- 工作清单要求逐项“讨论 → 确定 → 落地 → 验证”；用户本轮要求继续下一步，先补齐本项可供统一回答的方案。

已完成的用户端设置平铺、Telegram 端入口限制以及暂停公开全部退出不重新讨论。以下区分本轮已确认内容与待澄清项，不将用户提问记作采纳。

## 当前决议与待澄清项

| 编号 | 选择 | 当前结论及边界 |
| --- | --- | --- |
| Q01 | 后台账号及登录方式 | 已确认：管理端和商户端均使用邮箱定位账户，密码与邮箱验证码必须同时通过，不是两种可选登录方式；验证码通过前不签发登录 token。与产品用户身份及凭证独立；后台登录不自动注册 |
| Q02 | 开通、改密与找回 | 已确认：所有管理端用户由部署在后端服务器的 super 可执行程序手动创建，不只限首个管理员；商户用户由管理端创建，不开放自助注册。个人改密、临时密码首登修改及本机恢复按已采纳方案执行，不能免除密码＋邮箱验证码登录；不把创建管理端用户重新加入网页功能 |
| Q03 | 初始权限 | 已采纳：首版固定“平台管理员”和“商户主账号”两类，不设角色配置器、多级审批或逐按钮授权。平台管理员管理后台账户和已有用户状态；商户只访问本人账户及后续所属商户的数据。不能禁用最后一个可用平台管理员 |
| Q04 | 凭证、退出与缓存 | 已采纳，且用户补充：管理端与商户端各用独立用户表，均独立于产品 user；共性工具可复用，账户数据、缓存 key 和认证域分开。复用单 JWT 的 3 天有效期、剩余不足 36 小时响应头续签，无累计上限、刷新凭证或设备会话表。后台使用独立签名密钥和各端 audience；普通退出清理本端，改密/重置/禁用递增认证版本。按最新缩减范围，本轮不开放全部退出按钮或接口，保留已有产品用户内部能力，不额外开发后台全部退出入口。管理账户普通查询缓存 30 秒，权限相关写入在事务内查最新状态 |
| Q05 | 本轮交付与商户阶段边界 | 已采纳，并以 Q02 的明确开通渠道优先：接通两端登录、当前账户、改密、退出和页面鉴权；平台可创建商户用户，查询/禁用/恢复后台账号、重置密码；并按 idx 查询和禁用/恢复产品用户；管理端用户创建仅由 super 完成。企业/商户主体与绑定在 6.1 补齐，未绑定主体的商户账号只显示待开通，不能访问商户业务 |
| Q06 | 操作记录 | 已采纳：记录登录成功/失败、改密/重置、账号状态和产品用户状态变更的操作者、对象、时间、原因、结果及 traceId；业务变更成功与对应记录同事务，失败另记。提供平台只读查询；不保存密码、验证码或 token，不开放编辑/删除记录，不做全量请求体自动落库 |
| Q07 | 已登录后的敏感操作再验证 | 用户了解含义后已采纳本轮延期。这里指登录成功后，在提现或修改收款信息等敏感操作前，再验证一次身份；不是 Q01 首次登录所用方式。本轮不实施，资金敏感功能接入前再确定触发范围和验证方式 |

Q04 已由本轮“采纳你的建议”明确确认，不再作为待确认事项。Q07 的敏感操作再验证与 Q01 的登录认证组合分别记录，避免把邮箱验证码登录误认为登录后再次验证。
