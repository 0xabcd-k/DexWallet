# 2.5 后台登录与权限基础 实施记录

[阶段目录](../README.md) · [全部工作记录](../../README.md) · [工作范围清单](../../../../engineering/工程阶段与工作清单.md)

2026-10-30 按已确认 Q01–Q07 实施，分支 `feat/backend-auth`。

## 实施内容

- 增加独立 admin_user、merchant_user、后台验证码和操作记录四张表，business 迁移 000003；从 SQL 和 `.api` 生成 model、HTTP 契约及 TypeScript 类型。
- 两端必须同时验证密码与邮箱验证码。bcrypt 散列，12–72 字节密码；验证码 5 分钟、60 秒重发、5 次错误上限，按所属端/邮箱/来源限流。没有自助注册或管理端用户创建 API。
- 复用现有 JWT 库、3 天期限/36 小时响应头续签、30 秒缓存、事务及错误响应。三端签名密钥/audience/idx 类型隔离；管理写入事务内重查权限。临时密码只允许查看本人和改密，普通退出清理本端凭证，全部退出继续关闭。
- `backend/tools/super` 构建独立命令：创建、重置、启用管理员；密码从 stdin 读取，和 API 共用业务用例、配置及依赖，不启动 HTTP 监听。
- 管理端创建商户用户、查看后台账户、启禁用/重置密码、按 idx 查询并启禁用产品用户、分页查看只读操作记录。管理员变更按 id 顺序锁定集合，保护最后一名可用管理员。成功变更与审计同事务。
- 管理/商户端接入登录和设置；账号信息/改密/退出平铺在设置。商户主体及业务权限仍待 6.1。复用 `packages/session` 的并发凭证存储，保留用户端包装入口；桌面后台按页面拆分和延迟加载，移除两份旧概览占位文件。

## 配置与实际开放

运行入口、API、迁移及恢复见 [后台鉴权](../../../../engineering/后台鉴权.md)。没有修改共享开发库、创建实际管理员、配置生产 SMTP 或发布生产服务；集成测试仅使用自动清理的隔离库和 Redis key，邮件使用 fake 验证发送/登录边界。

登录后的敏感操作再验证、商户主体、资金功能和动态角色不在此次范围；原产品用户内部 LogoutAll 能力保留，三端均无公开全部退出入口。
