## 方案阶段生成兼容性探测

日期：2026-10-28。仓库起点 `17ba1b4`，当前分支 `docs/2.1-user-model`。工具为仓库 `.tools/bin/goctl`，通过 `go version -m` 核对为 tools.json 锁定的 v1.10.2；复制现有 go.mod/goctl.yaml 到临时目录，设置独立 GOCTL_HOME、GOCTL_CACHE、模板目录和固定 GOTOOLCHAIN，不读取个人模板。

输入为两个最小表：external_identity 包含 BIGINT 主键、identity_type、VARBINARY(512) subject、DATETIME(6) 及两个复合唯一索引；user_identity_binding 包含用户/身份 ID、identity_type、时间、唯一索引及复合外键。调用 `goctl model mysql ddl --src <临时 schema.sql> --dir <临时 model 目录> --style go_zero --home <临时模板目录>`，仅生成，不连接数据库。

| 探测 | 实际结果 | 结论与限制 |
| --- | --- | --- |
| CREATE TABLE 内声明复合外键 | 退出 1，`schema.sql line 20:1 Unsupported foreign key constraint` | 当前生成器不能直接消费该定义，原方案需要调整输入边界 |
| 去掉内联外键，保留索引与各字段 | 退出 0，输出 Done；生成 external_identity_model_gen.go 与 user_identity_binding_model_gen.go | CREATE TABLE 与 model 生成兼容；外键移入单独完整 DDL 约束文件，不代表去除数据库外键 |
| 生成类型检查 | Subject / IdentityType 为 string，CreatedAt / BoundAt 为 time.Time | 未手改产物；这是输出检查，不是数据库往返或完整业务编译验证 |
| 临时产物及副作用 | 使用 TemporaryDirectory，退出后删除；未改 backend、生成清单或数据库 | 无正式业务实现；不作为 MySQL 约束、事务或登录测试通过依据 |

工具对必填列建议增加 DEFAULT，仅为生成器提示；不为消除提示给身份/用户引用添加虚假默认值。日期默认值、产品用户表及完整三表的生成结果在实际实施后继续验证。

本版调整为完整 DDL 的 tables.sql + constraints.sql，生成器显式只读取 tables.sql；业务迁移必须包含外键，验收比对完整结构。模型方案详见 [实施方案](02实施方案.md)。本轮文档结构、链接及差异检查通过；业务验收仍未执行。
