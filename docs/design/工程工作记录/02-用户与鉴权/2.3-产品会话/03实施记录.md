## 偏差与遗留事项

没有直接开启 goctl --cache：锁定框架 TTL 抖动可能超过 30 秒、Redis 封装与现有客户端 DB/生命周期不匹配，生成 model 的写后失效也不等于当前外层事务提交。手写边界保留固定快照期限与提交后失效，复用 go-redis、encoding/json 和 go-zero SingleFlight，没有自建通用缓存框架。

Redis 故障返回 ErrCacheUnavailable，不无限回源；缓存删除失败只记诊断，已提交业务不伪装失败，以 30 秒快照期限兜底。缺少 Runner context 的带缓存事务写入在 SQL 前拒绝。未来关键写操作继续使用 WithSession/FindForUpdate，不能将普通缓存读作为事务授权依据。

本轮已把用户缓存用于普通鉴权，在 context 中供下游复用，并映射缓存故障为 503。登录与身份操作签发使用事务返回的用户版本；旧 token 的受限恢复仅开放在三个身份变更接口。全部退出事务锁定用户递增版本，不续签。

go-zero 继续生成路由/middleware 并负责 HTTP 生命周期，golang-jwt 负责签名验签。项目仅适配必须的 claims、版本、统一错误与受限恢复；框架默认 Authorize 的差异及配置说明见 [用户鉴权](../../../../engineering/用户鉴权.md)。没有增加设备会话表、刷新接口或 30 天上限。

默认 YAML 保持健康环境可启动，公开登录需显式配置 Auth/Session 和环境密钥。没有真实邮件/TG Bot 凭据，本轮测试使用依赖注入与测试签名；没有前端登录页或 token 持久存储，也没有管理端禁用接口。
