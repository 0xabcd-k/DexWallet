## 待讨论问题

细化 JWT claims、客户端存储、响应头接入及并发续签；验证禁用/解绑/换绑后旧凭证无法恢复。单 token 3 天有效、36 小时续签阈值已确定，不再设计独立刷新凭证、刷新接口或设备会话记录。

## 讨论与确认

允许多设备同时登录，采用有效期 3 天、剩余不足 36 小时响应头续签的单 token；用户已明确取消此前的 30 天强制重新认证上限，不设累计登录时长上限。2026-10-29 调整普通退出语义：仅清理当前客户端凭证与登录状态，不在服务端撤销单次登录，不做设备管理或为此建立设备会话表。已有凭证副本仍受有效期、账户状态及 auth_version 约束。

退出全部设备仍使所有旧凭证失效。解绑或换绑成功后更新用户认证版本、向当前端重发有效期 3 天的凭证，其他端旧凭证失效；失败不改变认证版本。账户禁用后拒绝新登录、使现有凭证失效并阻止用户发起业务操作，保留账户及历史数据。后台继续核验、结算和恢复已受理的资金业务，禁用不取消既有交易或抹除资金责任。

本轮用户进一步指定单 token 有效 3 天，剩余不足一半时通过响应头更新。阈值固定为 36 小时，每次新到期时间为 now + 3 天。过期 token 不能续签，不设独立刷新凭证或刷新接口。普通续签不改变 auth_version，旧 token 在其原期限及版本有效时仍可使用。
