## 目标与交付顺序

以已实现的 Telegram 频道 mock 任务贯通：绑定身份 → 查看本人或受邀任务 → 主动检查并领奖 → 原子结算 → 查看本人结果及账本。外部成员查询继续 mock，身份、资格、奖励和账务使用真实业务逻辑。仍只允许本地开发环境启用 mock；不要求提供真实频道或 Bot 凭据。

4.2–4.5 作为一条业务链路交付，按以下依赖顺序实现和验证：

1. [4.3](../4.3-奖励计算与Pro/02实施方案.md) 纯奖励计算及 Pro 边界。
2. [4.4](../4.4-邀请与助力/02实施方案.md) 任务专属邀请、关系与分成上下文。
3. [4.5](../4.5-奖励事务整合/02实施方案.md) 数据模型、原子结算与幂等恢复。
4. 本项公开接口、必要页面及端到端验收；完整事务可用后才开放领奖按钮。

抽奖归 4.6、奖励转入美元余额归 4.7、完整邀请成果与配置后台归 4.8；通知真实收发仍在 8.2–8.3。当前 $1 首奖进入 reward_usd，不能直接消费或在 Mini App 链上提现。

## 接口草案

下表均为待实现契约。继续以 .api 为唯一 HTTP 源，生成 Go/TS 类型；错误沿用项目 code/message/traceId 和 HTTP 状态语义，失败不夹带成功 data。业务编号使用 idx，金额与积分使用十进制字符串，版本使用 number。

| 接口 | 行为与权限 |
| --- | --- |
| GET /v1/user/tasks/:idx/claim-preview | 本人登录后查询资格、first/returning 阶段、self/help 模式、本人收益预估与 Pro；可带 invitationIdx。返回任务和身份版本；不查询外部成员、不占次数、不生成完成记录 |
| POST /v1/user/tasks/:idx/claim | 主动验证并结算；含 requestKey、mode、可选 invitationIdx、expectedTaskRevision、expectedIdentityRevision、expectedParticipantStage |
| GET /v1/user/task-completions/by-request/:requestKey | 从主库查询当前产品用户的原请求；用于响应丢失恢复，未查到不等于确定失败 |
| GET /v1/user/task-completions | 本人完成记录，按 idx 游标分页，可按 taskIdx 筛选；用于历史查询和本地请求信息丢失后的查找 |
| GET /v1/user/task-completions/:idx | 仅完成者查看自己的结果；当前绑定变化不转移历史归属 |
| GET /v1/user/reward-summary | 本人是否完成首任务、累计 Pro 进度及永久解锁状态；已有账户余额查询继续复用 |
| GET /v1/user/reward-grants/:idx | 仅实际收款人查看自己的奖励来源、金额、进度变化和关联流水；支持从已有账单进入 |

邀请生成接口及链接解析见 4.4。沿用 4.1 的列表、详情和 /check：/check 保持只读，不把老客户端的“检查”改为消耗资格。新界面主按钮明确为“检查并领奖”或“确认助力”。列表/详情的 claimAvailable 只在结算能力已配置且用户符合资格时为真。

后端不接受用户自报的 Telegram ID、关注状态、奖励金额、上级 ID 或 Pro 身份。预览不是领奖凭证，提交必须重查；版本字段用于发现已变化的上下文，不能替代授权和资格校验。

## 页面和恢复

1. 任务详情显示当前绑定、有效期、收益预估和资格。缺少身份先绑定，登录和绑定返回保留任务及邀请参数；返回不自动领奖。
2. 新用户显示 $1 待提现奖励与 1000 Pro 进度，明确不是 1000 可消费积分。老用户本人任务显示当前预估任务积分；助力展示邀请者、本人资格消耗及收益说明。
3. 提交前保存请求键及原参数，按服务地址和产品用户隔离；浏览器多标签使用短时存储协调，网络请求不放在存储锁内。复用现有转账恢复的做法，不扩展为全站请求框架。
4. 邀请页从“首任务”变为“老用户助力”时，拒绝旧上下文并刷新说明，不能自动改为无本人任务奖励的助力；用户重新确认后才发起新请求。身份或任务版本变化同理。
5. 成功结果来自已提交的完成记录及本人奖励记录，显示实际金额、积分和本次 Pro 变化。预览后因其他结算解锁 Pro，金额以本次结算前权益为准；预估不锁定权益。
6. 网络中断或提交结果未知时保留原请求，查询或使用相同参数、相同键重试。查询未找到仍不能直接换键。服务器明确未受理/已回滚的失败，才允许修正条件后发起新请求。
7. 同一资格被不同键完成时返回“资格已使用”；通过本人记录查找已有结果。若该 TG 的原完成属于其他产品用户，不返回原用户、奖励或请求详情。

结果只返回本人的奖励和进度；受邀者可看到邀请者公开资料及助力结果，不获得邀请者余额或上级关系。所有新增界面文案进入现有国际化资源。

## 错误与验收

错误区分缺少绑定、任务未开始/到期/暂停、未关注、验证暂不可用、资格已使用、邀请无效、上下文已变化、请求键冲突、事务繁忙和提交结果未知。业务拒绝不伪装为已完成；验证不可用不伪装为未关注。

验收至少覆盖本人首奖、老用户任务、邀请首奖与助力四条主路径；另外覆盖未登录/未绑定返回原页、旧检查接口无写入、首任务跨页面并发、确认内容变化、失效邀请、响应丢失恢复、多标签、换号隔离及历史权限。外部验证使用确定性 mock，完整事务在隔离 MySQL 验证，页面使用 Chromium/WebKit。详细资金和故障场景见 4.3–4.5。
