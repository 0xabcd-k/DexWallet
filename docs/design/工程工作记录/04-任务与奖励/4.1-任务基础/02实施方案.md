## 目标与工作边界

以「关注 Telegram 频道」具体化任务定义、所需身份、资格和外部验证接口。开发测试先用 mock，不要求真实频道、Bot 凭据或人工关注。4.1 定义基础；4.2 接通列表、详情、主动检查；4.3–4.5 完成奖励结算，不在此提前建立“完成但未发奖”的业务终态。

本轮采用以下已接受的首个任务口径；后续奖励金额计算和真实接入仍按所属阶段落实。业务规则仍以 [任务与奖励](../../../../product/04任务与奖励.md) 为准。

## 设计与实现步骤

### 定义与资格

- 类型使用具名值，采用 `telegram_channel_follow`；配置包含任务说明、奖励基础积分、有效期、频道数值 ID 和用户打开的频道链接。查询 ID 与展示链接分开，频道改名不改变核验对象；DDL、迁移与实际 API 已记录在工程说明中。
- 当前绑定的 Telegram 身份由服务端获取；缺少绑定时提示绑定，不调用验证器、不消耗资格。数值 Telegram ID 不能由客户端任意指定，用户名不作为身份依据。
- 同一任务、同一 Telegram 身份最多成功一次，不因解绑、换绑产品用户或退订再关注重置；已经关注的用户也可主动验证。以上次数和已有成员口径随实施指令确认，不新增跨任务的同频道终身限制。
- 只允许在任务有效期内检查并提交结算。该接口返回当前成员状态，不能据此证明历史加入时间；不默认支持过期补领或要求新关注，当前采用数据库 UTC 的左闭右开有效区间。

### 外部查询与结果

使用一个窄的成员查询边界：输入可信配置中的频道 ID 和已绑定的 Telegram 用户 ID，输出成员信息或明确错误。任务层据此判断条件，mock 与未来官方实现共用这条业务路径，不另建可以任意领奖的 mock 任务类型。

真实接入调用 [getChatMember](https://core.telegram.org/bots/api#getchatmember)。Bot 需为目标频道管理员；仅添加到频道不能作为可靠查询已具备的证据。按 [ChatMember](https://core.telegram.org/bots/api#chatmember) 定义，频道返回 `creator`、`administrator`、`member` 表示当前成员，`left`、`kicked` 表示非成员。`restricted` 官方仅用于超级群，当前频道任务不扩展到群任务，遇到该状态或未知/无效响应按无法核验处理。响应中的用户 ID 必须匹配本次查询身份。

超时、限流、凭据失效、频道无权限、协议异常与未关注分别表达；查询失败不能当成未关注或已完成，不能消耗资格或发奖。服务端保留可诊断错误，公开端不泄露 token。Bot token 由服务端配置持有，不进入客户端或任务展示数据；具体真实配置与联调后续落实。

### mock 边界

mock 以频道 ID、Telegram 用户 ID 和测试场景给出确定结果，覆盖成员、非成员、超时、限流、权限异常及错误响应。未配置的测试输入明确失败，不默认全部通过。单元测试注入 fake；本地联调显式使用隔离测试配置和数据，测试准备负责改变模拟成员状态，不要求打开或关注真实频道。

只替换外部查询，不 mock 绑定归属、任务资格、请求幂等或资金结算。生产不得启用 mock，不向公开 API 提供选择验证结果的参数。mock 通过只证明本地流程，不代表官方 API、频道权限或实际关注已验收。

### 与结算的衔接

用户主动检查时，服务端读取当前身份及绑定版本，在数据库事务外查询成员状态；通过后，由结算事务复核用户状态、会话、绑定版本、任务有效性与剩余资格。外部查询只是当时的成员快照，不承诺用户此后持续关注；后续结算保存实际核验身份及依据，不沿用换绑前的结果。

完成记录、次数消耗和全部奖励效果在 4.5 同事务落地；重复请求返回原结果，未知结果按原请求恢复。已有不撤销任务奖励规则保持，不新增持续监听、关注保留期或退订扣回机制。

## 验收条件

验收目标已同步 [场景追踪](../../../../testing/验收与场景追踪.md#telegram-频道任务的验证边界)。未绑定不执行查询；成员与非成员区分；故障不伪装成业务结果；冒用 ID、身份变化、重复请求及 mock 环境隔离均须覆盖。奖励原子性在 4.5 整合时验证，真实频道权限及 API 联通另行验收。本轮 mock、数据库和页面结果见 [验证记录](04验证记录.md)；奖励事务和真实频道验收尚未执行。
