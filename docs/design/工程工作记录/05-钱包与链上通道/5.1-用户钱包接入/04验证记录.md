## 复现与继续开发

以下命令使用本次已存在的目录。先检查设备与端口，避免同时启动相同 AVD 或占用 5580/5581；这些目录和路径仅是本机实测基线，不是其他开发机的默认安装位置。

### 1. 检查和启动已保留的模拟器

```sh
dex_android_sdk=/home/kelizhang/Android/Sdk
dex_avd_root=/home/kelizhang/.local/state/dexwallet/android-check-5zx_j2hl
dex_adb="$dex_android_sdk/platform-tools/adb"

"$dex_android_sdk/emulator/emulator" -accel-check
"$dex_adb" devices -l
```

在独立终端启动，保留该终端查看输出；无须改用户的 shell 配置，也无须安装桌面环境：

```sh
ANDROID_HOME="$dex_android_sdk" \
ANDROID_SDK_ROOT="$dex_android_sdk" \
ANDROID_AVD_HOME="$dex_avd_root/avd" \
ANDROID_EMULATOR_HOME="$dex_avd_root/runtime" \
"$dex_android_sdk/emulator/emulator" \
  -avd dexwallet_test_api35 \
  -no-window -no-audio -no-boot-anim -no-snapshot \
  -gpu swiftshader -memory 2048 -cores 2 -port 5580
```

另一终端重新定义上述三个 `dex_` 变量，再检查：

```sh
"$dex_adb" -s emulator-5580 get-state
"$dex_adb" -s emulator-5580 shell getprop sys.boot_completed
```

设备为 `device` 且启动属性为 `1` 后再进行操作。首次启动可能较慢；不能只根据 emulator 进程存在判断开机成功。

另建环境时使用新的独立根目录，创建 `avd/` 和 `runtime/` 后，用同样的四个 Android 环境变量调用 `cmdline-tools/latest/bin/avdmanager create avd`，参数为 `--name dexwallet_test_api35 --package 'system-images;android-35;google_apis;x86_64' --device pixel_7 --path "$dex_avd_root/avd/dexwallet_test_api35.avd"`，输入 `no` 接受默认硬件配置。本次创建没有使用 `--force`，启动没有使用 `-wipe-data`。

### 2. 校验、安装与打开钱包

保留的 AVD 已装好钱包。以下安装步骤供新建的干净设备复用，先确认 SHA-256 与上方值一致；换版本需要重新记录来源、校验值和结果。

```sh
sha256sum "$dex_avd_root/Tonkeeper-verified.apk"
"$dex_adb" -s emulator-5580 install "$dex_avd_root/Tonkeeper-verified.apk"
"$dex_adb" -s emulator-5580 shell am start -W \
  -n com.ton_keeper/com.tonapps.tonkeeper.ui.screen.root.RootActivity
```

不要向已有其他签名或版本的钱包强制覆盖安装。无窗口模式下，用 ADB 操作和取证：

```sh
"$dex_adb" -s emulator-5580 shell uiautomator dump /sdcard/Download/dexwallet-ui.xml
"$dex_adb" -s emulator-5580 exec-out cat /sdcard/Download/dexwallet-ui.xml > "$dex_avd_root/current-ui.xml"
"$dex_adb" -s emulator-5580 exec-out screencap -p > "$dex_avd_root/current-screen.png"
```

从当前 XML 中定位目标节点，再通过 `shell input tap X Y` 点击其 bounds 中心。本次欢迎页 Import existing wallet 的中心为 `(540, 2089)`；该坐标只用于解释本次证据，后续应重新读取节点，不能假设所有版本和分辨率都相同。返回可使用 `shell input keyevent KEYCODE_BACK`。

### 3. 本机服务联通与关闭

模拟器使用 `10.0.2.2` 访问宿主机回环服务。本次使用临时 HTTP 端口 34001，结束时已经关闭；后续应换成实际测试服务端口。这里验证的是 TCP/HTTP 到达能力，还没有验证 TON Connect manifest、HTTPS、钱包深链、公共 RPC 或 Telegram 容器。

用毕只关闭本次设备，保留已安装钱包和设备数据：

```sh
"$dex_adb" -s emulator-5580 emu kill
"$dex_adb" devices -l
```

## 问题与复验

| 现象 | 处理与可复用经验 |
| --- | --- |
| PATH 中找不到 adb/emulator，初步误以为没有手机操作环境 | 检查实际 SDK 目录后发现工具和镜像已安装；直接使用绝对路径即可，不能仅凭 `which` 结果认定未安装 |
| 没有 DISPLAY/Wayland | 使用无窗口模式和 SwiftShader，通过 ADB 读取、点击、截图；无需用户打开 Android Studio |
| GitHub API 限流、默认代理的 TLS 握手超时 | 改从官方 release 页面定位固定版本；本次对下载命令单独使用直连，没有修改全局代理或用户配置 |
| 大文件单连接下载中途超时 | 最终用 HTTP Range 分段下载官方同一附件、按顺序合并；安装前验证完整大小及官方 SHA-256。分段是本次下载处理手段，不是项目运行依赖 |

本次钱包 APK 启动成功不代表全部手机操作已经覆盖。PIN 输入、系统权限弹窗、账户创建/恢复、签名确认、安全页面截图限制、深链回跳和后台恢复仍需在对应钱包流程中实测。遇到某个客户端无法自动操作时，再针对具体阻塞请求用户协助。

## 验收结论与开放范围

可以复用本地 Android 模拟器承接真实 Android 钱包的后续兼容验证；本次证据限于已记录的版本和操作。用户已授权 Codex 管理专用测试密钥，该授权不改变生产用户密钥留在客户端的规则。本次没有生成或导入任何密钥。

下列仍为未执行，不能写成支持、通过或生产开放：

- TON 测试网连接、W5 账户检查、实际连接返回的 `SignMessage` 等功能检测。
- 用户签名是否能够返回给我们自己的后端，以及拒绝、过期、账户切换后的行为。
- 平台承担 Gas、广播、交易追踪、转账事件核验、重复提交和账本入账。
- My Wallet 及其他 Android 钱包、iOS、Telegram 实际容器、真机与硬件钱包。
- 主网 TON/USDT 或其他链、币种的正式兼容性；自建测试代币不能替代主网代币验收。

后续从「连接真实钱包并读取能力」开始，满足签名接口条件后再准备测试网资产并验证代付。脚本私钥签名可验证链上机制，不能替代外部钱包接口验证。5.1 正式验收与阶段进度仍以 [讨论记录](01讨论记录.md) 和工作范围清单为准。
