## OKX 的 USDC 支付与确认状态

支付固定为 **0.01 Circle 测试 USDC**，用户 `0xecd14F7586f5053CECae148Ae26309C2277D86A8`，平台 `0xa59C992Aa84657df4EbFF6F04E11a1632f6DB1FA`，chainId 84532，代币 `0x036CbD53842c5426634e7929541eC2318f3dCF7e`。

交易：[Base Sepolia 回执](https://sepolia.basescan.org/tx/0x9a0f39e588938373b479b023b4636ea252c964709c1641916a4f0f02433d8a28)。真实取消返回 4001。原生 Data 面板核对 USDC 域、chainId、合约、付款人、收款人、整数金额 10000、nonce 和有效期后，钱包仅返回签名；后端完成验签和模拟，由平台发送 EIP-3009 调用。

- 用户 USDC 19.98 → 19.97，平台 0.02 → 0.03，用户 ETH 保持 0。
- 平台费用 **547632000347 wei**：L2 执行费 547632000000，L1 数据费 347，operator fee 0；扣款与平台 ETH 变化一致。
- 原字节重发返回 `nonce too low`；已消费授权在原回执区块再次模拟返回 `authorization is used or canceled`。余额仍只移动一次。
- 最初导出时回执区块 `0x3388241` 尚未被 finalized 覆盖，因此保留 **confirmed** 快照；严格的 `base-live-check.mjs` 当时正确拒绝成功导出。18:29 UTC 节点 finalized 已到 `0x3388b15`，覆盖原回执，原有严格检查及授权重用审计通过。全程只查询原 txHash，没有重新签署或支付。

## 测试网络与客户端预检

OKX 的私钥导入表单位于 `#ui-ses-iframe`。顶层页面暂时没有文本不代表界面故障；通过原生 iframe 导入后正常连接 Solana 和 Base。Solana `signTransaction` 请求在钱包内显示主网及余额不足。实际调用 SVM `changeNetwork`，指定 Devnet genesis hash `EtWTRABZaYq6iMfeYKouRu166VU2xqa1`，返回 -32603：`Unable to add this SVM chain as it's not supported by OKX Wallet.` 未使用内部 force 参数或修改钱包校验。见 [响应](attachments/candidate-wallets-2026-11-03/okx-wallet-initial.json)、[签名阻塞截图](attachments/candidate-wallets-2026-11-03/okx-solana-wrong-network.png)。

TRON 三个候选钱包使用同一笔**未签署、未广播的 Nile USDT 请求**做界面对照：owner `TDHZum2JgP2ZgfnveW9f3VM3UjaafdJXio`，收款平台 `TPDBmTxJWYucGk5VjDsSi6jBdvVjpCnCsH`，官方测试合约 `TXYZopYRdj2D9XRtbG411XZZ3kM5VkAeBf`，数量 10000，费用上限 15000000 sun。三个请求的 txID 同为 `21f25e7ec1a9946d05a8324c037092c998caa5ae463656cb87df67d6c2c1b836`，不代表三笔成功付款；过期后必须重新准备和签名。

- **Trust**：provider 注入有延迟，等待后 `window.tronLink`、`window.tronWeb` 才出现。最初导入旧探针账户，随后通过原生 UI 导入并连接上述已备资账户，后者才用于签名检查。切网请求返回 null，但 RPC 仍是钱包主网节点；签名页显示十六进制错误，解码为 `Smart contract is not exist.`，Confirm 禁用。自定义网络页面只列 EVM 网络。见 [结构化记录](attachments/candidate-wallets-2026-11-03/trust-candidate-wallet.json)、[签名页](attachments/candidate-wallets-2026-11-03/trust-usdt-sign.png)、[节点页面](attachments/candidate-wallets-2026-11-03/trust-custom-networks.png)。
- **TokenPocket**：切网方法返回 4200 `Unsupported method`。原生 Data 面板显示固定 transfer calldata；首次费用预览 0.34 TRX，确认后显示 `Insufficient Balance`。在原钱包 Nodes 中添加官方 `https://nile.trongrid.io`，确认链 ID 不同的提示并选择节点；节点页面可读 Nile 区块，但刷新 DApp 后注入 provider 仍报告主网地址，签名预览 1.91 TRX，仍报余额不足。没有通过预充主网 TRX 绕过。见 [记录](attachments/candidate-wallets-2026-11-03/tokenpocket-candidate-wallet.json)、[自定义节点](attachments/candidate-wallets-2026-11-03/tokenpocket-nile-node.png)、[再次阻塞](attachments/candidate-wallets-2026-11-03/tokenpocket-custom-node-blocked.png)。
- **Bitget**：切网返回 4001 和 unsupported method 文案；签名页显示 `Insufficient gas balance`、需要主网 TRX、费用 1.50 TRX，确认入口变成 Top up TRX。原生 Metadata 包含完整未签交易，实际取消返回 `user reject this request`。当前账户的网络面板仅列 Tron，Node settings 无节点；包内存在 Nile 类名不足以证明 UI 可接入。见 [记录](attachments/candidate-wallets-2026-11-03/bitget-candidate-wallet.json)、[Gas 阻塞](attachments/candidate-wallets-2026-11-03/bitget-usdt-blocked.png)、[网络列表](attachments/candidate-wallets-2026-11-03/bitget-network-list.png)。页面 DOM 含隐藏提示，判断依据以截图中实际可见内容为准。

这轮未覆盖三者的移动端，也没有分别完成 TRX 与 USDT 实转。当前能完整证明 TRON 原钱包代付的仍是 [TronLink TRX](11TronLinkTRX资源代付实转验证.md)、[官方 Nile USDT](12TronUSDT实转与Energy来源.md) 与 [同代码测试币完整平台资源实验](18TRON完整资源代付验证.md)。

## Coinbase 与 Phantom 的诊断边界

Coinbase 官方 CRX 不含 manifest key，直接解包加载时 Chromium 用路径派生扩展 ID。原包据 runtime ID 选择环境，界面出现 QA 标记。对照中仅将**已校验 CRX 开发者公钥**写入 manifest 的 `key`，恢复官方 ID `hnfanknocfeofbddgcijnmhnfnkdnaad`；新建隔离 profile，重新经原生 UI 导入，未修改 JS、签名实现或内部存储。QA 标记消失，但连接请求仍未完成，不能将该包标为完全未修改，也不能据此称支持已通过。见 [唯一元数据改动及哈希](attachments/candidate-wallets-2026-11-03/coinbase-identity-adjustment.json)、[对照结果](attachments/candidate-wallets-2026-11-03/coinbase-candidate-wallet.json)、[正常身份首页](attachments/candidate-wallets-2026-11-03/coinbase-correct-id-home.png)。附带采集到 collectibles 404、chain-proxy 400，尚无证据确认它们就是连接挂起的原因。

Phantom 复用原官方 26.36.0 和独立 profile，解锁后连接仍失败；钱包账户、存储等 API 返回 403。没有规避服务访问限制，也没有换成脚本本地签名。见 [响应](attachments/candidate-wallets-2026-11-03/phantom-retry-wallet.json)、[连接失败截图](attachments/candidate-wallets-2026-11-03/phantom-retry-connection.png)。
