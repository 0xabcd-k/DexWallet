# 5.2 链上资产与直接收发 实施方案

[阶段目录](../README.md) · [全部工作记录](../../README.md) · [工作范围清单](../../../../engineering/工程阶段与工作清单.md)

## 2026-11-16 首批：只读资产查询与选择

用户在内置钱包管理交付、提出下一步「5.2 资产查询与选择」后要求继续。本批实现现有产品范围内的只读闭环，不将完整 5.2 的收款码、直接转账、签名、交易记录或广播提前记为完成；汇率和美元估值仍归 5.4，不固定稳定币为 1 美元。

后端维护四链九种主网资产目录：TON/USDT、Base ETH/USDC、Solana SOL/USDC/USDT、TRON TRX/USDT。身份是网络加原生币或完整合约/mint/master，固定精度；不按同名符号合并。测试网目录独立，USDC 用发行方测试地址，USDT 替身须显式配置并标识，不接受覆盖主网资产地址。网络 RPC 由部署配置启用，密钥由环境注入，不向客户端返回；缺配置明确未启用。

公开契约先定义在平台 `.api` 并生成 Go/TS：登录用户取得目录，按一个网络和公开地址查询该网络已支持资产。没有密钥、用户资产所有权绑定、数据库写入、冻结或入账。地址来自 App 内置钱包公开目录或已恢复的 TON 外部连接；只读查询不证明拥有地址，也不能复用为付款授权。

各链适配复用公开 HTTP/RPC 协议及成熟地址解析库：Base 原生余额/ERC20 balanceOf，Solana 原生余额及指定 mint 的全部 Token Accounts，TON 原生余额与指定 master 的 Jetton 钱包，TRON 原生余额/TRC20 balanceOf。响应边界核对地址、资产、精度与数值格式；链可提供的网络标识同步核验。数量全程使用整数/精确十进制字符串；RPC 缺字段、限流、超时、错误或格式异常不能变成零。一个资产查询失败可与同网络其他成功项并列，分别显示状态和查询时间。查询请求有超时、响应体上限和共享用户频率限制；本批不增加自动重试或余额缓存。

App 提供钱包与网络选择、资产列表/详情、名称/符号/标识搜索及本账户的本机收藏；收藏靠前，切换钱包/网络立即清除旧余额并取消旧请求，迟到结果不覆盖新选择。新钱包零余额也显示支持资产；查询失败提供手动刷新。资产详情显示完整标识、精度、网络、地址、数量及更新时间。查看和收藏不是支付授权，付款框仍遵守已确认的不显示持仓规则。Mini App 不打包原生资产页。

## 验证与完成条件

- 目录四链九主网组合准确，测试资产明确隔离，配置不会泄露端点凭据。
- 在真实 HTTP 外部边界 mock 正常、零值、大整数、部分失败、错误网络/资产、超时及坏响应；无钱包私钥输入，不执行写链方法。
- API 验证登录、输入和只读查询；前端验证不同用户隔离、搜索/收藏、切换及迟到结果、零与不可用的区别。
- 真实网络只读验证使用公开测试地址，不领取测试币、不发起交易；记录实际成功与失败，不把 mock 当作真实通道通过。
- 构建、契约生成、相称的 Go/前端检查及 Android App 页面验证通过后，更新实施/验证记录并提交推送。完整 5.2 仍保留后续批次。

该方案是用户授权范围内的工程选择，不新增收费或支付规则；任何实际资金能力仍须按已确认通道规则另行落实。
