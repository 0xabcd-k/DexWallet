# 5.5 本人与代他人充值 实施方案

[阶段目录](../README.md) · [全部工作记录](../../README.md) · [工作范围清单](../../../../engineering/工程阶段与工作清单.md)

## 首批范围

沿用[金额与报价](../../../../product/02业务规则.md#金额与报价)及[本人充值费用审核项](../../../链上资金费用逐项审核.md)。先接通 Solana Devnet 原生 SOL 平台代付路径的用户侧授权：已确认报价 → 唯一订单和付款尝试 → App 内置钱包签名 → 后端受理。订单受益人为本人，用户签名前已持久建单。签名绑定包含订单编号、原 blockhash、付款钱包、收款地址和总支付数量的确切消息。

受理须同时满足用户权限、换绑限制、报价时限、原网络费、交易可执行高度、模拟成功和付款钱包签名有效。重复请求按原报价编号恢复。下一批接入该原消息的平台补签、广播恢复与到账核验，最终按实收和已确认费用规则入账。代他人充值及其他链币分批验证。[接口与配置](../../../../engineering/测试网充值报价.md#solana-devnet-本人-sol-充值签名受理)

## 第二批范围

本人 SOL 的单笔 Devnet 执行由独立进程承担，逐单配置可支付的测试网络费。沿用已受理的消息和受益人，先持久化平台签名再广播，随后按原交易签名核对最终链上实收与实际费用。本人订单提供链上结果。下一批将已核验的实收关联美元账本及充值账单。[运行与状态](../../../../engineering/测试网充值报价.md#solana-devnet-本人-sol-充值执行)

## 第三批范围

已完成 Devnet 本人 SOL 的测试美元入账。按已核验的单笔实收、实际费用及锁定汇率核算，验证通过后把余额和订单凭证写入同一事务。下一批可沿用这条链路接入 Solana Devnet USDC，需单独核对 SPL 转账和收款代币账户的创建成本。[入账规则](../../../../engineering/测试网充值报价.md#本人-sol-充值入账与账单)

## 第四批范围

沿用本人 SOL 的订单和账本，USDC 单独启用测试签名。用户授权转入的 USDC 总量，平台按单批准 SOL 网络费及可退还的 ATA 开户垫资。用最终回执核对两个代币账户及平台 SOL 支出，按锁定的两种汇率结算。

## 第五批范围

扩展到 Solana Devnet 项目测试 USDT。报价签名绑定所选测试币的完整 mint，执行器逐单授权该 mint 和数量。两种开户情况均沿用独立的 SOL 垫资预算，按锁定的代币及 SOL 汇率结算。

## 第六批范围

先接 Base Sepolia 的本人 USDC 充值。用户签名授权限定的金额、收款方和订单，平台模拟后用自己的 ETH 广播。最终区块中的授权及转账事件共同证明资金归属，按原报价汇率和实际费用结算。原生 ETH 需要独立的钱包委托授权，排在下一批。[接口、状态及执行边界](../../../../engineering/测试网充值报价.md#base-sepolia-本人-usdc-充值)

## 第七批范围

在已启用指定智能账户的 Base Sepolia 地址上接通本人原生 ETH 充值。报价固定后只允许平台作为执行者和收款方，按原订单签署限额、时限与单一收款目标。平台取最终交易的授权日志与内部调用轨迹核验实收，再按同一份 ETH/USD 行情结算网络费与净入账。[运行与核验](../../../../engineering/测试网充值报价.md#base-sepolia-本人原生-eth-充值)

## 第八批范围

接通 TRON Nile 本人 TRX 充值。平台提供已有委托带宽，App 内置钱包对原交易和本人的报价归属分别签名。后端持久保存签名后才广播。单笔测试订单要求零燃烧，固化收款后以锁定行情入账。实际燃烧或带宽不符时保留原单核验。[签名约束与执行规则](../../../../engineering/测试网充值报价.md#tron-nile-本人-trx-充值)

## TRON Nile 测试 USDT

使用已验证的测试合约与平台委托的 Energy、带宽执行本人充值。交易和订单分别签名。按锁定的代币行情结算，对燃烧、Energy 来源和预算偏差保留原单核验。[执行与入账规则](../../../../engineering/测试网充值报价.md#tron-nile-本人测试-usdt-充值)
