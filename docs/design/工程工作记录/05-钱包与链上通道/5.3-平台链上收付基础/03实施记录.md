起点 `fa9c0d3`，已同名快进同步 `origin/feat/chain-receive-and-transfer-preparation`；交付分支 `feat/solana-receipt-verification`，提交标识以分支交付提交为准。保留用户已有 `.idea/git_toolbox_prj.xml`，不纳入本批提交，不自动合并主分支。

- `chainassets` 新增只读证据查询，固定网络身份、finalized 交易、历史签名状态；保留 null 以区分未知结果，原资产数量查询仍拒绝 null，不伪装为零。

- 交易记录保存首次原始证据、解析事实指纹及一次网络费；事件按指令位置去重，记录与事件原子提交。提交应答丢失时查询原记录恢复，资金表无写入。
- ServiceContext 复用现有节点客户端；新增内部命令，默认只读，显式 record 才持久化。没有 API/前端契约变更，没有新增依赖或签名服务。
- 真实 Devnet 复查三笔已有交易，公开快照进入普通回归；未使用秘密、领币、签名或广播。

## 偏差与遗留事项

本批未改变收费或产品规则。平台签名/广播、其他链、监听与出款任务仍属后续 5.3；行情/费用依赖归 5.4，充值与订单唯一分配归 5.5/6.5。仅一条转账事件成立不等于平台净实收或某用户订单归属，不能直接加余额。失败 Gas 与开户 rent 不在本批账务范围。

## 2026-11-19 第五批补验：真实快照与恢复

基线 `31b7b0e`，继续同一 `feat/base-internal-eth-receipts` 分支。没有修改业务核验规则、数据库版本、生成契约或默认 HTTP 客户端。补充真实 `base-internal-eth.json` 到已有快照回归，并增加隔离 MySQL 下真实轨迹保存、重复复用及提交应答丢失恢复的行为验收。

## 2026-11-19 第六批：TON 平台发送基础

基线 `7bb4922`，先同步 `origin/feat/base-internal-eth-receipts`，新建 `feat/ton-send-recovery`。用户原有 IDE 配置和未跟踪 UI 设计稿保持原状，不纳入提交。

新增 chainsend DDL、约束和 business 20 up/down，再接入生成器和 model；锁定/更新保留手写扩展。`logic/chainsend` 提供 Prepare/Execute/Find、固定 V4R2 payload、Ed25519 核验、完整消息持久化、广播前标记和未知结果恢复；共享 ServiceContext 仅组装 Store，无发送 worker 或公开调用入口。沿用已有 TON SDK，不新增依赖。

短事务限制不可变付款身份及钱包 seqno，外部签名/广播不持数据库行锁。重启重新验证存储消息，禁止改目标、金额、nonce 或有效期；并发可重播相同消息，接收结果不被迟到错误降级。到期只停止继续发送，仍需核对原付款结果，不自动记成功、退款或释放资金。

新增单元及隔离数据库行为测试，真实签名使用内存临时密钥，广播/提交应答/时间推进使用可控测试替身；不读取历史钱包私钥，也没有新的链上交易。工程说明集中在 [TON 平台出款执行](../../../../engineering/TON平台出款执行.md)，5.3 继续保持进行中。
