- ServiceContext 复用现有节点客户端；新增内部命令，默认只读，显式 record 才持久化。没有 API/前端契约变更，没有新增依赖或签名服务。
- 真实 Devnet 复查三笔已有交易，公开快照进入普通回归；未使用秘密、领币、签名或广播。

## 偏差与遗留事项

本批未改变收费或产品规则。平台签名/广播、其他链、监听与出款任务仍属后续 5.3；行情/费用依赖归 5.4，充值与订单唯一分配归 5.5/6.5。仅一条转账事件成立不等于平台净实收或某用户订单归属，不能直接加余额。失败 Gas 与开户 rent 不在本批账务范围。

## 2026-11-19 第二批：Base 核验

起点 `5973aab`，已同名同步 `origin/feat/solana-receipt-verification`，本批分支 `feat/base-receipt-verification`。用户已有 `.idea/git_toolbox_prj.xml` 与 `docs/design/DexWallet UI 设计任务书.md` 均保留，不纳入提交。

- 先改共享 DDL 与 business 17 up/down，再生成 model：添加事件类型、规范块哈希与三项费用，金额支持 uint256；保留旧 Solana 记录的原始证据、指纹及重复返回语义。没有新 SDK 或新事实表。
- Base 读取固定节点的交易、回执、finalized 头、规范区块及历史 Operator 费；核对交易/块定位与实际 ETH value 或 USDC Transfer，按日志自身位置而非数组位置识别事件。
- 新增 BaseVerifier/BaseService，复用原短事务、锁定、冲突和提交恢复；共享 ServiceContext 组装。工具按网络区分 Solana 指令与 Base 日志，默认只读，写库均要求 business 17。
- 普通 ETH 与 USDC 代付历史交易只读复查通过，智能账户内部 ETH 交易明确返回不支持。公开快照保留到普通离线回归；没有真实付款、用户余额修改或新 API/前端页面。

运行入口和兼容边界见 [Base 到账核验](../../../../engineering/Base到账核验.md)。后续继续 TON/TRON、内部 ETH 执行证据、签名广播及订单唯一分配；本批不将其中任何项声明为已开放。
