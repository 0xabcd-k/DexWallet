# 5.3 平台链上收付基础 实施方案

[阶段目录](../README.md) · [全部工作记录](../../README.md) · [工作范围清单](../../../../engineering/工程阶段与工作清单.md)

2026-11-16 首批实施选择，依据用户“继续”及既有 5.3 范围；不解释为费用清单已全部批准。

## 目标与边界

内部核验入口接收网络、固定资产 ID、交易签名、顶层指令位置、预期收款 owner、最小单位整数数量。网络由服务端 RPC 配置和 genesis hash 确认，交易与历史签名状态均须 finalized、slot 一致、执行成功。查不到、仅 confirmed、响应缺项、上游错误均不得认定失败已退款或已到账。

SOL 检查 System Program 的 transfer；SPL 检查原版 Token Program 的 transferChecked、mint/decimals/整数数量与交易时的 token account owner。原始交易账户索引用于还原 token account，不用今天的账户状态替代交易时状态。只核验顶层指令，拒绝 CPI 和未经覆盖的形态；self transfer 不作为到账。

## 持久化与工程入口

- SQL-first 新增 business 16：交易证据按网络/签名唯一，转账事件按交易/顶层指令位置唯一。网络费只放交易记录，不能逐事件累加。
- 原始成功交易和状态证据首见保存；重查只比对已确认的业务事实，不因 RPC JSON 字段顺序或观测时间变化覆盖证据。并发相同请求返回原记录，已有事实冲突显式报错；提交结果不明时用原事件身份查询恢复，不构造新事件。
- RPC 调用在数据库事务之外；同库交易/事件记录原子提交，不写任何用户账户、凭证、订单或 outbox。先改 DDL/迁移与生成入口，再生成 model，扩展查询和事务保持手写。
- 复用既有 chainassets 节点配置、HTTP 客户端与固定资产目录，新增只读 Solana 证据方法。业务核验与记录位于 chainreceipt，由 ServiceContext 组装。
- 无新公开 HTTP API，无 UI 变更。运维工具默认仅查证，显式 record 才写专用事实表；输入不携带用户授权或付款结果，不能直接入账。

## 验收

覆盖 SOL/SPL、精确大整数、错误网络/签名/目标/mint/程序/精度/owner、索引冒用、未最终确认与失败交易、部分或缺失响应；同 tx 不同指令与同指令并发重复、事实冲突及提交不明恢复。用隔离 MySQL 验证迁移/完整 DDL 一致与资金表不变；真实节点只读复查既有三资产交易，历史不可用时如实记未知，不重做资金交易。

公开证据保留在本项验证记录；私密配置不入库。

## 2026-11-19 第二批：Base 普通 ETH 与 USDC

沿用用户“继续”的工程授权，本批接入 Base 主网/ Sepolia 固定目录，先完成普通外层 ETH value 转账及发行方 USDC Transfer 日志核验；智能账户内部 ETH、跨链存入和失败费用回收不在本批开放范围。保持仅链上事实、不签名广播、不判定订单归属或美元入账。

- 独立读取 chain ID、交易、回执、finalized 高度及付款高度的规范区块，核对哈希、交易位置、成功状态；不能用确认次数或外层执行成功代替实际资产事件。
- ETH 只接受空 calldata 的正 value 外层转账。USDC 根据完整合约地址、Transfer topic、日志自身 logIndex、源/目标与 uint256 精确数量核对；不把日志数组位置或交易发送人当成转账位置/资金来源。
- 事件增加类型以区分 Solana 指令、EVM 外层 value 和 EVM 日志；仍按网络/交易/事件类型/位置唯一。SQL-first business 17 扩展原事实表，金额允许 uint256 的十进制长度，保留 Solana 历史记录及重复恢复语义。
- Base 网络费单列 L2 执行费、L1 数据费、Operator 费并求和；后者读取该交易所在规范区块的 GasPriceOracle，缺证据时不默认零。此为观察费用，不批准新的用户收费规则。
- 新增内部 Base 核验入口和显式命令；共享既有持久化逻辑、SQL 事务与 RPC 客户端，不引入新 SDK 或通用链框架。原始证据首次保存、冲突拒绝、提交不明查询恢复保持。
- 验收覆盖错误网络/区块/日志/资产/数量、失败/未知、各项费用缺失和大整数、同交易不同事件及并发去重、旧版本迁移与禁止丢失 Base 证据的回退。真实节点只读复查已有 USDC 代付与 ETH 普通转账；原智能账户 ETH 付款须明确拒绝，不冒充已支持。

## 2026-11-19 第三批：TRON TRX 与 USDT

沿用用户“继续”的工程授权，本批接入 TRON 主网/Nile 固定目录，核验单一顶层 TransferContract 的 TRX 及成功 TriggerSmartContract 回执中的白名单 TRC-20 Transfer 日志。只记录链上事实，不签名广播、不分配充值订单或入账；内部 TRX、TRC-10 和未知交易形态不开放。

- 固定主网/Nile 创世块 ID，全部资金证据读取 walletsolidity：交易、回执、最新固化头及付款区块。核对交易 ID、raw_data_hex SHA-256、块高度/时间与成员关系；空对象是未知，不能据此退款或再发。
- TRX 核对 owner、to、正 int64 sun；代币按完整合约、Transfer topic、严格地址/uint256 编码与预期目标/数量核对。TRON 日志没有 EVM logIndex，以原始回执 log 数组索引定位，不过滤后重排。
- 新事件类型为 tron_transfer/tron_log，复用 business 17 事实表、原始证据、指纹、事务锁、冲突和提交未知恢复。兼容 Solana/Base，没有新增 API、依赖或生成契约。
- feeAtoms 为该笔交易燃烧的 TRX（sun），资源消耗与细分费用保留在原始回执并参与指纹。proto3 省略的合法零值按协议处理，显式 null/负数/非整数拒绝；零燃烧不推定平台代付，不从当前资源余额反推历史提供者。
- 用已有 Nile TRX、官方水龙头 USDT 和自建资源对照币历史交易作只读复查。测试资产需分别配置完整合约 ID，不将对照币声明为发行方正式 USDT。验收包含错误网络、块、状态、资产、日志位置、大小整数、资源费用与并发/提交恢复。

## 2026-11-19 第四批：TON 与 USDT（Jetton）

沿用用户“继续”的授权，以收款账户的交易哈希定位唯一入站消息，接通 TON 普通转账和固定 master 的 Jetton 收款事实。只读核验、事实存储及提交恢复纳入本批；签名广播、完整 trace 成本结算、订单分配与入账保持后续实施。

- 固定主网/测试网 zero-state，使用已配置 TON Center V2/V3 节点；要求 finalized、非模拟、收款分片块已锚定主链，核对区块身份、LT 范围与主链高度。
- 将发送交易的 out message 与收款交易的 in message 按哈希、地址、数量和 body 关联，不能只看发送成功。TON 只接受空 body 或普通文本备注、无额外货币和转出；成功收款和 non-bounce、no-state/no-gas 跳过计算但确有 credit 的收款分别验证，VM 失败或 bounce 不确认。
- Jetton 核验成功的收款代币钱包 internal_transfer；由白名单 master 的 get_wallet_address 对目标 owner 派生地址，验证发送钱包 transfer 与接收 internal_transfer 的数量、query_id、owner 和目标。使用已有 tonutils-go 解析 BoC，不信任 JSON decoded 或通知文本。当前 get-method 仅证明当前 master 映射，不能伪称历史状态证明；映射变化拒绝，不自动重新归属。
- 每笔 TON 收款交易只有一个入站事件，类型 ton_incoming/ton_jetton、位置 0。共享事实表地址列扩到 68 字节，SQL-first business 18 保留已有三链记录并保护回退；无需新的事实表或 SDK。
- feeAtoms 仅为该收款交易 total_fees 加它自己发出消息的剩余 fwd_fee，扣费账户是该收款账户；完整消息链路费用及资源余款不能据此推定。原始消息/状态/费用进入证据和指纹，当前主链头前进不改变事实身份。
- 使用已有 0.01 TON、1 枚测试 USDT 和 no-state 备资收款的历史交易复查。保留真实快照、失败/假币/消息篡改/未固化反例、并发去重、迁移及提交恢复记录。公共无 key 节点曾实测 429，同次证据请求适当间隔，不隐式重试资金动作。
