# 用户端界面

本页给出可直接用于原型的界面规格。页面编号 U01–U17 是设计追踪标识，不是接口路由或数据库枚举。金额和资格按 [业务规则](../product/02业务规则.md) 及 [奖励流程](../product/04任务与奖励.md)，界面不重复定义可变参数。

## U01 钱包首页

2026-10-31 确认：顶部主要操作为「任务／收款／付款」，三入口下方展示美元余额卡。任务进入任务列表，收款进入 U04，付款直接进入 U05 扫码；余额卡进入 U02。设置入口保留，底部「钱包／奖励／记录」导航不因本次顶区调整而改名。

进行中提示链接具体 U10，链上钱包区可切换当前查看的钱包，资产行进入 U03，全部记录进入 U16。查看钱包与后续付款选择钱包是不同操作，不能因浏览过某个钱包就替用户授权付款。

美元余额与链上区域分开，不合并四类资产总额。无钱包时提供创建、导入和连接；一个区域加载失败不阻止其他区域查看。此处为已确认设计，当前实现进度仍以项目入口和阶段验收为准。

## U02 美元余额详情

从首页余额卡进入，上下两块布局：上方展示美元可用余额、处理中金额及一个主要「充值」按钮；下方展示本人美元账单，可进入具体 U10。冻结不等于最终扣款，拒绝恢复关联原单，账单筛选继承美元账户范围。

点击充值直接打开 U06 的统一付款框，受益账户固定为当前用户，使用项目已开放的链上资产给本人美元余额充值，按 U07 执行；不提供用同一个美元余额给自己充值的选项。按 U06 已确认的两步付款流程，付款框先展示汇率和本次需付数量，再选择付款钱包；最终支付仍须校验实际钱包余额和费用。

美元余额转出到链上的入口通过「付款 → 手动填写 → 转账到链上」承接，付款框选择美元余额后按 U08 执行。美元余额没有助记词备份功能；未开放通道明确说明原因，历史账单仍可查。

## U03 链上资产详情

绑定一个钱包、网络和资产，展示币量、参考美元估值、地址、数据更新时间、收发记录与独立网络费。资产信息可展开完整代币标识。

收款进入 U04 并预选资产；转账进入 U06；充值美元余额进入 U07 并预选来源。切换钱包刷新余额，不能用同名跨链余额凑数。零余额仍可收款，查询失败不显示成零。

## U04 收款

二维码在上，Tab 在二维码下方；默认选中「收款到余额」，另一个为「收款到链」。收款到余额展示本人昵称、idx 与账户码，支持付款人用余额互转或已开放链上资产代充值。

切到收款到链后，选择链、币及接收资产的钱包，取得明确地址后生成对应二维码；没有可用收款钱包时先引导创建、导入或连接，不展示占位地址。这里选择的是收款钱包，付款人的钱包由付款人稍后在付款抽屉选择。

普通码只确定收款目标，不要求预设金额；付款人扫码后在付款框补充金额。带金额的收款请求自动填入金额，并由请求约束决定是否允许修改；金额模式与币种随请求保留，不能在扫码后静默换目标。

提供复制、保存、分享、查看收款记录。分享卡片含到账类型，链上卡片同时含网络、资产和地址。拒绝保存权限时保留复制与分享。切换 Tab、链、币或收款钱包后更新码；展示二维码本身不产生收入。

## U05 扫码与收款对象

点击首页付款直接打开扫码页，识别成功后进入 U06 的统一付款框，展示已解析目标、金额及可用支付资产。相机权限失败保留相册、粘贴和手动入口；未知码说明原因并提供重扫，不自动执行不明合约或跳任意网址。

扫码页底部提供「手动填写」按钮，点击进入选择页面：默认 Tab 为「转账到余额」，填写收款人 idx 和美元金额；另一个 Tab 为「转账到链上」，填写链、币、地址和币数量，旁边显示美元估值。两种表单完成后都打开同一个付款框。

扫码、相册、粘贴、手动输入及外部链接共用目标解析规则。昵称仅用于辨认，账户按唯一 idx 查找；裸地址缺网络时补选，多个有效码先选一个。订单码按 U09 的订单约束进入付款，已付款订单直接 U10；统一付款框不抹平个人转账与商户订单的规则差异。

## U06 转账

扫码和手动填写汇入同一个付款框。2026-10-31 已确认：首页与入口按 U01–U05 组织，付款框取消持仓余额展示，支付资产展示汇率和本次需付数量，链上来源采用下述两步付款流程。交互已确认，尚未实现。Tab 决定最终到账位置，付款资产决定资金来源：

| 到账目标 | 支付资产 | 业务路径 |
| --- | --- | --- |
| 用户美元余额 | 美元余额 | 内部余额互转 |
| 用户美元余额 | 已开放链上资产 | 本人或代他人充值，按 U07 |
| 链上地址 | 美元余额 | 美元余额出金，按 U08 |
| 链上地址 | 同链同币的链上资产 | 用户钱包直接转账，当前不扩展跨链或跨币兑换 |

付款框有可信用户资料时显示头像、昵称和 idx；即使没有用户资料，也必须显示收款地址或 idx，链上目标同时显示链和币。扫码带入的昵称不能替代可信查找。目标为美元余额时金额以美元表达；链上目标默认填写币数量并展示美元估值。切换支付资产保持收款目标及应收金额不变，重新计算实际支付币量和费用。

支付资产包含美元余额及适用于当前路径的链上资产；链上资产优先展示常用、收藏，提供搜索。资产按链和真实币标识区分，同名跨链资产不能混用。当前路径不支持的资产置灰并说明原因，搜索不能绕过支持范围。本人充值只展示可用于充值的链上资产。

付款框不展示用户持仓余额、持有币量或持仓美元估值。链上支付选项只展示当前换算汇率和本次需要支付的资产数量，美元余额支付显示本次需付美元。收款目标、应收金额及费用仍保留在付款摘要。参考估值与有效报价区分；依赖所选钱包的费用先标记待确认，对应金额标为「预计支付」，选定钱包后展示最终扣款再确认。

这取代前一轮在付款框展示「币单价／可用币量／持仓美元估值」的方案。首页资产详情等持仓页面的余额展示不在本次调整范围。

**已确认的钱包选择能力：** 内置钱包在抽屉排最前，后面列出项目支持连接的外部钱包，提供钱包搜索框。候选需支持当前网络、资产及签名方式；选择或连接钱包不代表授权转账，纯美元余额付款无需选择用户的链上付款钱包，即使到账目标是链上地址也按平台出金流程执行。

**已确认的两步付款流程：先选支付资产，再选钱包。** 付款框以汇率和本次需付数量表达资产支付信息，首屏不预设付款钱包。确认依据见 [决议台账](../decisions/决议与待落实事项.md#2026-10-31-收付款入口统一付款框与本人充值)。

第一步在付款框确认目标、金额、支付资产和当前报价；链上来源的按钮使用「选择付款钱包」，点击只打开钱包抽屉，不提交付款。目标和金额有效、资产受支持、当前报价可用时允许进入这一步；尚未选钱包或待确认的钱包相关费用不阻止进入钱包选择。

第二步在抽屉选择内置或支持的外部钱包，外部钱包完成连接后，按实际账户校验网络、资产数量、网络费及报价。界面可用简短文字提示「余额不足」「网络费不足」「需要连接」或「不支持当前网络」，不强制铺开持仓数字；最终「确认付款」仅在所有支付条件满足时可用，再进入相应签名/授权。查询失败不能等同于零余额，不能跨钱包、跨链凑款。

如果所选钱包改变了费用或总扣款，先展示更新后的支付数量与费用，再由用户最终确认。关闭钱包抽屉返回原付款框，保留目标和金额。第一步确认与最终授权在文案和行为上明确区分；对外支付未知仍通过原业务查询恢复。

纯美元余额来源直接复核平台可用余额和业务条件，满足后确认，无需用户链上钱包抽屉。隐藏余额数字只调整信息展示，不移除提交前的资金、费用和并发保护。

费用摘要按资金路径呈现：中心化账户之间互转显示「手续费 0」，扣款与到账等额；美元余额转出到链上仍显示该链上通道的费用。手续费边界以 [业务规则](../product/02业务规则.md#手续费边界) 为准。

个人转账一次选择一种支付资产，不扩展个人组合转账；商户组合付款沿用 U09。不能自转同一美元账户，本人链上充值不属于自转余额。关闭付款框或钱包抽屉保留未提交目标与金额，不能凭关闭界面撤销已提交业务；提交后进入 U10，结果未知不出现「再转一次」。

## U07 充值美元余额

本人充值入口为「首页余额卡 → 美元余额详情 → 充值」，直接打开统一付款框，受益人固定为本人；代充值由对方账户码或 idx 进入，同样复用付款框并持续显示受益人。

付款框先选择项目已开放的链上支付资产并填写充值金额，展示支付币量、汇率、费用、净到账美元及报价有效期。按美元余额目标默认填写美元金额；通道允许的币量输入模式沿用产品金额规则，切换后重新报价。本人充值不提供美元余额作为资金来源。

复用 U06 已确认的两步付款流程：内置钱包排前，支持连接的外部钱包随后，可搜索。付款框先确认金额、资产与汇率/需付数量，点击「选择付款钱包」进入钱包抽屉；选定或连接钱包后复核报价、账户和支付条件，展示最终扣款，再按具体充值通道建立原单、授权和核验。结果进入 U10，钱包选择或签名成功均不表示美元已到账。更换付款钱包不能改变受益账户。

平台代付费用从金额扣除，未验证的通道不能静默改为用户另付；具体钱包能否完成代付签名按通道能力验证。手动外部转入只在已验证通道开放，不以普通地址复制替代充值流程。

## U08 转出到链上钱包

展示美元可用金额、目标地址与网络资产、美元扣款、网络费、到账币量以及审核说明。可选本人钱包地址或填写他人地址，不能将他人地址自动标为本人钱包。

提交后进入审核或出款进度；待重报价在 U10 对照新旧到账量确认。拒绝展示恢复金额；未知执行只查询，不再次申请相同出款。提交后地址修改须按原业务安全终止规则处理。

## U09 商户收银台

首屏显示商户、商品、订单金额、有效期与付款组成。美元余额默认优先，可关闭或修改；剩余部分选择一个链上钱包与资产。费用总额在确认前可见，明细在抽屉中展开。

纯余额付款显示「手续费 0」，用户按订单金额扣款、商户等额入账；组合付款的余额部分不收费，只展示链上部分对应费用。商户后续结算费用不计入本次纯余额付款。

主操作「确认付款」；未提交可返回，不替商户取消订单。余额足够可纯余额支付，关闭余额可纯链上支付。报价、账户或组成变化要求重新确认；新付款不可用时解释原因，既有付款继续 U10。

示例 $10 订单：$3 余额加 $7 对应 TON 网络 USDT，网络费用另列；实际币量按报价。组合先预留余额，再授权链上部分，两部分状态持续可见。

## U10 业务详情与进度

展示业务金额与单位、状态、来源目标、费用、报价版本、时间线和适用链上凭据；按业务只显示相关字段。支付、充值、出金、奖励转入、退款和结算复用结构，具体状态不同。

| 当前状态 | 界面动作 |
| --- | --- |
| 等待授权 | 返回钱包继续或安全退出当前授权 |
| 审核中、确认中 | 查询状态、查看详情、离开；显示最近核验时间 |
| 待重报价 | 新旧结果对比，确认继续；安全条件满足时可终止 |
| 已完成 | 查看账单、复制凭据、返回可信来源 |
| 确定失败 | 说明真实费用和资金恢复，条件满足时重新发起 |
| 待处理 | 查看已收或已退分项、提交说明、查看处理进度 |

组合退款显示「部分已退，其余处理中」，不能隐藏某一分项。申请帮助自动携带业务编号，不要求用户反复输入；已有申请直接展示状态。无链上交易时不展示区块浏览器按钮。

## U11 奖励首页

顶部独立展示待提现奖励、可消费积分和 Pro 进度。主要提示按状态优先引导首任务、检查领奖、积分抽奖或奖励转入，但任务列表与其他可用入口稳定保留。

任务卡片显示本次适用奖励、资格和主按钮；完成首任务后开放次操作「邀请好友完成」。Pro 面板解释来源、永久权益和翻倍生效时点，无购买或领取按钮。

首次结果展示「$1 已进入待提现奖励，Pro 增加 1000」，不写成获得 1000 积分。达到 Pro 与奖励达到 $2 分开显示。

首奖仍在首次任务完成后入账，不在注册或登录时预先显示已入账。内部关于预期任务奖励前置的解释不加入用户文案，继续如实展示首奖及转入条件。

## U12 任务详情与受邀助力

展示任务步骤、有效期、资格、本次奖励和当前状态。主流程为去完成、返回检查并领奖、查看结果；返回保留原邀请上下文，不自动验证为成功。

按任务显示所需外部身份及当前绑定状态；缺少时提供「绑定 Telegram」等明确入口，保留任务和邀请上下文，绑定返回后重新查询资格。次数展示对应外部身份，首奖与奖励余额展示对应产品用户；换绑不宣传为重置次数或重新获得首奖。未依赖外部身份的任务不显示无关绑定门槛。

受邀页补充邀请者和双方收益。老用户开始前醒目说明本人无奖励且占用参与资格，提交时再次确认；新用户说明首奖及完成后建立关系。本人打开自己的链接返回任务页。

已领奖显示原结果与记录；校验未满足显示具体缺项，超时先查原请求；到期、资格耗尽和邀请失效说明原因，保留其他任务入口。

任务页“去完成”和验证中的加载提示只是交互过程，不持久保存任务进行中状态；仅原子结算成功才展示完成。验证期间绑定变化则提示重新检查，不沿用旧身份验证结果。

## U13 积分抽奖

展示可消费积分、待提现奖励、单次结果和历史入口。主按钮「100 积分转一次」，积分不足明确缺额并引导任务；规则面板展示生效版本全部奖项与概率。

提交中防重复，结果确定后再播放动画；离开重进能看到原结果。普通结果短反馈，大额结果可增加视觉反馈，不承诺固定次数中奖，不提供自动连转或充值买积分入口。

## U14 奖励转入美元余额

展示待提现奖励、申请中金额、申请金额、固定本人到账账户、手续费 0 及条件清单。满足条件可选全部并确认，不填写链上地址。

不满足条件列出缺项、当前值和具体路径，没有操作路径时说明等待原因。提交进入 U10；拒绝退回显示原记录，可重新申请但重新核验，不重复处理原单。

## U15 邀请成果

「选择任务邀请」返回任务列表再生成具体链接。未完成首任务显示首次完成引导；空列表和筛选无结果分开。没有通用邀请链接或改绑上级入口。

## U17 身份与钱包管理

设置采用“小标题＋功能项”的平铺布局，按预计使用频率固定排序，不动态调整。当前顺序为账户信息（头像昵称、idx、昵称修改）、通用（语言）、绑定身份（邮箱与 Telegram）、账户操作（切换账户、退出登录）。一般功能直接在设置中展示和操作；仅当单块原子功能超过 6 个交互点且较复杂时，才使用子页面，不能按整个分类的交互点总数拆页。身份绑定、换绑表单在对应身份下就地展开。

用户通知订阅为后续预留能力：建议在设置中查询和管理邮箱、Telegram Bot 的业务提醒订阅，具体渠道控制和取消流程随接口细化。仅绑定身份不自动订阅，未接入时不显示可成功订阅或“已开启”的假状态。本轮没有增加设置项；真实收发验证归项目收尾，范围见 [3.6 通知预留方案](工程工作记录/03-资金账户与账本/3.6-美元余额互转与账单/02实施方案.md)。

主页面通过设置进入账户信息，不单列账户入口。未登录时可从设置登录，语言设置仍可使用。旧账户与身份管理链接在鉴权后跳转设置；身份链接保留所需身份提示和业务来源，绑定成功后可回到来源。

| 子流程 | 展示与操作 | 恢复与边界 |
| --- | --- | --- |
| 登录 | Mini App 静默鉴权；App 仅邮箱验证码、Telegram 两种入口 | 成功回来源业务；失败可重试或选择另一入口，不回退为设备登录 |
| 外部身份绑定 | 邮箱、TG 各最多一个，展示绑定状态及功能缺项，按需验证 | 成功保留当前产品用户并回原操作重查资格；占用则拒绝绑定，不合并或自动切换；换绑前须同时有邮箱和 TG，仅一种时引导先绑定另一种；登录态下验证新身份，无旧身份验证步骤，解绑至少保留一种登录方式 |
| 账户与帮助 | 昵称、头像、idx、身份来源、语言、帮助、反馈、退出登录 | 普通退出清理当前端凭证与登录状态，不表示服务端撤销这次登录；退出全部设备暂不提供前端入口或公开接口，内部能力保留；不提供设备列表或指定设备撤销；登出不取消交易，反馈不自动退款 |
| 钱包管理 | 内置及外部分组、网络地址、默认选择、备份或会话状态 | 切换刷新链上资产，不切换产品账户或登录状态；断开不删记录 |
| 创建内置钱包 | 名称、本机解锁、助记词备份、备份核对、完成 | 本地密钥方案按客户端验证，后端不接收密钥 |
| 导入钱包 | 支持格式输入、校验、展示可恢复账户 | 不覆盖已有钱包，不承诺任意助记词恢复所有链账户 |
| 连接外部钱包 | 按当前网络与能力打开官方选择器，同设备授权返回 | 无品牌白名单，无跨设备配对；拒绝保留原表单 |
| 备份或移除 | 备份查看需本机解锁，移除明确仅删除本机访问 | 确认已备份，不宣称后端能够恢复密钥 |

缺钱包时允许改用外部钱包，不强迫完成内置创建。授权返回失败可手动切回并继续原业务；会话过期需重连，用户主动断开后不自动重连。

邮箱登录用户除操作必要条件外可使用功能，不统一要求先绑定 TG。登录页不提供直接登录、游客登录或钱包登录；相关文案已纳入国际化资源。2.4 已实现登录、账户与身份管理页面；本页其他业务页面仍按各自阶段推进。

登录 token 单次有效 3 天，剩余不足 36 小时时在正常请求响应头中自动更新，新 token 从签发时起有效 3 天，不设累计登录时长上限，不增加单独续期页面或刷新请求。token 过期后重新认证，保留来源页面；恢复后重新校验权限，不自动重放扣款或领奖。普通退出、切换账户后忽略先前请求迟到的续签结果，避免恢复已退出的登录；并发响应不得用较早到期的 token 覆盖较晚到期的 token。

邮箱入口统一注册与登录：输入邮箱 → 获取验证码 → 输入验证码 → 验证成功后进入。无密码设置步骤；发送成功仅表示进入收码步骤，不显示已登录。验证码错误、过期或发送失败时保留邮箱与原业务目标，给出对应反馈；按业务规则显示 60 秒重发倒计时、5 分钟有效期及错误次数限制；重发后提示使用最新验证码。

绑定冲突提示该邮箱或 TG 已被其他账户使用，保留当前账户和页面上下文。若用户需要登录该身份所属账户，须主动选择切换并完成认证；不把绑定成功或失败当作切换账户指令，也不提供自动合并余额、奖励或任务记录的操作。

产品昵称和头像独立维护；首次通过 TG 注册可用其资料初始化，邮箱注册使用默认资料。后续登录、换绑或 TG 资料变化不覆盖用户编辑；身份识别使用稳定标识，不使用昵称或头像。

解绑或换绑成功后保留当前设备的新会话，其他设备需重新登录。解绑后的身份若已无当前绑定，再次登录将创建新账户；界面提示可用保留的登录方式进入原账户。

Telegram Mini App 隐藏 Telegram 换绑、切换账户和退出登录入口，同时不显示空的“账户操作”分类；账户加载失败时也不显示退出按钮，保留重试。Telegram 解绑按钮仍禁用并显示原因，前端操作入口同时拦截。以上均以当前运行端判断，不以账户登录方式判断；邮箱操作、缺少 Telegram 时的绑定及其他端操作仍遵循原有条件，后端 API 不增加端限制。

普通接口的登录状态变化允许用户缓存的 30 秒传播窗口，不承诺换绑后其他页面瞬间刷新；关键写操作以服务端事务复核结果为准。缓存或依赖暂不可用时显示可重试的服务错误，不将其伪装为验证码错误或用户已退出。
