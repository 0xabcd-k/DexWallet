# DexWallet 专项讨论清单

本清单承接 [已回答的功能清单](待确认功能清单.md)，集中讨论钱包与支付、商户后台、异常订单处理。请直接替换「回答：待填写」，可按编号逐项作答，也可填写「后续讨论」「首版不做」或「由你出方案」。答案相互关联时可引用编号。

建议先回答资金进出与组合支付，再确定商户结算和异常处理。第04部分是允许后续细化的事项，第05部分是已经委托设计的事项，不要求本轮逐项回答。

## 已确定的前提

| 项目 | 已确定内容 |
| --- | --- |
| 首版载体 | Telegram Mini App，静默鉴权；为后续多平台接入预留边界 |
| 钱包能力 | 支持内置钱包创建或导入，也允许外部钱包；支持多个钱包，后端不保存用户密钥；不强制创建钱包才能做任务 |
| 账户区分 | 任务积分、任务待提现美元余额、中心化钱包美元余额、用户链上资产分别管理 |
| 奖励提现 | 任务待提现余额转入本人中心化钱包美元余额；最低2美元、无手续费；申请扣款生成订单，拒绝退回；自动执行，高风险预留人工审核 |
| Pro | 首次1美元记1000点进度，本人任务及好友助力所得任务积分计入，20%分成不计入；达到2000自动永久解锁，消费积分不减进度 |
| 组合支付 | 中心化余额可以与去中心化资产合并消费，但仅支持合并一种去中心化资产，具体含义和流程在下文确定 |
| 首版钱包功能 | 收款、普通转账、单币种资产详情、相册识别支付二维码、手动输入orderId均做 |
| 商户与异常处理 | 商户接入接口、接入说明、商户管理后台、异常订单查询与人工处理入口均做 |
| 奖励撤销 | 不做任务奖励及分成的事后撤销；支付退款、事务失败回滚及提现拒绝退回属于不同流程 |

本文将「奖励提现」用于任务待提现余额转入中心化余额，将「链上转出」用于中心化余额转到用户链上钱包，以免两条流程混淆。网络和币种暂不指定，待方案建议后确定。
