普通链上转账由付款钱包支付网络费、美元出金由平台先付并从金额扣费，另有现行 D09 方案依据；下表保留其来源，不把 D09 的方案状态写成用户已经逐项审核。

## 审核口径

- 网络费：执行相关链上交易的成本。下列 A、B 组先讨论这部分由谁支付、最终由谁承担。
- 平台服务费：平台可能额外收取的费用，是否收取、承担人和费率均须按 C04 单独审核，不能把网络费承担结论自动扩展为服务费授权。
- 外部来源费用：交易所或外部钱包服务商收取的费用，由该来源实际规则决定；平台只能明确展示已知信息，不能替第三方承诺金额。
- 先支付：实际向链上付出网络费的一方；最终承担：结算后承受这笔成本的一方。平台代付后向用户结算，两者不同。
- 每个金额都须标明总支出或净到账；固定净到账和固定支出分别按 C01、C02 审核。

A、B、C 组以下条目全部为“待逐项审核”。依据为已有决议的部分单独标注，补充建议尚未自动确认。实际费率、费用币种、计算与舍入参数见 C04、C05，未写定的数值保持未决。

## A 主交易场景

| 编号与场景 | 资金路径 | 网络费先由谁支付 | 最终承担、扣费位置及到账影响的建议 | 当前依据 |
| --- | --- | --- | --- | --- |
| A01 钱包直接转账及收款 | 用户钱包 → 本人另一钱包或他人钱包；含外部钱包转入本产品所查看的钱包 | 发送钱包或外部来源按实际通道支付 | 发送方承担网络费；费用由发送方资金支付，接收方不另向平台支付本次收款网络费；只承诺通道报价所明确的到账量 | D09 现行方案；接收方不另付平台收款网络费为本轮明确建议 |
| A02 本人充值美元余额 | 本人钱包 → 平台链上钱包 → 本人美元余额入账 | 平台按已验证代付通道先支付 | 充值人承担；费用从充值总额结算，美元余额按净额入账；固定净到账时反算应付币量 | 决议台账 C06 已确认代付方向；具体结算口径按本清单 C01、C02 审核 |
| A03 代他人充值美元余额 | A 的钱包 → 平台链上钱包 → B 的美元余额入账 | 平台按已验证代付通道先支付 | 建议 A 承担，按 B 的净到账金额计算 A 的总支付；不再从 B 的既有美元余额扣费 | 决议台账 C06 代付方向已确认；最终承担与净到账口径为建议 |
| A04 交易所或未连接钱包手动充值 | 外部来源 → 平台收款地址 → 对应受益人入账 | 外部来源支付发送交易费用 | 转入人承担来源端费用，平台按核验实收及事先公布的通道规则入账；不重复收取来源端已支付的网络费。平台另有实际链上操作时须说明用途与计费依据，归集成本按 B05 处理 | S11 有条件补充通道，尚未开放；费用细则为建议 |
| A05 美元余额转到本人链上钱包 | 扣本人美元余额 → 平台钱包向本人地址出款 | 平台 | 转出人承担；从其确认的美元总扣款中结算，提前展示目标币净到账 | D09 现行方案，具体金额口径待审核 |
| A06 美元余额转到他人链上地址 | 扣付款人美元余额 → 平台钱包向他人地址出款 | 平台 | 付款人承担；以目标币净到账反算美元本金及费用，不从收款人的产品余额扣费 | 本轮建议；与 A05 分列，便于审核给他人付款的到账保障 |
| A07 纯链上支付商户订单 | 用户钱包 → 平台链上钱包 → 商户应付款入账 | 按实际通道由用户钱包直接支付，或由已验证代付通道先支付；通道能力待验证 | 建议付款用户承担网络费，订单本金与费用分列，商户按订单金额入账。备选为商户承担并减少商户净入账；两者本轮尚未选定 | S20 及上一轮建议，尚未确认承担人 |
| A08 组合付款的链上部分 | 美元余额内部划转＋用户钱包链上支付差额 → 商户入账 | 链上部分按实际通道支付，代付能力待验证 | 建议付款用户承担链上部分网络费；余额分项为 0，商户按订单金额入账。A07 的结论不自动代替本项审核 | 余额分项免费已确认；链上承担人为建议 |
| A09 商户链上结算 | 扣商户应付款 → 平台钱包向商户地址出款 | 平台 | 商户承担，从确认的结算总额中结算费用，显示净到账；不追溯向原订单付款用户收费 | 本轮建议 |
| A10 正常商户订单链上退款 | 扣商户可用资金 → 平台钱包向核验后的退款地址出款 | 平台 | 商户承担本次退款网络费；商户扣款包含批准的退款本金及费用，用户收到确认的退款本金。退款币量及原支付费用另按 C09、C10 审核 | 本轮建议，退款政策尚待落实 |
| A11 组合退款的链上部分 | 余额原路退回＋平台钱包退回链上分项 | 平台支付链上分项网络费 | 商户承担链上退款网络费；余额退款分项手续费为 0。A10 的结论不自动代替本项审核 | 余额分项免费已确认；链上承担人为建议 |

个人直接转账成功后，双方另行转回资产按 A01 的新交易处理，不等同于商户退款，也不提供无条件撤回原交易。本人和代他人充值的争议退款须先解决原入账资金归属，不能同时保留受益人入账与退款；若最终允许链上退回，再按获批的退款费用规则处理。

## B 异常与平台资金场景

| 编号与场景 | 网络费先付方 | 最终承担与处理建议 |
| --- | --- | --- |
| B01 用户原因导致异常款退回 | 平台发起退回时由平台先付 | 经核实属于用户误操作的多付、重复支付、少付后选择退款、晚到、错链错币等，建议用户承担可执行退回的网络费；退回前确认本金、费用与净退金额，再从该笔待退款中结算，不自动扣其其他余额；不承诺所有错链错币都可找回 |
| B02 平台原因导致异常款退回或纠正 | 平台 | 平台承担额外链上费用，不减少用户确认应得的退款或到账金额；按核验结果处理本金，不能重复补款 |
| B03 异常原因或归属尚未明确 | 未核实前不自动发出退回交易 | 不预先认定用户承担；先查归属和原因，再按明确的承担方及金额处理。未归属款不是平台手续费收入 |
| B04 少付后的受控补付 | 发起补付的钱包或已验证代付通道 | 用户原因少付时，补付人承担新增网络费；平台错误导致补付时，额外网络费由平台承担。本项只确定费用，补付本金按原单实收差额核定 |
| B05 平台收款归集 | 平台钱包 | 平台承担归集网络费，不在充值或付款完成后再次向原用户扣取归集费 |
| B06 平台钱包调拨与备付补充 | 平台钱包 | 平台承担，包括热冷钱包调拨、出款钱包补资及平台钱包网络费资产补充；不计成用户充值，也不向某一笔用户余额转账摊派 |
| B07 取消或失败且没有实际网络成本 | 没有发生相关支付 | 不收网络费；平台已预扣但未使用的网络费按 C07 退回。若先前已有其他附属链上操作产生费用，则该实际成本按 B08 处理，不能仅凭主交易未广播判断全部为零 |
| B08 交易失败但已产生实际链上成本 | 按原执行通道 | 核验实际成本后，普通执行失败按原业务已审核的承担规则结算；平台错误引起的额外成本由平台承担。失败不能据此继续收取未发生的网络费 |
| B09 内部重试、受控替代或恢复 | 按实际执行方 | 同一笔业务不重复收平台服务费；平台故障导致的额外网络成本由平台承担。普通重试若需增加用户承担费用，先按 C06、C08 检查授权，不因重试自动追加扣款 |

数据库补记、查单、通知重试本身不产生链上资金流，不得以这些动作收取链上手续费。链上回滚、错误确认后的处理如果确需新的链上补款或退回，按 B02/B03 核实责任与授权；不能把账务冲正本身计成一笔链上手续费。

## C 金额、费率与结算口径

| 编号 | 待审核事项 | 建议或待选内容 |
| --- | --- | --- |
| C01 固定净到账 | 填写的金额是否代表收款人最终收到的金额 | 费用由付款人承担时，给他人充值、转账及商户订单建议保持目标净到账，反算付款人本金加费用；切换来源不改变应收金额。示例：净到账 $100、费用折合 $1，则总支付对应 $101，币量按实际报价换算。若 A07 改选商户承担，则按订单价款与商户费用分列计算商户净收入 |
| C02 固定总支出 | 填写的金额是否代表包含费用的全部支出 | 仅在通道明确支持该输入模式时，先扣费再显示净到账。示例：总预算折合 $100、费用折合 $1，净到账对应 $99；不得把界面上“到账 $100”解释成此模式 |
| C03 网络费计算方式 | 实际成本还是固定收费 | 建议网络费按可核验实际成本结算，确认前展示预计值及授权上限；若使用固定收费或加价，需另外明确规则，不把加价隐藏为网络实际成本 |
| C04 平台服务费 | 是否另收、向谁收、如何定价 | 待决定。A01–A11 每种业务分别记录是否收取、付款人或收款人/商户承担、固定金额或比例及计算基数、最低/最高费用；本轮不填任意费率，也不把审核网络费承担视为同意服务费 |
| C05 扣费资产与换算 | 费用用什么资产支付，如何换算和舍入 | 用户钱包直付按网络与钱包实际要求；平台代付建议在业务资金中结算并明确扣费资产、换算报价和舍入。具体资产、精度及汇率参数逐通道确认，不从用户另一资产余额静默扣款 |
| C06 确认前的费用授权 | 最终确认需要展示哪些金额 | 展示业务本金、网络费预计值及上限、已审核的平台服务费、总支出、净到账及计价资产；钱包相关费用确定后才最终确认。没有服务费决议时不把该项自动定为可收费 |
| C07 预扣未用费用退回 | 预计费用高于实际费用时如何处理 | 若采用 C03 的实际成本结算，平台实际预扣而未使用的费用退回原扣费来源，并关联原业务；不把用户钱包已经直接支付的实际网络费当作平台持有的可退款项 |
| C08 超出授权上限 | 实际需要的费用高于用户已确认额度 | 执行前发现超限时重新报价并确认；不得自动追加扣款。已发生且无法再取得事前确认的超额成本建议由平台承担；直接由外部钱包支付的费用仍须经过该钱包授权 |
| C09 原付款费用能否退还 | 商品退款是否同时退原付款手续费 | 建议已经实际发生的原支付网络费不自动返还；商户或平台是否另外补偿须明确。未使用的预扣款按 C07 处理；平台服务费如获准收取，正常退款、异常退款和失败时是否退还须单独确定 |
| C10 链上退款本金口径 | 退原币数量还是按美元退款额重新换算 | 待决定，不能把“商户承担退款网络费”等同于已经确认退款币量或汇差承担。需要确定原币数量/美元价值口径、报价时点及汇差承担者 |

表中 $1 等数值仅为解释金额口径的假设，不是收费承诺、网络费预测或稳定币与美元固定汇率。
