# 任务详情与完成结果需求

[返回产品规划](大纲.md)。关联功能：F03、F06。负责人【待填写】；优先级与目标版本【待填写】；原型【待填写】。

原有设想包含介绍任务内容的“任务完成页”，同时存在本任务详情文档。待决策：详情与完成结果是同一页的不同状态，还是独立页面。以下为可填写的统一需求模板。

## 用户故事与入口

作为参与者，我希望在开始前知道做什么、如何判定完成、奖励归谁，并在提交后知道是否成功和何时到账。

入口：任务列表、邀请链接、历史记录。待填写：登录要求、邀请码保留方式、任务不存在或已过期时的返回路径。

## 单个任务定义模板

每种首发任务填写一份，可按业务类型增加字段。

| 项目 | 待填写内容 |
| --- | --- |
| 任务名称、idx 与类型 | 标题、唯一业务标识、任务分类 |
| 用户价值与任务提供方 | 用户为何参与；谁提供任务和预算 |
| 开始与结束时间 | 时区、报名截止、提交截止、是否允许跨期完成 |
| 参与资格 | 新老用户、Pro、地区或其他资格 |
| 操作步骤 | 明确顺序、外部页面、所需信息与预计耗时 |
| 完成条件 | 可观察的动作、证据来源、有效性和去重规则 |
| 次数与周期 | 一次性或重复、重置时点、本人和助力的次数关系 |
| 奖励 | 本人基础奖励、Pro 处理、助力收益、邀请返佣适用性 |
| 审核与结算 | 自动或人工验证、响应时限、何时入账 |
| 失败与申诉 | 失败原因、能否重做、申诉方式、处理时限 |
| 配置版本 | 发布后规则变更如何影响正在参与的用户 |

## 业务流程

建议流程：读取任务与身份 → 展示本人或助力模式 → 校验资格 → 执行任务 → 提交或接收完成证明 → 验证 → 记录任务结果 → 发放相关奖励 → 展示到账及后续入口。

| 阶段 | 需要确定的规则 |
| --- | --- |
| 自己做 | 任务奖励展示是否含 Pro 加成；何时锁定奖励规则 |
| 邀请别人做 | 是替本人完成任务、增加进度，还是独立的好友任务 |
| 新人帮助别人 | 1 美元的领取者、初始奖励是否重复、绑定关系的时点 |
| 老人帮助别人 | “一个助力”的计算对象、上限、可否帮助多人 |
| 验证 | 客户端操作、第三方回调或人工证据分别如何判定 |
| 结算 | 本人、邀请人、被助力人分别得到什么；如何关联同一次任务 |
| 结果告知 | 任务完成、奖励待到账和奖励已到账是否分别展示 |

建议任务状态：未开始、进行中、验证中、已完成、验证失败、已过期、已取消。建议奖励状态：待发放、已发放、失败待处理、已撤销。状态转换条件、允许重试的范围和超时规则【待填写】。

## 边界与异常

| 场景 | 待填写的处理规则 |
| --- | --- |
| 重复点击、重复证明或第三方重复回调 | 如何识别同一次完成；不重复发奖 |
| 外部页面返回但没有有效证明 | 如何告知验证中或未完成；何时重查 |
| 任务期间过期、下架、预算不足 | 已开始用户是否保留资格；存量任务如何结算 |
| 完成时 Pro 或邀请关系变化 | 按开始、完成还是结算时的身份计算 |
| 本人完成与好友助力同时发生 | 是否分别生效；是否共享次数或奖励上限 |
| 完成已确认但发奖失败 | 保留完成事实；如何补发及避免重复 |
| 奖励撤销或作弊判定 | 本人、邀请人、助力进度、Pro 和已提现款如何处理 |

## 验收场景草案

| 前置条件与动作 | 可观察的预期结果 |
| --- | --- |
| 有资格的普通用户完成任务 | 任务结果、基础奖励和账单一致 |
| Pro 用户完成任务 | 按确认范围翻倍，计算依据可查询 |
| 新用户通过邀请完成任务 | 双方各笔奖励、邀请关系与助力记录符合规则 |
| 老用户通过邀请完成任务 | 助力数及可能的本人奖励符合规则 |
| 未满足完成条件或验证超时 | 不提前显示已发奖，可查询或申诉 |
| 重复证明及发奖重试 | 同一业务结果只产生应有的奖励 |
| 已完成任务撤销 | 所有受影响记录按确认规则同步，可追溯原因 |

验收需补充真实规则下的具体输入、金额或积分、证据和负责人；统计口径见[邀请统计](邀请统计.md)，账务见[账单](账单.md)。
