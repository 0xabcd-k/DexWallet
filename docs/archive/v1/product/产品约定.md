# 产品约定

本轮先形成可画原型的完整产品。已确定规则优先；尚未回答的问题采用下文默认方案，页面按默认方案展开，不要求逐项补答。默认方案属于规划假设，不代表已经上线或经过资金通道验证。

## 已确定范围

| 事项 | 规划依据 |
| --- | --- |
| 载体 | Telegram Mini App 先行，后续独立 App；用户端导航为钱包、任务、邀请 |
| 身份 | Mini App 使用 Telegram 静默鉴权，产品账户与平台身份分开 |
| 钱包 | 内置钱包可创建、导入；也可连接外部钱包；多个钱包可切换，后端不保存用户密钥 |
| 连接方式 | 不限制钱包品牌，按网络和签名能力接入；首版仅同设备唤起和返回，不做跨设备配对 |
| Mini App 资产 | TON 网络的 TON、USDT |
| App 资产 | TON：TON、USDT；Base：ETH、USDC；Solana：SOL、USDC、USDT；TRON：TRX、USDT |
| 中心化余额 | 支持链上充值、转出到链上以及产品账户之间互转；使用项目汇率表换算美元 |
| 充值费用 | 平台代付网络费用，从用户金额中扣除；确认到账后及时入账，不以用户点击完成为准 |
| 链上转出审核 | 结合系统及用户维度统计进行风险判断；符合条件自动处理，其他情况进入人工审核 |
| 首奖 | 首次本人完成任务得 1 美元待提现奖励，另记 1000 点 Pro 进度，不发放 1000 可消费积分 |
| 任务与邀请 | 每类任务分别判定资格和完成，用户主动点击完成领奖；完成首次任务后才能邀请；禁止本人助力 |
| 助力 | 新用户首次完成得 1 美元，老用户助力无本人奖励且消耗参与资格；邀请者得任务积分 |
| 邀请关系 | 首次任务通过邀请页完成时绑定，用户不能修改；直接上级得最终任务积分的 20%，向下取整，不递归 |
| Pro | 首奖进度加本人任务及好友助力所得任务积分累计到 2000 自动永久解锁；分成不计进度，消耗积分不减进度；触发解锁当笔不翻倍 |
| 水果机 | 每次 100 积分，初始 RTP 为 0.95，现金入任务待提现余额；扣分、结果和入账一起完成 |
| 奖励提现 | 待提现奖励转到本人美元余额；最低 2 美元、无手续费，申请扣除，拒绝退回；动态条件与高风险审核可调整 |
| 其他 | 有商户后台、商户接口说明、异常订单处理；不做通用邀请或任务奖励事后撤销 |

充值、中心化余额互转和汇率换算来自用户在专项清单中的最新补充；其中尚未写完的出金费用及钱包切换回答不作为完整决议。

## 本轮默认方案

| 编号 | 默认方案 | 对页面的影响 |
| --- | --- | --- |
| P01 | 普通链上收发覆盖各客户端已确定资产；付款、充值和美元余额链上转出也按这些资产设计，逐通道启用 | 资产选择只显示当前可用通道；未验证的代付能力显示暂不可用，不提前扣款 |
| P02 | 平台美元余额互转仅面向已注册用户，按产品账户 ID 查找，可扫账户收款码；首版免手续费 | 转账分“链上转账”和“账户转账”，确认接收人的昵称、ID 后付款 |
| P03 | 付款允许切换钱包；上次使用的钱包作为默认，但每笔展示实际付款账户 | 钱包选择抽屉复用到支付、转账、充值页 |
| P04 | 组合付款限定一个链上钱包、一个网络、一种链上资产，加本人美元余额 | 默认优先使用美元余额，可关闭或修改使用金额，不跨钱包、跨链凑款 |
| P05 | 平台统一收款，商户记美元余额；订单按美元计价 | 用户付款完成后商户订单显示已支付，商户余额增加可核对的结算金额 |
| P06 | 组合付款先预留美元部分，再授权链上部分；两部分核实后整单成功 | 处理中分别展示两部分状态；结果不明时继续查询，不重复发起或擅自释放资金 |
| P07 | 订单过期只阻止新付款；已开始的付款继续核验 | 超时、少付、多付、重复付款、过期到账等进入异常订单；回调失败不改变已收款事实 |
| P08 | 商户由平台开通，一商户一个主操作账户，首版不做复杂组织权限 | 商户有订单、收款单、资金结算、接入设置；平台处理开通及停用 |
| P09 | 正常订单首版支持整单退款；异常多付可退差额；退款原则上回到原资金来源 | 商户发起，平台审核；资金不足或链上结果未知时进入待处理，不冒充已退款 |
| P10 | 商户主动申请结算，平台审核后出金 | 结算申请锁定可结算金额，拒绝退回，结果未知保持处理中 |
| P11 | 中心化余额链上转出费用暂按平台垫付、从转出金额中扣除设计 | 展示扣除美元、网络费、预计到账币量；费用不足时不能提交 |
| P12 | 链上充值在达到对应通道确认要求后即时入账；页面先显示确认中 | 接口成功或钱包返回均不直接显示到账；不承诺所有链零等待 |
| P13 | App 初版沿用 Telegram 身份授权入口；商户和平台后台采用独立管理账户 | App 有登录页，Mini App 正常不展示登录页；外部钱包连接不替代产品登录 |
| P14 | 平台管理先供单人维护使用；保留操作记录，不做角色配置和多级审批 | 危险资金操作要求复核及填写原因，登录及权限由管理端统一提供 |

P01、P06、P11 涉及资金通道能力，开发前须落实可执行方案；页面可先画出正常与不可用状态。充值的代付是用户要求，普通用户间链上转账默认由付款钱包支付网络费，两者费用说明分开。

## 原型默认参数

| 参数 | 本轮取值 | 说明 |
| --- | --- | --- |
| 奖励提现最低金额 | 2 美元 | 已确定，不因其他限额调整 |
| 美元余额链上转出最低金额 | 5 美元 | 规划值，可按网络调整，且扣费后到账必须为正 |
| 充值最低净入账金额 | 1 美元 | 规划值，确认页预先展示；小额意外到账进入待处理，不直接丢弃 |
| 平台余额互转最低金额 | 0.01 美元 | 规划值 |
| 商户结算最低金额 | 10 美元 | 规划值，可配置 |
| 订单新付款有效期 | 15 分钟 | 规划值，不等于链上最终确认期限 |
| 付款与兑换报价有效期 | 30 秒 | 规划值，过期重新报价并再次确认；已提交交易保留原报价核验 |
| 商户服务费 | 原型先按 0 展示 | 可配置；实际开放前确定，不影响单独列示网络费 |

汇率由平台行情源维护。页面显示报价时间及有效期；行情过期或不可用时暂停需要换算的新交易，资产余额和既有记录仍可查看。以上费用与限额是原型默认值，不能替代实际通道成本测算。

水果机采用 [现有候选奖项表](../design/水果机奖励方案.md) 规划规则弹窗：普通结果集中、最高 5 美元、无空奖、无累计奖池。具体概率表仍为规划方案，正式启用以运营发布版本为准。

## 四类余额的页面用词

| 名称 | 页面用途 |
| --- | --- |
| 美元余额 | 平台中心化余额，可充值、转账、消费和提现到链上 |
| 链上资产 | 所选钱包在各网络的原生币或代币，不与美元余额直接合并数量 |
| 任务积分 | 用于水果机，积分分成也进入这里 |
| 待提现奖励 | 首奖与水果机现金奖励，符合条件后转入美元余额 |

Pro 进度不是余额，独立展示。用户端“奖励提现”与“美元余额提现”是不同页面；“链上收款”与“充值美元余额”也分开，避免用户误判资金去向。
