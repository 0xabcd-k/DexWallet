# 任务列表与奖励体验需求

[返回产品规划](大纲.md)。关联功能：F03、F04、F06。优先级与目标版本【待填写】；原型【待填写】。

原有设想：展示可做任务，每个任务有“自己做”和“邀请别人做”两个选项，页面包含邀请弹窗和水果机。原始数值与规则见 R01–R07；以下细化项均待确认。

## 用户目标与页面结构

用户故事：作为任务参与者，我希望知道任务内容、完成条件、可得奖励和所需时间，并选择自己完成或邀请好友。目标用户和主要场景【待填写】。

| 区域 | 建议展示 | 待填写规则 |
| --- | --- | --- |
| 奖励概览 | 当前积分、奖励余额、Pro 进度、规则入口 | 与钱包一致的计算口径；初始奖励如何展示 |
| 任务卡片 | 标题、类型、完成条件、奖励、有效期、状态 | 首发任务类型、排序、筛选、分页、上下架 |
| 自己做入口 | 当前用户可获得的任务奖励 | 资格、次数、跳转位置、已完成时行为 |
| 邀请入口 | 邀请规则、分享动作和收益说明 | 任务是否可邀请；与自己做是否互斥 |
| 水果机入口 | 可用积分、参与条件、历史结果 | 是否首发、是否独立页面、维护时行为 |
| 说明与帮助 | 奖励规则、未到账帮助、活动有效期 | 文案、客服入口与国际化资源 |

### 页面状态

待填写：首次加载、无任务、无符合筛选项、加载失败、任务已下架、奖励预算耗尽、用户受限、维护中。每个状态说明可见内容、可用操作、重试和帮助入口。

## 邀请弹窗

建议流程：选择任务 → 查看邀请人与好友各自收益 → 生成或取得链接 → 复制或分享 → 展示操作结果。

待填写：链接范围（通用或任务专属）、有效期、分享渠道、复制失败替代方式、已过期链接、登录后恢复、邀请成功判定。复制成功仅代表复制操作完成；有效邀请按[邀请统计](邀请统计.md)的规则统计。

## 水果机与积分

原有设想：每 100 积分转一次，奖励期望为 0.1 美元 × RTP，单次奖励可高可低。下列机制需要先决定，再制作界面和配置。

| 问题 | 待填写内容 |
| --- | --- |
| 玩法性质 | 仅展示已确定奖励的动画，还是产生随机奖励的机制 |
| 参与资格 | 哪些积分可用、是否扣除、次数上限、余额不足提示 |
| 奖励配置 | 奖项、单位、概率、上下限、RTP 定义和数值、配置版本 |
| 计算与核验 | 每个结果由谁确定；如何核对概率合计和奖励期望 |
| 结果入账 | 扣积分、发奖励、Pro 进度的顺序和关联记录 |
| 并发与重复操作 | 连点、多设备同时参与、一笔请求重试的规则 |
| 动画与恢复 | 是否可跳过；关闭页面、断网后如何恢复同一结果 |
| 异常处理 | 未扣成功、已扣未出结果、已出结果未入账、服务暂停 |
| 用户说明 | 展示哪些概率和规则；名义折算与实际奖励如何区分 |
| 规则变更 | 新旧配置生效时点；进行中的参与适用哪个版本 |

## 验收场景草案

| 场景 | 可观察的预期结果 |
| --- | --- |
| 普通用户、Pro、新人助力、老人助力 | 各自展示和到账与确认后的矩阵一致 |
| 已完成、下架、过期或无资格任务 | 不提供无效操作，说明原因 |
| 复制失败或链接过期 | 有明确结果和可执行的下一步 |
| 积分不足或多个窗口并发参与 | 不超额消耗；结果与账单可关联 |
| 水果机请求重复、动画中途退出 | 同一次参与不会重复扣除或重新抽取结果 |
| 奖励配置切换 | 进行中参与按已确认的版本规则完成 |

需记录的指标【待填写】：列表曝光、任务点击、邀请操作、开始参与、参与结果及失败原因。完成证明和发奖见[任务详情](任务详情.md)。
