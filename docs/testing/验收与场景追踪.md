## 异常与恢复矩阵

所有异常均需记录业务 idx、资金状态和允许操作。E01–E28 保留旧工作流含义，处理策略由服务端返回，不能由页面错误文本猜测。

| 异常 | 用户或后台反馈 | 服务端与资金处理 | 恢复与验收 |
| --- | --- | --- | --- |
| E01 链接失效或被改 | 无法使用、重新扫描 | 校验对象、版本、金额，不建资金单 | 修改链接不能改变订单价款 |
| E02 裸地址或不支持资产 | 补网络或说明不支持 | 校验真实网络资产标识 | 不用同名假币或错链付款 |
| E03 对象冻结停用不存在 | 不可新收款，历史仍可查 | 拒绝新请求，已实收登记异常 | 资金不因停用丢失 |
| E04 余额不足 | 缺额与换方式 | 提交复查并原子锁定，不超支 | 准备失败无无主冻结 |
| E05 手续费不足或代付不可用 | 确认前提示 | 不产生不可执行承诺，不静默改费用承担 | 补条件或改用已验证方式 |
| E06 报价过期行情异常 | 新旧比较或暂不可用 | 未受理重报价，已有效提交保留版本 | 不改历史成交 |
| E07 钱包未安装拒绝过期 | 安装、换钱包或重连 | 连接失败不扣款，拒绝结合广播证据 | 保留原业务，不盲目释放未知占用 |
| E08 账户或网络变化 | 重新确认 | 未提交参数失效，原交易继续原快照核验 | 不把新账户写入旧尝试 |
| E09 重复或跨设备并发 | 同一结果 | 主体动作幂等，同键异参冲突，订单有效尝试唯一 | 只有一次应有扣增 |
| E10 响应丢失或进程回收 | 找回原状态 | 先查受理记录，后台继续执行 | 不重发资金与奖励 |
| E11 签名后广播未知 | 提交待核验 | 保存提案交易，核查或受控重播替代 | 不再发独立重复交易 |
| E12 确认慢或 RPC 中断 | 最近查询与处理中 | 补扫描缺口，多来源核验，保留占用 | 超时转有责任的异常队列 |
| E13 执行失败弹回或失效 | 真实结果与实际费用 | 核验最终资产变动，确定不可执行再释放 | 无效事件不当到账 |
| E14 少付或组合部分到款 | 已收、差额、待处理 | 记录实收，补付受控，未足额不报成功 | 能退回或明确确认补付 |
| E15 多付 | 应付与超额分开 | 应收计商户，超额独立待退 | 不超实际实收分配 |
| E16 订单重复实收 | 原单已付与重复款记录 | 第二笔记异常不重记商品收入 | 不重复发货 |
| E17 关闭过期后到账 | 原付款核验或晚到处理 | 有效在途按规则完成，安全终止后转异常 | 释放后不偷偷重扣余额 |
| E18 无备注或无关联 | 提交线索与待归属 | 验证归属与认领权，阻止重复认领 | 截图金额不足以认领 |
| E19 到账后账本失败 | 到账处理中 | 持久证据，幂等重试结账 | 不要求用户再付 |
| E20 通知失败重复乱序 | 支付成功、通知异常 | 按事件版本重试与去重 | 不改支付事实、不重复交付 |
| E21 退款与结算并发 | 占用原因与实际可用 | 锁定商户金额及退款额度 | 同一钱不能占用两次 |
| E22 出款后状态未落库 | 核验中，无重复执行 | 原任务链上证据补结账 | 不产生第二笔出款 |
| E23 链上回滚或确认不一致 | 核查中 | 保存新旧证据，按影响冲正或追补 | 已消费资金转专门处理，不抹历史 |
| E24 备付不足或维护 | 新业务不可用、原单待处理 | 暂停新不可执行请求，保留占用，安排调拨 | 恢复后重核价格和授权 |
| E25 实际费用偏离估算 | 最终费用及退回 | 按授权上限，超出须重确认或平台承担 | 不静默追加扣款，结余按规则释放 |
| E26 错链错资产意外小额 | 待处理线索，无保证找回 | 可识别实收留记录，按实际控制能力恢复 | 同名币不自动兑美元 |
| E27 撤回成功互转或代充值 | 已到账、可提交争议 | 核实权属和受益余额，不把投诉当撤销授权 | 防止退款与受益余额双保留 |
| E28 外部签名长期未广播 | 已有提案处理中 | 可执行提案纳入在途，证明失效才替代或释放 | 不因未广播就重复打款 |

## 奖励验收

| 规则 | 场景与预期 |
| --- | --- |
| R01 | 同一产品用户的两个首次任务并发完成时只产生一份 $1 首奖与 1000 进度，包括使用不同外部身份的情形；不产生首奖可消费积分；另一任务按实际结算资格处理 |
| R02 | 验证不满足不发奖；外部超时可查原结果；重复领奖只一次，任务到期按类型策略；外部身份解绑、重绑或换产品账户不重置该任务次数 |
| R03 | 首任务前无邀请入口，自己打开自己的链接不助力；无通用邀请链接 |
| R04 | 新用户受邀得首奖，老用户助力无本人奖励并消耗同一参与资格 |
| R05 | 多个有资格好友每次有效助力均给邀请者积分，同一参与者不能绕资格重复 |
| R06 | 打开链接不绑定；首次完成才绑定，老用户不能补建或改绑，帮助他人不改上级 |
| R07 | Pro 后最终任务积分先计算，再给上级 20% 向下取整；分成不递归、不再次倍增 |
| R08 | 首奖进度、任务积分计入，分成不计；跨 2000 当笔不翻倍，消费不降级 |
| R09 | 不足 100 不扣分；恰好 100 可一次；奖项边界按固定随机输入确定性验证 |
| R10 | 任一步事务失败全回滚；响应丢失与动画中断恢复同一结果和一次入账 |
| R11 | Pro、最低金额、动态条件分别检查；申请扣奖励，通过只增本人美元，拒绝只返一次，无手续费 |
| R12 | 不存在通用已发奖励撤销入口；回滚、拒绝退回和资金差异处理不被该限制误禁用 |

## 身份与任务归属补充验收

以下是 2.1 讨论形成的验收要求，尚未实施或运行；未决策略确定后再补对应失败、恢复和并发案例。

| 场景 | 可观察结果与待落实边界 |
| --- | --- |
| Mini App 静默登录 | 已验证 TG 对应已有用户时返回原用户；首次建立用户及绑定，不因重试重复创建 |
| App 登录入口 | 仅提供邮箱验证码、Telegram；无直接登录、游客登录或钱包登录；认证失败或会话失效不回退为设备登录 |
| 邮箱验证码登录 | 首次验证成功创建产品用户及邮箱关联，后续登录返回原 idx；发送验证码不创建已验证用户或会话；错误、过期或已消费验证码不能再次签发会话；并发首次验证不重复创建用户；无密码设置流程 |
| 邮箱用户未绑定 TG | 保持产品登录，可使用不依赖 TG 的功能；需 TG 的任务引导绑定，不将 TG 设为全局门槛 |
| 功能缺少必需身份 | 保持产品登录，说明缺少的身份并引导绑定；返回原任务后重新校验，不自动领奖或扣款；无此依赖的功能不被拦截 |
| 导入、切换或断开钱包 | 当前产品用户 idx、产品会话及产品奖励账户保持不变 |
| 外部身份换绑 | 已消耗次数仍属于原外部身份；新身份使用自身剩余资格；产品首奖状态与既有奖励不被重置或转移；换绑是否获准另按确认后的规则执行 |
| 首奖与任务资格交叉 | 未领首奖的产品用户不能使用已耗尽的外部任务资格；已领首奖的产品用户即便使用有资格的新身份也不能再领首奖 |

在途任务的身份/受益人固定时点仍待讨论。首奖实际入账时点已确认保持 R01：首次任务完成后，不在注册或登录时入账，不与首次任务再叠加一份普通任务奖励。内部“预期任务奖励前置”的解释不出现在用户引导中，也不产生新增抵扣或追回流程。

邮箱验证码的有效期、发送与尝试限制、重发及失败恢复参数在鉴权方案细化后补充边界用例；当前仅记录验收要求，未实现或运行邮箱认证。

## 关键端到端案例

资金案例忽略费用并以实际报价换算币量：A 链上给 B 充值净 $20；B 给 C 转 $5，B 剩 $15、C 得 $5；B 用 $3 余额和 $7 链上价款付 $10 商户订单，B 余额 $12、商户应付款 $10。核对 A 的支出、B/C 余额、项目原币实收和商户负债。

退款与结算使用互斥分支或不同订单：退款时按原构成退回，不能同时把同一资金结算企业；结算时锁定商户金额，实际企业到账后才减应付款。模拟链上已完成但数据库失败、另一设备重复请求与回调丢失，结果必须能恢复且只入账或出款一次。

奖励案例按 [任务与奖励](../product/04任务与奖励.md) 的首奖、助力、上级分成与 Pro 临界示例逐项核对四类账户和进度，不用总资产相等替代分账户验证。

## 测试层次与设备覆盖

单元测试控制时间、随机与外部边界，验证账本原子性、资格、计算、状态转换、幂等和错误语义；集成测试单独使用真实数据库、协议、测试网络、签名及通知。支付真实资产前完成对应环境演练，不让普通单元测试依赖线上服务。

钱包兼容按 iOS、Android、Telegram 容器及独立 App 分别验证：发现与安装、连接拒绝、会话过期、账户网络变化、原生币与稳定币、签名广播、手动切回、系统回收恢复。每条已开放网络资产均需覆盖，不按钱包宣传支持推定交易接口可用。

原型验证观察六条体验路径，记录入口选择、资金去向解释、奖励条件理解、重复付款倾向与恢复成功；尚未进行的用户测试不得填成已通过。
